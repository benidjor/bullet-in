## 2. 의존 구조

```
수집: body_level 가드 · 바이라인 함수  ──►  번역: 26 → 29건 body_source 채우기
번역: 프롬프트 · 게이트                ──►  E안 퍼가기 정책 개정
번역 + 단계 재분류                     ──►  선수 명단 DB (#144)

독립: football.london 95행 삭제 · 단계 재분류 · 기타 필터 UI · 서빙 · guardian
```

**지금 순서를 지켜야 하는 구간은 첫 줄 하나뿐이다.**
수집 트랙의 가드가 머지되기 전에 본문을 채우면 그 URL 이 완전체로 굳어 언론사 원문이 들어올 길이 막힌다.

번역 트랙의 나머지 (football.london 삭제 · 게이트 · 프롬프트) 는 이 구간과 무관해서 기다리지 않고 진행할 수 있다.

## 3. 필드 소유권

2026-07-29 에 두 세션이 병렬로 일하다 부딪혔다.
서로 다른 파일을 만졌는데도 충돌한 이유는 `body_source` 하나를 세 목적으로 쓰고 있었기 때문이다
— 중복 판정 기준 · 번역 재료 · 기자명 원천.

그래서 작업 갈래를 파일 단위가 아니라 필드 단위로 나눈다.

| 필드 | 소유 트랙 | 다른 트랙 |
| --- | --- | --- |
| `body_source` · `body_level` | 수집 | 읽기만 · 쓰려면 소유 트랙과 합의 |
| `journalist` · `outlet` · `tier` | 수집 (신뢰도 레지스트리) | 읽기만 |
| `body_ko` · `summary_ko` · `summary3_ko` · `title_ko` | 번역 | 읽기만 |
| `transfer_stage` | 분류 | 읽기만 |
| `url` · `content_hash` · 중복 판정 | 수집 | 읽기만 |
| 템플릿 · 필터 · 정렬 | 서빙 | 쓰기 없음 |

## 4. 병렬 세션 운영 규칙

2026-07-29 병렬 작업에서 얻은 교훈이다.
병렬 자체는 성과가 있었다 — 두 세션이 서로의 결함을 하나씩 찾아 구현 전에 고쳤다
(등급 산출이 무너지는 경로 · 본문 출처를 소스 이름으로 추론하던 오류 · 인용 트윗의 시각을 지우던 정규식).

문제는 분할 기준과 조율 시점이었다.

- **세션을 열 때 쓰는 필드를 먼저 선언한다.**
겹치면 그 자리에서 나누거나 순서를 정한다.
설계를 끝낸 뒤에 맞추면 양쪽 다 다시 써야 한다.
- **필드가 겹치는 조합으로는 병렬을 열지 않는다.**
세션끼리 직접 주고받을 길이 없어 조율은 사람 손을 거친다.
2026-07-29 에는 여덟 번 넘게 오갔다.
- **순서를 지켜야 하는 구간에서는 병렬을 열지 않는다.**
한쪽이 기다리는 동안에는 조율에 드는 비용만 남는다.
- **공유 자원은 미리 알린다.**
같은 VM · DB · Gemini 키를 쓴다.
대량 호출과 배포는 시작하기 전에 알린다 (2026-07-29 에 한 세션이 730회를 사전 고지 없이 호출했다).
