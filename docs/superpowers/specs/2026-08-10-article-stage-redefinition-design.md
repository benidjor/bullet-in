## 1. 배경 · 문제

메인 목록의 영입 단계 필터 분포 (오피셜 7 · 이적 합의 124 · 협상 중 102 · 개인 합의 9 · 관심 168 · 루머 131 · 기타 63) 가 직관에 반한다는 발제 (2026-08-08) 에서 출발했다.
이적 합의가 협상 중보다 많고, 개인 합의가 9건뿐인 구성을 독자가 이해할 수 없다.

감사 실측 (§2) 으로 확인한 원인은 세 겹이며, 순수 오분류는 그중 가장 작은 축이다.

- **완료된 딜의 거처가 없다** — official 은 공홈 규칙 전용이라 (2026-07-19 확정), 타 매체의 "계약 체결 완료 · 등번호 배정 · 회고" 기사가 전부 agreed 에 영구 누적된다.
agreed 121건 중 완결 사가 후속이 80건 이상이다.
- **현행 agreed 정의가 임박 보도까지 포함한다** — "딜 확정 · 임박 보도" 를 한 버킷으로 정의했으므로 (07-19 §2), 사가의 협상 후반 · 임박 기사가 정의대로 agreed 에 뭉친다.
오분류가 아니라 정의가 시킨 결과다.
- **타 구단 간 딜이 단계 필터에 섞인다** — "이적 주체가 아스날이 아니어도 단계는 그대로 매긴다 (방향만 none)" 규칙 때문에, 완결 사가를 걷어낸 잔여 agreed 41건 중 약 24건이 타 구단 딜 · 아스날이 놓친 딜이다.

여기에 화면 문제 두 가지가 같은 뿌리로 얽힌다.

- 오피셜 배지가 "이적 완료" 로 읽히지만 실제 의미는 "공홈 공지" 다.
공홈은 합의 때 · 확정 때 각각 올리므로 같은 딜에 오피셜이 두 번 나온다 (트로사르 실측: 5267e88b 합의 → 7782fd9e 확정).
- 무산 · 잔류 확정 기사의 거처가 없어 프롬프트의 두 규칙 ("무산 → 도달했던 마지막 단계" vs "재계약 → other") 이 충돌하고, 비니시우스 잔류 같은 사가 결말이 기본 숨김 버킷 (other) 으로 사라진다.

## 3. 확정 결정 (사용자, 2026-08-09 ~ 08-10)

07-19 확정 ("이적 합의 = 합의부터 임박까지 넓은 버킷") 을 재개정한다.

- '이적 합의' 는 **진짜 확정 보도만** 담는다 — 이적 확정 + here we go 처럼 사실상 확정으로 쓰이는 보도.
- 임박 · 근접 · 눈앞 보도는 **협상 중으로 넓혀** 담는다.
- 완료된 이적의 후속 보도를 담는 **'이적 완료' (done) 를 신설**한다 (3층 구분 — 안 ㄱ).
- 아스날 관련 딜의 종결 보도를 담는 **'무산' (collapsed) 을 신설**한다 (선택지 ㉰).
- 메디컬의 사이드바 그룹 소속을 협상 중 → 이적 합의로 옮긴다.
- 단계 필터의 계수 · 목록을 방향 in · out (아스날 주체) 한정으로 바꾼다 (§8).

### 3.1 단계 체계

| 순서 | enum | 라벨 | 정의 | 경로 |
| --- | --- | --- | --- | --- |
| 1 | official | 오피셜 | 공홈 공지 (불변) | 규칙 |
| 2 | done (신설) | 이적 완료 | 완료된 이적의 후속 · 부대 보도 — 체결 완료 · 등번호 · 입단 소감 · 회고 · 해설 | LLM + 명단 주입 |
| 3 | agreed | 이적 합의 | 확정 보도만 — 구단 간 완전 합의 도달 · here we go 류 · 체결을 새 소식으로 전하는 기사 | LLM |
| 4 | medical | 메디컬 | 유지 | LLM |
| 5 | personal_terms | 개인 합의 | 유지 + "준비 · 계획 · 근접은 합의가 아니다" 명시 | LLM |
| 6 | negotiating | 협상 중 | 넓힘 — 협상 · 제안 · 거절 + 합의 임박 · 근접 · 눈앞 (확정 아님) | LLM |
| 7 | interest | 관심 | 유지 | LLM |
| 8 | rumour | 루머 | 유지 | LLM + 가십 규칙 |
| 9 | collapsed (신설) | 무산 | 아스날 관련 딜의 종결 — 잔류 확정 · 재계약 체결 · 결렬 확정 · 하이재킹 완패 | LLM |
| — | other | 기타 | 유지 (기본 숨김 토글 불변) | LLM |

- agreed ↔ negotiating 경계는 수사가 아니라 **주장 유무**로 가른다 — 기사가 합의 도달을 사실로 보도하면 agreed, 접근 중이라고 보도하면 negotiating.
- 사이드바 표시 그룹: 오피셜 / 이적 완료 / 이적 합의 (+ 메디컬 편입) / 개인 합의 / 협상 중 / 관심 / 루머 / 무산 (+ 기타 토글).
- 예시 기대 매핑 (기마랑이스 사가 3층 분해): "이적료 협상 진전 · £80m 제안 · 영입 임박" → 협상 중 · "9천만 유로 합의 · 원칙적 합의" → 이적 합의 · "계약 체결 완료 · 등번호 39번 · 발표 지연 · 회고" → 이적 완료.
- 오피셜 라벨 문구는 유지한다 — 완료 라벨이 따로 생기면서 "오피셜 = 공홈 공지 · 완료 = 딜 종결" 의 의미가 화면에서 갈라져 오독 (backlog g) 이 구조적으로 해소된다.

### 3.2 무산의 경계

경계 완화에는 제외가 따라야 한다.

- 무산은 **아스날 관련 딜의 종결**에만 쓴다.
타 구단 간 딜의 무산 · 결렬은 기존 규칙대로 그 딜이 도달했던 마지막 단계로 남긴다.
- 진행 중인 잔류 · 재계약 협상 보도는 무산이 아니다 — 결말이 확정된 보도만 무산이다.
- **하이재킹 완결 보도 (아스날이 경쟁에서 밀린 딜의 성사) 는 무산이다** — 방향은 아스날이 시도했던 축 (in/out).
당초 "주된 관점으로 가른다" 안을 등록했으나 dry-run 에서 주관점 판별이 판마다 흔들렸고 (§6.1), 모델의 자연 판독 · 아스날 팬 관점 모두 무산 쪽과 일치해 규칙을 이쪽으로 단순화했다 (사용자 확정 2026-08-10).
- 기존 프롬프트의 "무산 → 도달했던 마지막 단계" · "재계약 → other" 두 규칙 중 아스날 관련 딜 부분을 collapsed 로 대체해 충돌 (§2 의 40건 산재) 을 해소한다.

## 4. 프롬프트 · 재료 설계 (STAGE_PROMPT 개정 요지)

이번 회차는 스펙 문안까지이고 코드 반영은 다음 회차다.

1. **agreed 좁힘** — 임박 계열 문구를 제거하고 "구단 간 완전 합의 도달 · 딜 확정을 사실로 보도 (here we go · 구두 합의 · 원칙적 합의 포함)" 로 바꾼다.
2. **negotiating 넓힘** — "이적료 · 조건 협상 · 제안 · 거절 + 합의 임박 · 근접 · 눈앞 · 마무리 단계 (합의 도달을 사실로 전하지 않는 한)".
3. **done 신설** — "이미 완료된 이적의 후속 · 부대 보도 (체결 완료 · 등번호 · 입단 소감 · 회고 · 해설)".
완료 여부 판단이 세계 지식에 기대지 않도록 확정 명단 (`players` 의 in_done · out_done) 을 `{roster}` 재료로 주입한다 — 시소 트러블슈팅 (2026-08-08) 의 해법과 같은 패턴.
4. **collapsed 신설** — §3.2 정의 · 제외 · 관점 경계를 조항으로 넣는다.
5. **personal_terms 오염 차단** — "연봉 · 조건 제시 준비 · 계획 · 근접은 합의가 아니다 (negotiating 또는 interest)" 를 추가한다.
6. **방향 규칙 보강** — "아스날이 이적의 당사자 (사는 쪽 · 파는 쪽) 가 아니면 반드시 none — 관심을 가졌거나 경쟁에서 밀린 딜도 none" 을 예시 (몽가 · 로저스) 와 함께 강화한다.
구단명은 `{club}` 파라미터로 뺀다 (§9).
7. **입력 확장** — 분류 입력을 제목 + summary_ko (1문장) 에서 제목 + summary3_ko (3문장) 로 교체한다.
둘 다 이미 저장된 필드라 생성 비용 증가는 없고 호출당 입력 토큰만 소폭 는다.
단, summary3 도 모델 생성물이라 요약 환각 (§2) 을 없애 주지는 않으므로 dry-run 에서 현행 입력판과 나란히 재서 채택한다.
본문 발췌 추가는 summary3 판이 부족할 때만 후속 검토한다.

공통 사항.

- **PLAYERS_CLAUSE 동기화** — 선수 단위 stage enum 에 done · collapsed 를 추가하고 한 줄 정의를 기사 단위와 일치시킨다 (동기화 원칙 · 가드 테스트 존재).
- **방어 불변량** — LLM 이 official 을 반환하면 강등하는 방어는 유지하되 강등 목적지를 agreed → done 으로 바꾼다 (타 매체의 "오피셜" 보도는 새 체계에서 완료 계열).
official 생성 경로는 계속 규칙 전용이다.
- **시소 중단 신호** — 문안 조정 중 한쪽을 살리면 다른 쪽이 죽는 패턴이 2판 반복되면 문구 탐색을 멈추고 근거 주입 (명단 · 메타데이터) 을 설계한다 (`docs/troubleshooting/2026-08-08-prompt-wording-seesaw-on-boundary-cases.md`).

## 5. 명단 주입의 시차 원칙

소급 재분류 시점의 명단 (예: 기마랑이스 = 완료) 이 과거 기사에도 주입되므로, "명단에 완료면 done" 으로 설계하면 사가 초반 협상 기사까지 done 으로 쏠린다.

- 1차 기준은 **기사 자체가 전하는 시점 상태**다 — 협상 보도는 협상이다.
- 명단은 "이 딜이 완료 상태임" 을 알려 후속 · 회고류 판정을 돕는 **보조 근거**로만 쓴다.
- dry-run 과잉 그룹의 사가 초반 기사 (§6) 가 이 원칙의 검증 표본이다.

### 6.2 적용 회차 재검증 · 채택 (2026-08-10 ~ 08-11 · v1b 기각 · v1c 채택)

§6.1 의 잔여 결함 2유형을 표적으로 문안을 보강해 같은 기대값 40행 (판당 2회) 으로 재검증했다.
채점 기대값 2행은 §3.2 재조정 (하이재킹 완결 = 무산 · 방향은 시도했던 축) 을 반영해 갱신했다 — 로저스 28ae2559 · 몽가 745f1094 = collapsed · in.

- **v1b 기각 (시소 1판째)** — 정의 머리 좁힘 + "기사에 구단 미등장이면 collapsed 불가" 차단 + 방향 줄 축약을 한꺼번에 넣자, 로메로는 고쳐졌으나 비니시우스 잔류 확정 2건이 other 로 추락하는 등 회귀 5건.
잔류 판정에 필요한 "아스날 영입 대상" 근거가 입력에 없어 문구가 세계 지식 활용까지 차단한 것 — 시소 트러블슈팅 (2026-08-08) 과 같은 뿌리다.
- **v1c 채택** — v1 원문에서 두 문장만 변경: 주관점 문장 → 하이재킹 단순화 문장 (§3.2) · collapsed 정의 끝에 협상 · 매각 거부 방침 차단 한 문장.
로메로 · 하이재킹 2행 · 비니시우스 2행 · 토미야스 · 디오망데 전부 2회 반복 안정 통과.
- **알려진 한계 (사용자 확정 2026-08-11)** — v1c 의 신규 손실 2건 (로저스 회고 61f2f088 은 원제 · 요약이 서로 다른 행 · fe031baa 는 펀딧 권고의 rumour ↔ interest 진동) 은 시소 2판째 신호로 문구 탐색을 중단하고 수용했다.
근본 해법 (명단 주입) 은 명단 정리 세션의 값 갱신 뒤 재평가한다.
- **소급 후 수동 정정 목록 (눈검수 리포트에 포함)** — 로드리 a72f428a (negotiating 또는 other · none) · 로저스 회고 61f2f088 (collapsed · in) · 촐리스 1bdc581a (done · in) · 펀딧 fe031baa · d30835af (rumour · in) — 실제 소급 결과를 보고 어긋난 것만 정정한다.
- **미검증 경계 2건 (코드 리뷰 발견 · 눈검수에서 유형 확인)** — ① 아스날 자체 스쿼드 재계약 기사 (dry-run 표본에 없음 · collapsed 의 재계약 문구에 걸리면 안 되고 other 가 정답) ② 선수 단위 잔류 조항의 collapsed 개정 (PLAYERS_CLAUSE 가 구 체계의 other 지시와 모순돼 동기화했으나 소표본 미검증 — 기사-선수 어긋남 지표 재측정으로 확인).
- **재확인 사례 추가 (병렬 세션 인계 · §7 목록의 보강)** — `ef722e49` (goal · 2026-08-09 「아스날, 브루노 기마랑이스 영입 후 수비멘디에 거액 이적료 책정」) 은 아스날이 파는 건인데 방향이 in 으로 저장돼 있다.
소급 후 out 으로 교정됐는지 확인한다 — 번역 제목이 원제의 경쟁 구단 언급을 떨어뜨려 방출 신호가 약한 행이라, 방향 축 교정의 난도 표본이기도 하다.
- 하네스 · 원 출력: `assets/2026-08-10-stage-dryrun/` 의 v1b_dryrun.py · v1c_dryrun.py · result_v1b_* · result_v1c_*.
- 파생 기록: 단계 필터 in · out 한정 (§8) 에 따라 방향이 none 으로 규칙 고정된 bbc_gossip 기사가 루머 계수 · 필터 목록에서 빠진다.
가십 도달 경로는 가십 밴드 · 전체 목록으로 유지된다.
- 파생 기록 2 (코드 리뷰 발견 · §8 개정으로 해소): collapsed 의 방향 분포가 none 우세라 게이트를 그대로 걸면 무산 필터가 제 내용물을 잃는다.
스펙 회차에 collapsed 방향 분포 실측이 없어 두 결정 (필터 한정 · 무산 신설) 의 충돌이 설계 단계에서 보이지 않았다.
- 파생 기록 3 (코드 리뷰 발견): 톱스토리 · 결말 카드의 단계 가중치 (`_LEAD_STAGE_RANK`) 에 신설 enum 을 넣지 않으면, 완료 보도가 미등재 (가중치 0) 로 추락하고 하이재킹 완결이 collapsed 가 되면서 결말 카드가 주 사용처에서 사라진다.
done 은 종전 agreed 자리를 잇고 collapsed 는 결말 카드 문턱 (1) 을 넘도록 편입했다.

## 7. 소급 재분류 계획 (다음 회차)

- 대상: 분류 전건 약 606건 — **단계와 방향을 함께** NULL 복원 → 분류 패스 재실행 (기존 멱등 런북 경로 · 최대 3패스 수렴 · fetch 없음).
호출 약 35 ~ 40회 · 비용 수백 원 미만 — 단 Gemini Tier 1 선불이므로 실행 전 승인을 받는다.
- 선행: DB 백업 덤프 · before 분포 재측정.
- 검증: 전후 분포 비교표 + 이적 합의 · 완료 · 무산 전건 제목 눈검수 리포트 + 알려진 사례 재확인:
몽가 745f1094 · 로저스 하이재킹 28ae2559 (무산 · in — §3.2 재조정 규칙) · 노르가르 표기 2건 (방향 out) · 비니시우스 잔류 4건 (무산) · 드 마샬크 2건 (기타) · 트로사르 공홈 2건 (오피셜 유지) · 기마랑이스 사가 3층 분해 (§3.1) · 토미야스 2건 (방향 none).
- 재분류 후 재렌더 · 표시 계층 확인까지가 완료 조건이다.
- 예상 분포 (agreed 표본 20건 환산 · 참고치): agreed 121 → 이적 합의 약 30 · 협상 중 +35 · 완료 약 45 · 무산 · 기타 소수.
"이적 합의 > 협상 중" 역전이 구조적으로 해소된다.

## 8. 표시 계층 설계 (구현은 다음 회차 · serve 필드 조율)

- **단계 필터 in · out 한정** — 사이드바 단계 필터의 계수와 목록을 방향 in · out (아스날 주체) 기사로 한정한다.
타 구단 딜 (none) 은 DB 분류를 유지한 채 필터 분모에서만 빠지고, 전체 목록 · 팀 facet (구단 칩) · 사건 묶음 · 선수 필터로는 계속 도달된다.
이 설계에서는 방향 값이 필터 노출을 좌우하므로 **방향 재분류 (§7) 의 정확도가 선행 조건**이다.
- **무산은 방향 게이트의 예외다 (개정 2026-08-11 · 사용자 확정)** — collapsed 는 정의상 아스날 관련 딜의 종결에만 붙는 관점 값이라 "타 구단 딜 제외" 라는 한정의 취지가 분류 단계에서 이미 충족돼 있다.
방향까지 걸면 잔류 확정 · 재계약 체결 (dry-run 실측상 방향 none · 하이재킹만 in) 이 자기 필터에서 빠져, 카드에는 무산 배지가 보이는데 사이드바 건수는 0 에 가깝고 필터를 체크하면 사라지는 불일치가 생긴다.
무산 신설의 동기 자체가 "사가 결말이 기본 숨김 버킷으로 사라진다" 였으므로 필터 도달 가능성을 우선한다.
대가로 타 구단 무산 침범 (§6.1 의 로드리 유형) 이 필터에 노출되므로 눈검수 · 수동 정정으로 관리한다.
판정은 `render.in_stage_filter()` 와 app.js 가 같은 규칙을 공유한다.
- **사건 묶음 · 클럽 칩과 독립** — 카드 배지 (단계) · 클럽 칩 (팀 축) · 묶음 소그룹 (이벤트 클러스터링) 은 별개 기계로 불변이다.
재분류 후에는 같은 묶음 안에서 타 구단 성사 = 이적 합의 → 완료, 아스날 쪽 = 무산으로 갈라져 묶음의 이야기 구조가 선명해진다.
- **사다리와의 관계** — 사다리 정렬 기준은 `render._STAGE_DISPLAY_GROUPS` 순서다 (2026-08-05 사다리 스펙 §4.1).
완료는 오피셜 아래 진행 최상단에 삽입하고, **무산은 진행 단계가 아니므로 사다리 축에 넣지 않고 종결 표시로 처리**한다.
구체 화면은 다음 회차 serve 세션 몫이다.

## 9. 멀티 클럽 확장 대비

빅6 확장 의향 (사용자 · 2026-08-01) 을 고려한 제약을 명시한다.

- 단계 축은 딜 자체의 속성이라 확장에 안전하다.
- **방향 축과 무산은 관점 값이다** — 같은 기사가 첼시 관점에선 in/완료, 아스날 관점에선 none/무산이다.
단일 컬럼 방향은 멀티 클럽에서 구조적으로 깨지므로, 확장 착수 시 구단별 관점 분리 (관점 테이블 또는 구단 주입 재분류) 가 선행이다.
- 이번 개정에서는 프롬프트의 구단명을 `{club}` 파라미터로 빼 두는 것까지만 한다 — 확장 시 프롬프트 재작성 없이 구단명 주입으로 간다.
"아스날 = 전부" 하드코딩 경계 원칙과 같은 줄기다.
- **확장 착수 시 무산 · 방향은 대상 전 구단에 대해 재도출한다** — collapsed 행이 재도출 1순위다.
하이재킹 무산 규칙 (§3.2) 을 골라도 관점 오염이 새로 생기는 것이 아니다 — 잔류 확정 (타 구단의 재계약 성사) 같은 무산 값 자체가 태생적으로 관점 값이라, 어느 규칙이든 확장 시 재도출은 같은 크기로 필요하다.
- 확장 전까지 `transfer_stage` 의 collapsed 와 `transfer_direction` 은 **아스날 관점 값**이다.
다른 소비자 (분석 · 알림) 가 구단 중립 값으로 오용하지 않도록 스키마 주석 수준으로 명시한다 (구현 회차).
