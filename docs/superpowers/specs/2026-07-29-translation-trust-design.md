# 번역 신뢰성 — 원문 없이 생성된 본문 정리 · 재발 방지 설계 (2026-07-29)

배포판에 원문 본문 없이 제목만으로 만들어진 한국어 본문이 섞여 있다는 것이 2026-07-28 감사에서 드러났다.
이 문서는 그 범위를 다시 측정해 실제 대상을 가려내고, 대상별 처리 방침과 재발 방지 장치를 정한 설계다.
브레인스토밍 과정에서 프롬프트 다섯 판본과 게이트 조합을 실제로 돌려 비교했으므로, 근거가 되는 수치를 6절에 함께 싣는다.

## 1. 문제

- 확인된 피해 : https://bullet-in.pages.dev/article/096b26b9772dc5374ce5b83da59c5c575ee9fc7c484db9004a2b955a3580310f
— 방출 선수 15명 명단 전체가 지어낸 것이었다.
- 원인은 `enrich.py:364` 다.
`body=r.get("body_source") or r.get("body_excerpt") or ""` 로 빈 문자열을 넘기는데, `TRANSLATE_PROMPT` 는 "본문 전체를 완역하라" 고 지시한다.
번역할 원문이 없는데 완역을 요구하니 모델이 빈칸을 채워 넣는다.
- 요약도 같은 호출에서 나온다 (`_extract_full` 이 네 필드를 한 응답에서 꺼낸다).
그래서 `body_ko` 만 지우고 요약을 남기는 처리는 성립하지 않는다.

## 2. 범위

이번 설계가 다루는 것.

다루지 않는 것.

- 트윗 81건 (`x_afcstuff` · `x_ornstein`) — `title_original` 에 트윗 전문이 있어 재료가 갖춰져 있다 (6.1절).
- The Athletic 퍼가기 금지 정책 개정 (E안 트랙) — 별도 세션.
이번 설계의 프롬프트 · 게이트는 그 트랙이 그대로 재사용한다.

다만 바이라인은 이번 게이트에 직접 영향을 주므로 예외로 처리한다 (4.1절).

## 4. 설계

### 4.1. 수집 — 본문 확보 경로를 바꾼다

원문 기사를 다시 수집하는 방법은 쓸 수 없다.
26건 URL 을 1회 재수집한 결과 본문을 얻은 것은 1건뿐이다 (6.2절).
매체 쪽 차단이고 프록시와 무관하다.

그래서 어댑터를 이렇게 고친다.

- `fmkorea.py` 의 `else` 분기에서 원문 기사 접속에 실패하면, 이미 받아 둔 게시글 HTML 에서 본문을 꺼내 쓴다.
`_is_repost_blocked` 가 참이면 지금처럼 본문 없이 진행한다.
- 이 경로는 새로 만드는 것이 아니다.
The Athletic 이 퍼가기 금지가 아닐 때 이미 같은 방식으로 동작한다 (`fmkorea.py:229`).
- `body_source` 에서 바이라인 (기자명 · 발행 날짜 · 시각) 을 걷어낸 뒤 저장한다.
기자와 발행 시각은 `journalist` · `published_at` 필드로 이미 따로 뽑고 있어 본문에 중복으로 남을 이유가 없다.
바이라인을 남겨 두면 게이트가 발행 시각을 "빠진 정보" 로 잡아 모델이 그 줄을 본문에 옮기게 된다 (6.4절 실측).

### 4.2. 라우팅 — 매체명이 아니라 본문 언어로 가른다

`partition_by_paywall` (`enrich.py:351`) 은 `outlet` 이 `PAYWALLED_OUTLETS` 에 있는지만 본다.
게시글 본문을 채택한 행은 `outlet` 이 The Telegraph 이므로 번역 모드로 가고, 한국어를 한국어로 "번역" 하게 된다.

- 어댑터가 담는 `lang` 값은 저장되지 않는다 (`models.py` 에 필드가 없고 `rows_missing_translation` 도 뽑지 않는다).
- 매체명 문자열로 갈라내는 방식은 애초에 취약하다.
배포판에 `더 선` · `더선` · `더썬`, `Sky` · `Sky Sports` · `스카이스포츠`, `아스` · `AS`, `메일` · `데일리 메일` · `Daily Mail` · `DM+` 이 따로 존재한다.
- 본문이 한국어인지를 저장해 그것으로 가른다.
컬럼 추가와 기존 행 소급 설정은 구현 단계에서 정한다.

### 4.3. 생성 — 프롬프트를 개정한다

현행 `PARAPHRASE_PROMPT` 에 두 묶음을 더한다.

완역 · 수치 보존.

```
- body_ko 는 요약이 아니라 전문 재작성이다: 원문의 모든 문단을 순서대로 빠짐없이 옮기고,
  수치 · 인용 · 세부 사실을 임의로 줄이거나 합치지 않는다.
- 원문에 나오는 모든 숫자 (금액 · 나이 · 연도 · 경기 수 · 기록) 를 하나도 빠뜨리지 않는다.
```

주입 금지.

```
- 원문에 없는 소제목을 만들지 않는다. 원문에 소제목이 없으면 산출물에도 소제목이 없다.
- 원문에 없는 수식어 · 부사 · 역할 명칭 (미드필더 · 공격수 · 감독 등) 을 붙이지 않는다.
- 원문에 없는 시간 · 정도 표현 (즉시 · 이미 · 크게 · 확고히 · 전격 등) 을 넣지 않는다.
- 숫자는 원문 표기를 그대로 쓴다 (£50m 을 5,000만 파운드로 바꾸지 않는다).
- 원문이 단정한 것을 추측으로, 추측한 것을 단정으로 바꾸지 않는다.
```

조사 · 어순만 바꾸는 방식은 채택하지 않는다.
충실도는 가장 높지만 44건 중 43건이 원문 텍스트의 절반 이상을 그대로 담았고 최고치가 0.996 이었다 (6.3절).

### 4.4. 게이트 — 두 방향으로 걸되 본문을 버리지 않는다

```
① 개정 프롬프트로 생성
② 누락 게이트  — 원문 숫자가 산출물에 남았는가
③ 복제 게이트  — 글자 8-gram 잔존율이 임계값 이하인가
④ 하나라도 걸리면 사유를 붙여 재생성 (최대 2회)
⑤ 세 시도 중 최선을 채택 — 누락이 없는 것 중 잔존율이 가장 낮은 것
⑥ 잔존율이 높게 남은 행은 ops 목록에 올려 사람이 확인
```

두 게이트는 규칙만으로 판정하는 코드이고 LLM 을 쓰지 않는다.
숫자 비교는 단위 환산 (`£50m` 과 `5,000만`) 을 같은 값으로 취급한다.

**게이트는 재생성 트리거이지 폐기 조건이 아니다.**
누락이나 복제를 이유로 본문을 버리면 멀쩡한 본문이 사라진다.
44건에 폐기 규칙을 적용했을 때 4건이 본문을 잃었는데, 그 4건은 재생성으로 오히려 개선된 행이었다 (저장본 누락 15개 → 1개 등).

재생성 지시는 이렇게 붙인다.

```
[누락]  직전 시도에서 다음 숫자가 누락됐다 — 46, 2031.
        이 수치들을 원문 맥락 그대로 반드시 포함한다.
[복제]  직전 시도는 원문 표현을 지나치게 그대로 옮겼다.
        사실 · 수치 · 인용은 그대로 두되 문장 구성과 표현을 크게 바꿔 다시 쓴다.
        단 원문에 없는 내용 · 수식어 · 소제목을 새로 넣지 않는다.
```

복제 지시에 주입 금지를 함께 붙이는 것이 중요하다.
붙이지 않으면 모델이 표현을 바꿀 여지를 원문에 없는 내용을 넣어 만들어 낸다.

### 4.5. 재발 방지 — 재료가 없으면 생성하지 않는다

`body_source` 와 `body_excerpt` 가 모두 비어 있고 `source_id` 가 `BODY_AS_TITLE_SOURCES` 밖이면, `body_ko` · `summary_ko` · `summary3_ko` 를 생성하지 않는다.

- `BODY_AS_TITLE_SOURCES` 는 `enrich.py:264` 에 이미 있는 상수다 (`{"x_afcstuff", "x_ornstein"}`).
- 배포판 467건에 이 조건을 적용하면 정확히 68건이 걸리고 트윗 81건은 통과한다.
- `url` 기준으로 판정하면 안 된다.
`x_ornstein` 4건 중 1건은 URL 이 The Athletic 기사로 리졸브돼 있지만 `title_original` 은 여전히 255자 트윗 전문이다.
- 이 상태의 행은 제목 · 메타 · 원문 링크만 서빙한다.
템플릿의 요약 출력은 전부 조건문으로 감싸여 있어 (`_cards.html.j2:13` · `detail.html.j2:11` · `:24`) 마크업 변경 없이 그려진다.
`detail.html.j2:20` 의 자동 번역 안내문만 상황에 맞게 바꾼다.

### 4.6. football.london — 소스를 제거한다

- 사용자 판단 : 저품질 기사가 많고 신뢰할 만한 내용은 상위 티어가 함께 다룬다.
- `config/sources.yaml` 에서 `enabled: false` 로 수집을 끊는다.
- 적재된 95건은 전부 내린다.
42건은 06-28 이전 잔재라 수집을 끊어도 저절로 사라지지 않는다.
- 애그리게이터 (`x_backtrack`) 경로로 들어오는 football.london 기사는 계속 허용한다.
이 경로는 `football_london` 소스와 별개로 동작한다.

처리 방식은 **DB 행 삭제로 확정한다** (2026-07-29).
행을 두고 렌더에서만 빼는 방식과 비교해 정한 것이고, 근거는 아래 세 가지 확인이다.

- `enabled: false` 만으로는 화면에서 사라지지 않는다.
`SERVING_SELECT_SQL` 은 `FROM articles` 전체를 읽으므로 (`run.py:30`) 수집만 끊긴다.
- 옛 상세 페이지 파일은 어느 방식이든 남지 않는다.
`sweep_orphan_pages` (`render.py:708`) 가 렌더 대상에 없는 HTML 을 지운다.
- 배포는 산출물이 50건 미만이면 중단하는 가드를 갖고 있다 (`infra/deploy-site.sh`).
467 에서 372 로 줄어드는 규모는 걸리지 않는다.

삭제를 고른 이유.

- 코드를 고치지 않아도 된다.
행만 지우면 SELECT · 렌더 · 배포가 그대로 동작하고 파일 정리까지 따라온다.
- DB 상태와 화면 상태가 어긋나지 않는다.
렌더에서만 빼면 나중에 "DB 에는 있는데 왜 안 보이는가" 를 다시 조사하게 된다.
- 서빙 제외 목록이라는 새 유지보수 대상이 생기지 않는다.
`SERVING_SELECT_SQL` 은 런북 절차도 함께 쓰는 공용 정의라 의미를 바꾸면 영향 범위가 넓다.
- 행을 남겨서 얻는 유일한 이점인 데이터 보존은 삭제 전 덤프로 똑같이 얻는다.

실행 절차.

```
① 삭제 대상 95건을 content_hash 포함 전량 덤프 → 저장소 밖 보관
② config/sources.yaml 의 football_london 을 enabled: false
③ DELETE FROM articles WHERE source_id='football_london'   (95행)
④ 렌더 실행 → sweep_orphan_pages 가 상세 페이지 95개 삭제
⑤ 배포 후 건수 확인 (467 → 372 예상)
```

②를 ③보다 먼저 한다.
순서가 바뀌면 다음 회차가 다시 수집한다.

배포판의 상세 페이지 URL 95개는 삭제와 함께 404 가 된다.
외부에 공유된 링크가 끊기는 것은 감수한다.

## 5. 실행 순서

1. football.london 수집 중단 · 덤프 · 95건 제거.

표본은 별도 표기가 없으면 배포판 사본 `bulletin_mock` 467건이다 (2026-07-27 21:02 수집분).
프롬프트 비교의 표본은 `fmkorea` × The Athletic 44건이다.
이 44건은 게시글 본문을 재료로 쓰는 유일한 모집단이라, 4.1절 이후의 26건이 어떻게 처리될지를 미리 보여 준다.

### 6.1. 트윗을 제외한 근거

```sql
SELECT CASE WHEN source_id IN ('x_afcstuff','x_ornstein') THEN 'A. 트윗'
            WHEN (body_source IS NULL OR body_source='') THEN 'B. 기사인데 원문 본문 없음'
            ELSE 'C. 원문 본문 있음' END AS 구분,
       COUNT(*), MAX(CHAR_LENGTH(body_ko)/NULLIF(CHAR_LENGTH(title_original)
         +CHAR_LENGTH(COALESCE(body_source,''))+CHAR_LENGTH(COALESCE(body_excerpt,'')),0))
FROM bulletin_mock.articles WHERE body_ko<>'' GROUP BY 구분;
```

트윗 86건의 비율 상한이 1.03 이고 원문 본문이 있는 313건은 0.59 다.
반면 B 는 최대 15.26 이다.

### 6.2. 원문 재수집 실패

26건 URL 을 프로덕션과 같은 경로 (`extract_article_body`) 로 1회 접속했다.

```
상태 분포 {'200': 8, '406': 11, '403': 7} · 본문 200자 이상 확보 1/26
```

| 매체 | 건수 | 응답 |
| --- | --- | --- |
| BeSoccer | 11 | 406 |
| The Telegraph | 6 | 403 |
| The Times | 2 | 200 (페이월 화면) |
| A BOLA · BB · Daily Mail · 메일 · ESPN | 5 | 200 (본문 추출 실패) |
| 하늘운동 (sport.sky.de) | 1 | 403 |
| 아스 (as.com) | 1 | 200 · 본문 2,226자 |

브라우저 헤더를 붙여 재시도해도 406 · 403 이 그대로였다.
로컬에서 프록시 없이 접속한 결과이므로 프록시가 원인이라는 가설은 성립하지 않는다.

그 과정에서 URL 품질 문제도 함께 확인했다.
`991b2bce` 는 `outlet` 이 ESPN 인데 URL 은 thetimes.com 이고, `c7a304e4` 는 기자 프로필 페이지, `2486986a` 는 pressreader 지면 페이지, `0d120abf` 는 t.co 단축링크다.

### 6.3. 프롬프트 다섯 판본 비교

같은 프롬프트를 두 번씩 돌려 모델 흔들림과 실제 차이를 갈랐다.
숫자 누락과 주입은 단위 환산으로 설명되는 것을 걷어낸 값이다.

| 판본 | 누락 | 주입 | 없던 소제목 | 신규 어절 | 잔존 (글자) | 0.90 초과 |
| --- | --- | --- | --- | --- | --- | --- |
| 저장본 (현행 프롬프트) | 17% | 4개 | 33개 | 38% | 0.373 | 0건 |
| 완역 조항 추가 | 4% | 5~8개 | 21~29개 | 33% | 0.451~0.464 | 0건 |
| **완역 + 주입 금지 (채택)** | 3~4% | 1개 | 9~10개 | 19~21% | 0.632~0.680 | 3~8건 |
| 조사 유지 · 어순 변경 | 2% | 2개 | 0개 | 7~8% | 0.758~0.767 | 6건 |
| 유의어 치환만 | 3% | 0~2개 | 0개 | 20~21% | 0.651~0.669 | 2~3건 |

잔존율은 산출물의 글자 8-gram 중 원문에도 있는 것의 비율이다.
모델 흔들림은 잔존율 평균 절대 차 0.06~0.14 이고 프롬프트 사이 차이는 0.22~0.33 이므로, 표의 차이는 흔들림으로 설명되지 않는다.

여기서 얻은 것이 이번 설계의 핵심이다.
**주입 · 누락 · 복제 셋을 동시에 만족하는 프롬프트는 없다.**
주입을 막으면 쓸 수 있는 재료가 원문뿐이라 표현이 원문을 따라가고, 표현을 다듬으면 주입과 누락이 돌아온다.
그래서 프롬프트 하나로 해결하지 않고 게이트를 붙인다.

### 6.4. 바이라인 결함

첫 파이프라인 실측에서 통과하지 못한 5건 중 3건이 발행 날짜 · 시각 때문이었다.

```
0d4588aa 누락 ['2026']            'By David Ornstein June 19, 2026 3:19 am' 유래
52b02702 누락 ['2','2026','46']    'By James McNicholas … July 3, 2026 Updated 2:46 am' 유래
cf37ebc2 누락 ['18','20','2026']   'By Art de Roché May 18, 2026 1:20 pm' 유래
```

원문 숫자 813개 중 54개 (7%) 가 바이라인에서 온다.
게이트가 이것을 채우라고 하면 모델은 바이라인 줄을 옮기는 수밖에 없고 (발행 시각은 바꿔 쓸 수 없다), 그러면 잔존율이 오른다.
다시 표현을 바꾸라고 하면 숫자가 빠진다.
실제로 `126556af` 산출물에 "해당 내용은 2026년 6월 27일 12:32 am 기준 디 애슬레틱의 보도에 담겼다" 라는 문장이 생겼다.

바이라인을 숫자 집합에서 제외하자 재시도 없이 통과하는 행이 27건에서 32건으로 늘고 호출이 73회에서 64회로 줄었다.
다만 4.1절대로 `body_source` 자체에서 걷어내야 모델이 옮길 여지까지 사라진다.

### 6.5. 파이프라인 실측

게이트를 재생성 트리거로만 쓰고 세 시도 중 최선을 채택하는 규칙으로 44건을 판정한 결과다.

```
44/44 전부 본문 제공 · 숫자 누락 총 0개
잔존율 최소 0.18 · 중앙 0.53 · 최대 0.93
잔존율 0.75 초과 4건 (0.934 · 0.919 · 0.809 · 0.775)
```

재시도를 거듭해도 결과가 좋아졌다 나빠졌다 하지는 않았다.
재시도 24회 중 누락이 늘어난 것이 4회 · 잔존이 오른 것이 7회이고, 평균 변화는 누락 -1.17개 · 잔존 -0.243 으로 양쪽 다 개선 방향이다.

임계값 0.75 는 근거가 약하다.
저장본 최대 0.63 과 완역 조항 판본 최대 0.86 사이에서 임의로 골랐다.

본문을 버리지 않는 설계에서는 임계값이 본문의 생사를 정하지 않는다.
어느 값이든 44건 전부 본문이 나오고, 임계값이 바꾸는 것은 재시도 횟수와 채택본의 잔존율뿐이다.

| 임계값 | 호출 | 재시도한 행 | 채택본 잔존율 중앙 | 잔존율 0.80 초과 |
| --- | --- | --- | --- | --- |
| 0.60 ~ 0.75 | 60회 | 12건 | 0.534 | 3건 |
| 0.80 | 55회 | 8건 | 0.585 | 3건 |
| 0.85 ~ 0.90 | 53회 | 7건 | 0.585 | 3건 |

기록된 시도가 0.75 기준으로 생성됐으므로 이 표는 근사치이고, **0.75 아래 구간은 이 데이터로 평가할 수 없다**.
0.60 으로 조이면 재시도가 더 붙어 잔존율이 더 내려갈 수 있으나 확인하려면 새로 돌려야 한다.

값은 구현 후 실제 `fmkorea` 26건에 돌려 보고 정한다.
지금 표본은 The Athletic 44건이라 매체와 문체가 다르고, 0.75 와 0.85 의 차이가 호출 7회 수준이라 미리 정밀하게 고를 실익이 적다.

## 7. 검증 기준

- `fmkorea` 26건 재생성 후 `body_source` 가 빈 행이 0건이 되거나, 남은 행은 퍼가기 금지 표식이 확인된 것뿐이다.
- 재생성한 행에서 숫자 누락이 0개다 (단위 환산 · 바이라인 제외 기준).
- 잔존율 0.75 를 넘는 행 목록이 ops 에 노출되고 건수가 기록된다.
- 재발 방지 게이트 단위 테스트 — `body_source` · `body_excerpt` 가 비고 `source_id` 가 트윗 소스가 아니면 생성 대상에서 빠진다.
트윗 소스는 빠지지 않는다.
- football.london 행 제거 후 배포판 건수가 예상과 일치하고, 기자 필터 · 언론사 목록에 잔재가 없다.
- 로컬 렌더로 본문 없는 행의 상세 페이지가 깨지지 않는지 확인한다.

## 8. 미결 · 한계

**미결**

- 복제 게이트 임계값 — 0.75 로 시작하되 구현 후 실제 `fmkorea` 26건의 분포를 보고 확정한다 (6.5절).
본문의 생사를 정하는 값이 아니라 재시도 횟수를 정하는 값이므로 착수를 막지 않는다.
- 본문 언어를 어디에 저장할지 — 컬럼 추가 대 다른 방법 (4.2절).

**한계 — 이 설계로 해결되지 않는 것**

- 게시자 오역은 잡을 수 없다.
게이트는 전부 "원문과 다른가" 를 보므로 원문 자체가 틀리면 통과한다.
실물 : https://bullet-in.pages.dev/article/8210fbfdc38d640180941da3d32a55975bc57a0f6b3dff909ce05d4f59f7b995
— 게시자가 Jean-Philippe Mateta 를 "앙리필리프 마테타" 로 적었고 그대로 서빙 중이다.
`config/name_map.yaml` 에 표기를 넣으면 개별 건은 잡히지만 사전에 없는 이름은 남는다.
- 어휘 주입은 코드로 잡히지 않는다.
숫자와 소제목은 잡히지만 "미드필더" · "즉시" 같은 수식은 프롬프트로만 억제한다.
- 바이라인 제거 정규식은 본문이 진짜로 날짜를 언급하면 함께 지운다.
현 표본에서는 바이라인에만 나타났다.
- 프롬프트 · 게이트 수치는 The Athletic 44건 표본이다.
`fmkorea` 26건은 The Telegraph · The Times · BeSoccer 계열 게시글이라 같은 값이 나올지는 확인되지 않았다.
- 잔존율 0.9 를 넘는 행이 남는다 (44건 중 2건).
본문을 버리지 않기로 했으므로 ops 확인으로 관리한다.
