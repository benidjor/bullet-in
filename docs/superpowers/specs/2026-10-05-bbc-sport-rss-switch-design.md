# BBC Sport 수집을 팀 페이지에서 아스날 RSS 로 옮기는 설계 (2026-10-05)

## 1. 배경

### 1.1. 문제

BBC Sport 는 아스날 팀 페이지 (`https://www.bbc.com/sport/football/teams/arsenal`) 를 HTML 어댑터로 읽는다.
목록에서 기사 링크를 고르고, 링크 안의 제목 칸 (`LinkPostHeadline`) 에서 제목을 얻은 뒤 이적 키워드로 거른다.

팀 페이지가 기사 카드 목록에서 짧은 글이 이어지는 피드 모양으로 바뀌었다.
제목 칸이 있는 카드는 거의 없고, 나머지 링크는 피드 글 본문 속 링크라 제목을 얻지 못한다.
제목이 확인되지 않은 링크는 키워드 검사까지 가지 못하고 버려진다.

2026-10-02 SLO-5 재설계 (#515) 뒤로 이 소스는 「제목 확인 비율이 절반 미만」 으로 무응답이 이어져 끊김으로 판정된다.
SLO-5 는 그 뒤로 계속 1 (미달) 이다.

경위는 `docs/troubleshooting/2026-10-02-bbc-sport-missed-most-articles-for-a-month-without-a-signal.md` 에 있다.
이 설계는 안건 2ω 의 첫 조각이다 (§7).

## 2. 수집 경로

### 2.1. RSS 어댑터가 하는 일

`adapters/rss.py` 의 `RssAdapter` 를 HTML 어댑터와 같은 수준으로 키운다.
지금 rss 어댑터를 쓰는 소스는 0개라 다른 소스에는 영향이 없다.

| 단계 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 피드 받기 | `feedparser.parse(주소)` | `httpx` 로 받고 본문만 `feedparser` 로 해석 |
| 중복 · 목록 지문 | 없음 | 주소 중복 제거 · 목록 지문 (`list_sig`) |
| 키워드 필터 | 없음 | 설정의 `title_contains` |
| 본문 · 이미지 · 저자 | 피드 요약만 | `body_selector` 가 있으면 기사 페이지에서 추출 |
| 발행 시각 | 피드 문자열 그대로 | 피드 발행 시각을 싣고, 기사 페이지에서 더 정밀한 값을 얻으면 그 값 |
| 수집 단계 기록 | 없음 | `entries` · `deduped` · `passed` · `list_sig` |

### 2.2. 피드를 httpx 로 받는 이유

`feedparser.parse(주소)` 는 HTTP 오류나 해석 실패에도 예외를 내지 않고 빈 목록을 돌려준다.
그러면 피드가 죽어도 「새 글 없음」 과 구별되지 않는다.

`httpx` 로 받으면 HTML 어댑터와 같은 User-Agent · 시간 제한 · 리다이렉트 처리를 쓰고, 상태 코드가 오류면 예외가 난다.
예외는 수집 단계에서 그 소스의 오류로 기록되고, SLO-5 응답 판정이 무응답 (`error`) 으로 본다.

### 2.3. 목록 지문과 키워드

목록 지문은 HTML 어댑터와 같은 규칙을 따른다.
키워드 필터 **앞**의 주소 묶음으로 만들어, 키워드에 걸리는 글이 없어도 목록이 바뀌면 지문이 바뀐다.

키워드는 피드 항목의 제목에 건다.
설정에 `title_contains` 가 없으면 모든 항목을 통과시킨다 (지금의 동작).

### 2.4. 기사 페이지에서 본문 받기

HTML 어댑터의 상세 받기 코드 (본문 · 대표 이미지 · 본문 이미지 · 저자 · 발행 시각) 를 함수로 떼어 두 어댑터가 함께 쓴다.
코드를 복사하지 않는 이유는, BBC 가 RSS 로 옮겨도 본문과 저자를 HTML 시절과 같은 코드로 읽어야 하기 때문이다.
전담 기자 (Sami Mokbel) 의 등급 승격은 저자 이름으로 판정하므로 저자 추출이 같아야 한다.

상세 받기가 HTTP 오류로 실패하면 지금처럼 제목만 남기고 본문을 비운다.

### 2.5. 기사 주소 규칙

`canonical.py` 의 추적 인자 목록에 `at_medium` · `at_campaign` 을 더한다.
지금 이 인자가 든 저장 주소가 0건이라, 기존 행의 `content_hash` 는 바뀌지 않는다 (§1.2.3).

추적 인자는 앞부분 일치로 지운다.
`at_` 전체를 지우지 않고 두 이름만 넣는 이유는, 다른 사이트의 정상 인자를 지우지 않기 위해서다.

### 2.6. 설정

`config/sources.yaml` 의 `bbc_sport` 항목을 이렇게 바꾼다.

| 키 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| `adapter` | `html` | `rss` |
| `config.list_url` · `item_selector` · `title_selector` | 팀 페이지와 셀렉터 | 없앰 |
| `config.feed_url` | 없음 | 아스날 RSS 주소 |
| `config.title_contains` | `*transfer_kw` | 그대로 |
| `config.body_selector` | `article` | 그대로 |
| `list_unchanged_cap_hours` | 없음 (전역 48) | `240` |

이름 · 등급 (1.5) · 매체 · 서빙 범위 · 신선도 임계 (96h) 는 그대로다.

원본 (`raw_items`) 의 `source_type` 만 `html` 에서 `rss` 로 바뀐다.
`src/` 안에서 이 값으로 분기하는 코드는 없다 (어댑터와 원본을 만드는 일회성 스크립트 둘 · `backfill_journalist.py` · `refetch_urls.py` 가 값을 정할 뿐이다).

## 3. SLO-5 판정

### 3.1. 응답 판정에 rss 분기

지금 `quality.responded` 는 수집 단계 기록이 없으면 어댑터와 무관하게 무응답 (`no_record`) 으로 본다.
기록이 있으면 html · x_playwright · fmkorea 만 따로 보고, 나머지 어댑터는 응답으로 본다.

지금의 RSS 어댑터는 기록을 남기지 않아, 그대로 전환하면 BBC Sport 는 계속 무응답이다.
반대로 기록을 더하면서 rss 분기를 두지 않으면, 피드 항목이 0개여도 응답으로 떨어진다.
그래서 기록과 분기를 함께 넣는다.

| 경우 | 판정 | 무응답 사유 |
| --- | --- | --- |
| 피드 받기에서 예외 (HTTP 오류 · 시간 초과 · 해석 실패) | 무응답 | `error` (기존) |
| 수집 단계 기록이 없음 | 무응답 | `no_record` (기존) |
| 피드 항목 0개 | 무응답 | `no_entries` (새 사유) |
| 피드 항목은 있지만 링크가 하나도 없음 | 무응답 | `no_links` (기존) |
| 목록 지문이 없음 | 무응답 | `no_record` (기존) |
| 그 밖 | 응답 | — |

끊김 규칙은 바꾸지 않는다.
무응답이 2회 연속이면 끊김이고, 응답하는 동안에는 목록이 상한보다 오래 그대로일 때만 끊김이다.

### 3.2. 목록 상한 240시간

전역 상한 48시간으로는 RSS 가 조용한 주마다 거짓 끊김이 난다 (§1.2.4 의 최장 공백 135.2시간).

| 근거 | 값 |
| --- | --- |
| RSS 항목 사이 최장 공백 (09-10 ~ 10-03 · 24개) | 135.2시간 |
| 이미 쓰는 소스별 상한 | Ornstein 240시간 · Sky Sports 288시간 |
| 정한 값 | 240시간 (관측 최장의 약 1.8배 · Ornstein 과 같음) |

표본은 3주 남짓이고 A매치 휴식기를 포함하지 않는다.
팀 페이지에 09-30 자 「International break can take your mind away from a bad defeat」 글이 있어, 10월 첫째 주부터 휴식기다.
휴식기의 공백은 리그 기간보다 길 수 있어 넉넉하게 잡았다.

상한이 늦게 잡는 고장은 「응답은 하는데 같은 항목만 돌려주는 피드」 하나다.
피드 주소가 죽거나 항목이 0개가 되는 고장은 무응답 2회 연속으로 6시간 안에 잡힌다.

### 3.3. 화면과 알림 문구

| 자리 | 바꾼 뒤 |
| --- | --- |
| 수집 현황 화면의 「수집 단계」 칸 (`serve/ops_view.py`) | 「피드 항목 N · 키워드 N」 |
| 끊김 알림의 「왜 끊김인가」 (`notify.py`) | `no_entries` → 「피드 항목 0개 · N회 연속」 |
| 끊김 알림의 「수집 단계 기록」 (`notify._funnel_lines`) | 피드 항목 · 중복 제거 · 키워드 세 단계 |

## 4. 시험 · 검증 · 배포

### 4.1. 단위 테스트

HTTP 는 기존 어댑터 테스트처럼 `respx` 로 흉내 낸다.

| 대상 | 테스트 |
| --- | --- |
| RSS 어댑터 | 키워드 필터 · 중복 제거 · 목록 지문 · 수집 단계 기록 · 본문 받기 · 발행 시각 · HTTP 오류가 예외로 나오는지 |
| HTML 어댑터 | 상세 받기 코드를 떼어 낸 뒤에도 기존 테스트 전부 통과 |
| 응답 판정 | rss 분기 다섯 경우 (§3.1) |
| 주소 규칙 | `at_medium` · `at_campaign` 제거 (BBC 도메인 통일과 함께) |
| 화면 · 알림 문구 | §3.3 의 세 자리 |

RSS 어댑터 테스트의 픽스처는 2026-10-04 15:55 UTC 에 받은 실제 BBC 피드에서 항목 몇 개를 잘라 만든다.
지어낸 피드는 실제 필드 이름 (`pubDate` · 추적 인자가 붙은 `link`) 을 검증하지 못하기 때문이다.
기존 `tests/fixtures/sample_feed.xml` 은 그대로 둔다.

### 4.2. 머지 전 라이브 검증

워크트리에서 `bbc_sport` 어댑터 하나만 `fetch()` 한다.
접속은 한 번이고 출력은 파일로 받아 둔다.

확인할 값은 피드 항목 수 · 키워드 통과 수 · 항목별 본문 길이 · 저자 · 발행 시각이다.
2026-10-04 기준 기대값은 항목 24 · 키워드 통과 5 이고, 그중 3건은 이미 저장돼 있어 새 기사는 2건 안팎이다.

### 4.3. 배포 뒤 확인

머지하면 다음 실행의 첫 태스크가 코드와 설정을 함께 내려받는다.
운영 DB 를 손으로 고치는 일은 없다.

| 확인 | 기대 |
| --- | --- |
| 수집 현황 화면의 BBC Sport 행 | 「피드 항목 N · 키워드 N」 · 상태가 끊김이 아님 |

## 6. 기각한 대안

### 6.1. 팀 페이지 피드 글을 기사로 읽기

피드 글 하나를 기사 하나로 읽는 방식이다.
RSS 에 없는 짧은 글까지 얻지만, 새 읽기 방식이 필요하고 다른 구단 글을 따로 걸러야 한다.
글의 고유 주소도 페이지 안 앵커라 원문 링크가 약하다.
RSS 를 먼저 넣고 겹침을 잰 뒤 필요하면 따로 정한다 (§5).

### 6.2. 셀렉터를 카드 링크로만 좁히기

본문 속 링크를 대상에서 빼면 제목 확인 비율이 올라가 SLO-5 는 초록이 된다.
하지만 놓치던 기사는 회복되지 않는다.
신호만 끄는 셈이라 기각했다.

### 6.3. 상한을 168시간이나 144시간으로

얼어붙은 피드를 더 빨리 잡지만, 표본에 휴식기가 없어 이번 휴식기에 거짓 끊김이 날 수 있다.
거짓 끊김은 사고 채널 알림과 SLO-5 미달 표시로 이어진다.
240시간으로 시작해 실측으로 다시 정하기로 했다 (§5).

## 7. 범위 밖 (2ω 의 다른 조각)

2ω (비수기 수집 기준) 는 다섯 조각으로 나눴고 이 설계는 첫 조각 ⓐ 다.

| 조각 | 내용 |
| --- | --- |
| ⓑ 비수기 키워드 기준 | 이적이 아닌 아스날 기사를 얼마나 받을지 · 화면 배치 · 번역 비용 |
| ⓒ 원본 발행 시각 저장 | `raw_items` 에 발행 시각 칼럼 |
| ⓓ 바깥 기준 대조 | 목록만으로 조용함과 멈춤을 가르지 못하는 문제 |
