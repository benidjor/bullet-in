# 같은 기자가 한글 · 영문 두 항목으로 갈리는 문제 — 설계 (2026-08-19)

## 1. 배경

사이드바의 기자 목록에 같은 사람이 두 번 나온다.
「제임스 맥니콜라스」 5건과 `James McNicholas` 20건이 별개 항목이고, 어느 쪽을 골라도 그 기자의 기사 절반만 나온다.

접는 장치는 이미 있다.
`credibility.yaml` 에 표기가 있으면 서빙이 영문 정식명으로 접는다 — 온스테인 36건이 그렇게 한 항목으로 돈다.

**막고 있는 것은 「등재하면 공신력이 붙는다」 는 결합이다.**
표기만 통일하려 해도 tier 를 정해야 해서 「이 기자를 얼마나 믿을 것인가」 라는 제품 판단이 따라붙는다.

이 설계는 그 결합을 끊는다.

### 1.2. 사이드바 항목만 세면 규모가 작게 나온다

잔여 안건 메모리의 값은 10종이었고 사이드바 항목 기준으로는 11종이 나온다.
**원자료로 세면 18종 · 23건이다.**

차이의 원인은 사이드바 항목이 만들어지는 규칙이다.
기자 항목은 어느 기사에서든 대표인 이름에만 만들어진다 (`facet_counts` 의 정책 C).
한 번도 대표가 된 적 없는 공저자는 카드에 실려 필터로는 잡히는데 사이드바에는 항목이 없다.

**따라서 이 트랙의 잣대는 사이드바가 아니라 카드 원자료다.**
사이드바 기준 11종은 항목이 있는 것만 센 부분값이다.

## 2. 실측 — 표기만 갈리는 것이 아니다

### 2.1. 공신력도 함께 갈린다

| 표기 | 건수 | 카드에 실린 공신력 |
| --- | --- | --- |
| `James McNicholas` | 20 | 1 · 1.5 · 2 |
| 「제임스 맥니콜라스」 | 5 | 1 · 1.5 |
| `SIMON JONES` | 7 | 3 · 4 |
| 「사이먼 존스」 | 1 | 4 |

같은 사람의 기사인데 배지가 갈린다.
표기 통일은 목록을 합치는 일일 뿐 아니라 **한 기자에게 두 등급이 붙는 상태를 없애는 일**이다.

### 2.2. 한글끼리도 갈린다

「세바스찬 스태포드-블루어」 와 「세바스찬 스태포드-블로어」 가 별개 항목이다.

미등재 표기의 흔들림을 접는 장치는 있다 (`fold_alias_spellings` · 안건 x).
그 장치가 쓰는 `norm_alias` 는 공백과 대소문자만 지우므로 `JAMES SHARPE` 와 `James Sharpe` 는 접지만 「블루어」 와 「블로어」 는 못 접는다.

### 2.3. 언론사에도 같은 갈림이 있다

기자를 재다가 나온 것이라 지시받은 범위 밖이지만, 처방의 한쪽이 겹쳐서 함께 적는다.

## 3. 원인 — tier 가 필수 필드다

`credibility.py` 의 두 자리가 tier 를 무조건 읽는다.

```python
def _build(entries, dest):
    for e in entries or []:
        tier = float(e["tier"])          # tier 없는 항목은 여기서 KeyError

def load_registry(path):
    ...
    jour.setdefault(e["name"].lower(), float(e["tier"]))   # 같은 이유
```

그래서 「표기만 통일하고 등급은 안 매긴다」 를 표현할 방법이 없다.

**반면 서빙이 쓰는 조회 맵은 이미 tier 를 안 본다.**
`journalist_directory` 는 `name` 과 `outlet` 만 읽어 별칭 → 정식명 맵을 만든다.
즉 접기에 필요한 것은 이미 다 있고, 등급 필드가 입구를 막고 있을 뿐이다.

## 4. 처방

### 4.1. tier 를 선택 항목으로 만든다

`_build` 와 `load_registry` 가 tier 없는 항목을 건너뛰게 한다.
그 항목은 `Registry.journalists` 에 안 들어가고 `journalist_directory` 에만 들어간다.

**`journalist_directory` 와 `outlet_directory` 는 안 고친다.**
둘 다 tier 를 안 읽으므로 표기 전용 항목이 그대로 조회 맵에 실린다.

`credibility.yaml` 의 모양은 tier 를 뺀 한 줄이다.

```yaml
# 표기 전용 — 등급은 안 매긴다 (기존 폴백이 그대로 판정)
- {name: Simon Jones, outlet: Daily Mail, aliases: ["사이먼 존스", "SIMON JONES"]}
```

### 4.2. 공신력이 안 붙는 것을 코드로 확인했다

`resolve_tier` 의 세 경로 모두 표기 전용 항목의 영향을 안 받는다.

| 경로 | 등급 산출 | 표기 전용 항목의 영향 |
| --- | --- | --- |
| 고정 소스 | 소스 tier · 등재 기자면 `min(j_tier, tier)` 로 승격 | `registry.journalists` 에 없어 승격 없음 |
| `fmkorea` | 본문에서 등재 별칭을 찾아 `min` | 같은 이유로 안 잡힘 |
| `x_mentions` | 본문 핸들을 등재와 대조 | 같은 이유로 안 잡힘 |

**따라서 카드의 공신력 배지는 한 장도 안 움직인다.**

사이드바의 공신력 묶음도 마찬가지다.
`_journalist_tier` 는 등재 기자면 레지스트리를, 아니면 기사에 저장된 tier 를 쓴다.
표기 전용 항목은 레지스트리 조회가 비어 기사 저장값으로 떨어지므로 지금과 같은 자리에 놓인다.

### 4.3. 언론사는 표시 계층 한 줄이다

`outlet_display` 는 저장된 언론사명이 있으면 그대로 돌려주고 언론사 사전을 안 본다.

```python
# 지금
if row.get("outlet"):
    return row["outlet"]

# 이후 — 이미 인자로 받고 있는 outlet_dir 로 한 번 접는다
if row.get("outlet"):
    return (outlet_dir or {}).get(norm_alias(row["outlet"]), row["outlet"])
```

사전에 없는 40종은 사전에 없으므로 그대로 통과한다.
`articles.outlet` 저장값은 안 건드린다 — 표시 계층에서만 접는다.

**이 함수를 카드 칩 · 사이드바 항목 키 · 상세 페이지 표기가 공유하므로 셋이 함께 바뀐다.**
`?outlet=더선` 형태로 저장해 둔 기존 북마크는 안 맞게 된다.

## 6. 검증

**불변 조건은 「한 사람이 사이드바에 두 항목으로 나오지 않는다」 이다.**

18종 · 23건은 이 회차의 값이고 회차마다 움직인다.
신규 적재분이 계속 새 표기를 들여오므로 건수를 기준선으로 넘기지 않는다.

측정은 배포된 `all.html` 한 장으로 한다.

```
① 카드의 data-journalist 를 | 로 쪼개 이름 목록을 만든다
② 한글이 섞인 표기를 고른다
③ 각각을 journalist_directory 로 조회한다
   → 정식명으로 접히면 통과
   → 접히는 곳이 없으면 미해결 목록에 남긴다
```

배포 전후로 다음 셋이 안 움직여야 한다.

- 카드의 공신력 배지 (§4.2 근거로 안 움직이는 것이 정상)
- 사이드바 공신력 묶음별 건수
- 기사 총수

## 7. 남기는 구멍

**표기 전용 항목의 별칭이 등재 항목의 별칭과 겹치면 조용히 한쪽이 진다.**

`_build` 의 중복 별칭 검사는 tier 있는 항목만 도므로 표기 전용 항목은 그 검사를 안 탄다.
`journalist_directory` 는 `setdefault` 라 yaml 에 먼저 적힌 쪽이 이긴다.

지금 규모 (표기 전용 3종) 에서는 겹칠 여지가 없어 이번엔 적어만 둔다.
겹침 검사를 넣을지는 구현 회차의 판단으로 넘긴다.

「마리오 코르테가나」 는 다른 기사에 `Mario Cortegana` 가 있는 것이라 한 단계 약한 근거다.

조사가 「원문 기사를 열어 바이라인을 읽는다」 에서 **「그 매체의 기자 명단에서 찾는다」** 로 좁혀진다.

### 9.4. 이 재측정이 남기는 규칙

**조사가 필요하다고 적기 전에 가진 재료를 다 세어 본다.**
언론사 쪽에서도 같은 일이 있었다 — 「약칭이 무엇인지는 원문을 봐야 한다」 로 넘긴 아홉 종이 `url` 컬럼을 한 번 조인하니 전부 풀렸다 (언론사 표기 통일 설계 §2.1).
두 번 다 **DB 에 이미 있는 컬럼**이 답을 갖고 있었다.

### 9.5. §5 와 §1.2 의 값은 폐기한다

§5 의 「13종 · 기사 10건」 과 §1.2 의 「18종 23건」 은 소급 전 · 렌더 결과 기준이다.
**이 절의 20종 25건이 정본이다.**

## 10. 다른 트랙의 소급이 이 수치를 움직인다

저자 회수 트랙 (안건 y) 이 저자 미상 기사의 저자를 되살리는 소급을 준비하고 있다.
그 트랙이 사본 실행으로 관측한 값을 전해 왔고, **아래는 우리가 직접 잰 값이 아니라 그쪽 관측이다.**

| 값 | 소급 전 (2026-08-19 15:03 회차) | 소급 반영 뒤 |
| --- | --- | --- |
| 사이드바 기자 항목 | 153종 | 206종 (그쪽 관측) |
| 한글로 남는 표기 | 18종 | **20종** (§9 에서 직접 확인) |

소급은 2026-08-19 14:08 UTC 에 운영에 반영됐고, **예고된 20종을 §9 에서 직접 재서 확인했다.**
새로 들어온 「존 퍼시」 · 「플로리안 플라텐버그」 는 둘 다 갈래 C 다.

### 9.1. 형제 안건 — 사람이 아닌 값이 기자 항목이 된다

저자 회수 트랙이 「소급으로 들어오는 값 7개가 사람이 아니다」 라며 판단을 넘겨 왔다.
**우리 쪽에서 지금 데이터를 재 보니 같은 모양이 이미 있고, 한 덩어리가 아니라 세 갈래다.**

| 갈래 | 지금 데이터의 실물 | 성격 | 조치 |
| --- | --- | --- | --- |
| 매체명이 기자 자리에 옴 | `BBC` 2건 · `GOAL` 2건 | 조직 바이라인 접기가 놓침 | **처리 대상** |
| 편집국 표기 | `Guardian staff reporter` 5건 | 원문이 실제로 그렇게 씀 | 조치 불필요 |
| 소스가 붙인 통칭 라벨 | `BBC Gossip` 76건 · `Arsenal Official` 8건 | `config/sources.yaml` 의 `journalist_label` | 의도된 값 |

**첫 갈래만 우리 문제다.**
`_journalist_view` 에 조직 바이라인을 언론사 정식명으로 접는 규칙이 이미 있는데, 그 판정이 정확한 문자열 일치라 변형을 놓친다.
`GOAL` 은 소스의 표시명과 언론사명이 모두 `Goal.com` 이라 `goal` 과 안 맞아 접히지 않는다.

**그쪽이 전한 7개도 이 세 갈래로 갈린다.**
`ESPN` · `ESPN.com.br` 은 첫 갈래이고, `Redacción Deportes` · `Redazione` 는 둘째 갈래이며, `now.arsenal` · `Imhonlamhen` · `Yan Diomande` 는 진짜 저자다.
**따라서 「매체명 목록으로 걸러내면 정당한 저자도 함께 빠진다」 는 걱정은 갈래를 나누면 사라진다** — 첫 갈래는 언론사 사전으로 판정되므로 목록을 새로 만들 필요가 없다.

**이 안건은 이 스펙에 흡수하지 않는다.**
α 의 축은 「같은 사람이 두 표기로 갈린다」 이고 이것은 「사람이 아닌 값이 기자 자리에 있다」 라 다르다.
지금 규모도 2종 4건으로 작다.
잔여 안건으로 넘기되 이 절을 착수 입력으로 쓴다.
