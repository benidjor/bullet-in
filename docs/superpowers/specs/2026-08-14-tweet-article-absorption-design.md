# 트윗 행을 기사 행으로 흡수하는 설계 (2026-08-14)

같은 기사가 트윗 행과 기사 행으로 갈라져 화면에 여러 항목으로 나오는 문제를 푼다.
안건 k 이고 이 문서는 설계까지다 — 코드 변경과 DB 쓰기는 다음 회차 몫이다.

판단 기준은 2026-07-27 에 사용자가 확정했다.
관련 보도로 접혀 있는지는 중요하지 않다.
묶음은 서로 다른 매체의 보도를 모으는 장치이지 같은 기사의 중복을 가리는 장치가 아니다.

---

## 1. 실측

### 1.1 잣대와 스냅샷

기사 수가 회차마다 움직여서 운영 덤프를 한 시점으로 고정해 쟀다.

- 사본 `bulletin_tweetabs` = 2026-08-14 13:42 KST 운영 덤프 (`articles` · `article_players` · `players`).
- 운영 DB 는 읽기만 했다 · 사본에만 썼다 · Gemini 호출 0.
- 사본 규모 = `articles` 708 · `article_players` 2,584 · `players` 412.

**옛 실측 (2026-07-27 · 트윗 행 79 · 접혀 렌더된 44) 은 값만 낡은 것이 아니다.**
「접혀 렌더된 44건 = 중복 후보 풀」 이라는 **잣대 자체가 틀렸다.**
접힘은 같은 주인공 묶음이라는 뜻이지 같은 기사라는 뜻이 아니라서, 그 수에는 다른 매체의 별개 보도가 대부분 섞여 있다.

### 1.2 후보 풀 — 값마다 잣대를 함께 적는다

| 값 | 잣대 |
| --- | --- |
| 트윗 키 행 163 | `articles` 전건 중 url 호스트가 `x.com` · `twitter.com` |
| x_afcstuff 170 (트윗 키 160 · 기사 키 10) | 같음 · `source_id` 별 |
| x_ornstein 5 (트윗 키 3 · 기사 키 2) | 같음 |
| 서빙에 든 트윗 키 행 163 | `run.serving_rows` 통과분 (서빙 693 중 · fmkorea 무관 제외 15) |
| 관련 보도로 접혀 렌더 120 | `render_index` 로직 재현 · 묶음 대표 · 결말 카드 · 상단 밴드를 뺀 나머지 |

나머지 자리는 묶음 대표 (단독) 12 · 묶음 대표 (관련 있음) 12 · 가십 대표 8 · 가십 숨김 6 · 결말 카드 3 · 상단 밴드 2 다.

### 1.3 원인은 셋이 아니라 넷이다

착수 입력에 적혀 있던 셋을 코드에 대 봤고 하나가 더 나왔다.

**① afcstuff 는 카드를 아예 안 담는다.**

`parse_afcstuff_tweets` 가 `card_href` 를 payload 에 넣지 않는다 (`x_playwright.py`).
넣는 것은 `parse_self_tweets` 뿐이고 그것은 x_ornstein 전용이다.
그래서 저장된 afcstuff 트윗 행에는 **mongo 에도 원문 링크가 없다** — `raw_payload.card_href` 를 가진 x 문서 9건은 전부 x_ornstein 이다.

**이것이 소급 설계를 가른다.**
afcstuff 트윗 행은 URL 로 소급할 방법이 원리적으로 없다.

**② 페이월이면 승격을 포기한다.**

`backtrack_promote` 가 `is_paywalled(final_url)` 이면 트윗 URL 을 유지한다 (`x_backtrack.py`).
VM 저널 전 구간 (2026-07-20 ~ 08-14 · 26일) 에서 그렇게 포기한 고유 기사가 8건이고 전부 The Athletic 이다.

| 7469603 비니시우스 | `4c869ed2` fmkorea |

즉 흡수가 켜져 있었다면 그 6건은 트윗 행이 애초에 안 생겼다.

**③ URL 정규화가 좁다.**

**④ 호스트 별칭이 안 접힌다 (착수 입력에 없던 것).**

`canonical_url` 은 호스트를 소문자로만 바꾸고 발행사의 다른 도메인을 접지 않는다.
같은 BBC 기사가 `www.bbc.co.uk` 와 `www.bbc.com` 으로 두 행이 된 것이 3묶음 6행이다.

### 1.4 확장 정규화의 효과 — 5묶음 10행이 5행이 된다

before 목록 = 현재 708행에서 출발해 셌다.

- 추적 파라미터 확대 + 호스트 별칭 접기 → 키 708 → 703 · **5행 감소.**
- 5묶음 = BBC 호스트 3 · Athletic 파라미터 2 (은두카 `19454b4c` ↔ `104c9906` · 비니시우스 `5baf63ff` ↔ `fd206c97`).
- 은두카 쌍은 2026-07-27 메모에 적힌 그 사례가 그대로 남아 있는 것이다.

**다섯 묶음 모두 기사 키 행끼리다** — 이 축만으로는 트윗 행이 한 건도 안 줄어든다.
그래도 이 축이 흡수의 **선행 조건**인 이유는 §2.2 에 적는다.

**지우면 안 되는 파라미터가 실물로 있다.**

스카이 라이브 블로그의 `postid` 는 같은 경로에서 글을 가르는 키다.

```
86620050  .../live-blog/31771/12476234/transfer-centre-...?postid=12184200
cc294b1b  .../live-blog/31771/12476234/transfer-centre-...?postid=12126772
```

접두로 지웠으면 이 둘이 한 행이 됐다.
BBC 의 `post=` 도 같은 성격이고 3행이 걸린다.

**문턱으로는 오탐도 미탐도 못 거른다.**

## 2. 설계

### 2.1 층이 셋이다

| 층 | 무엇 | 성격 | 표본 도달 |
| --- | --- | --- | --- |
| ① 수집 | 페이월도 URL 만 기사 주소로 교체 + 확장 정규화 | 결정적 (URL 동일) · 오탐 원리적 0 | 확정 16 중 6 |
| ② 서빙 | 같은 기자 · 2시간 · 주역 겹치는 트윗 키 · 본문 없음 행을 서빙 입력에서 제외 | 확률적 · 행 보존 · 되돌릴 수 있음 | 확정 16 중 12 |
| ③ 등재 | `credibility.yaml` 에 기자 셋 추가 | 데이터 · 즉시 | ②의 도달을 +3 |

세 층을 다 채택한다 (사용자 확정 2026-08-14).

**① 은 새 규칙이 아니라 두 소스의 동작을 같게 만드는 것이다.**
x_ornstein 은 `resolve_card_urls` 로 이미 카드 주소를 키로 쓰고 페이월 여부를 보지 않는다.
x_afcstuff 만 페이월에서 되돌아간다.

### 2.2 ① 수집 — URL 만 바꾸면 기존 dedup 이 합친다

**바꾸는 것은 한 분기다.**
`backtrack_promote` 가 `is_paywalled(final_url)` 일 때 항목을 그대로 돌려보내는 대신, `resolve_card_urls` 와 같이 **URL 만 기사 주소로 바꾸고 본문은 저장하지 않는다.**

**흡수 방향은 `dedup.classify` 가 이미 정해 놓았다.**

| 상대 기사 행 | 판정 | 결과 |
| --- | --- | --- |
| 이미 있다 (`body_level` 1 · 2) | `blocked` | **트윗 행이 안 생긴다** · 기사 행이 남는다 |
| 아직 없다 | `new` | 기사 URL 을 키로 한 행이 생긴다 |
| 나중에 전문이 온다 | `upgrade` | **같은 행이 제자리에서 채워진다** (`ON DUPLICATE KEY UPDATE` · 번역은 NULL 로 초기화돼 다시 돈다) |

즉 살아남는 것은 **본문 등급이 높은 행**이고, 트윗 행은 사라지거나 그 행으로 자란다.
새 저장 경로를 만들지 않는다.

**확장 정규화가 선행 조건인 이유.**

저널이 남긴 페이월 URL 과 저장된 기사 행의 URL 을 대 보면, 6건 중 3건이 현행 정규화로는 **다른 키다.**

- 7497282 로메로 — 저널은 파라미터 없음 · 저장 행 `085cb9d7` 은 `smid` + `source` × 2 + `unlocked_article_code`.
- 7505908 루이스-스켈리 — 저널은 `unlocked_article_code` + `source` + `smid` · 저장 행 `5d806a70` 은 파라미터 없음.
- 7510567 빈센트 조셉 — 저널에 **서로 다른 `unlocked_article_code` 로 두 줄**이 있어 트윗 경로 안에서만 두 행이 된다.

정규화를 안 넓히고 페이월 분기만 고치면 **합쳐지는 대신 세 번째 행이 생긴다.**

**제거 목록은 접두와 완전 일치를 나눈다.**

| 방식 | 키 |
| --- | --- |
| 접두 일치 (현행 유지) | `utm_` |
| 완전 일치 (신설) | `fbclid` · `gclid` · `smid` · `source` · `unlocked_article_code` · `ito` · `ns_campaign` · `ns_mchannel` · `wt.mc_id` · `mrfcid` |
| 유지 (제거 금지) | `postid` · `post` · `banner` |

**`source` 를 접두로 두면 안 된다** — 접두 일치는 `sourceid` 같은 키까지 삼킨다.
비교는 소문자로 한다 (`WT.mc_id` 실물).
목록에 키를 더할 때는 §1.4 처럼 **그 키를 지웠을 때 한 키가 되는 묶음을 먼저 세고**, 서로 다른 글이 합쳐지지 않는지 확인한다.

**호스트 별칭 접기.**

| 접는 것 | 근거 |
| --- | --- |
| `bbc.co.uk` → `bbc.com` | 실측 3묶음 6행 |
| `dailymail.co.uk` → `dailymail.com` | 지금 겹치는 묶음은 0 이지만 두 도메인이 표본에 다 있다 (`.com` 10행 · `.co.uk` 2행) |

**`origin_url` 컬럼 (사용자 확정 2026-08-14).**

URL 을 바꾸면 그 행의 「원문 기사 보기」 가 페이월로 간다.
그래서 바뀌기 전 주소를 `articles.origin_url` 에 보관하고, **본문이 아직 없는 행은 그 주소로 보낸다.**

- 채우는 곳 = URL 을 교체하는 두 자리 (`resolve_card_urls` · `backtrack_promote` 의 페이월 분기).
- x_ornstein 은 이미 `raw_payload["tweet_url"]` 에 같은 값을 담고 있어 재료가 있다.
- 표시 조건 = `body_level = 0` 이고 `origin_url` 이 있으면 `origin_url` · 아니면 `url`.
- upsert 는 `origin_url=COALESCE(VALUES(origin_url), articles.origin_url)` 로 둔다 — 전문이 와서 소스가 바뀌어도 이력이 안 지워진다.

**링크 라벨은 이 회차에서 정하지 않는다.**
트윗으로 보내면서 「원문 기사 보기」 라고 적는 것이 맞는지는 표시 판단이라 구현 회차에서 화면을 보고 정한다.

### 2.3 ② 서빙 — `serving_rows` 안에 둔다

**규칙 (2026-08-14 확정).**

트윗 키 행이면서 `body_level = 0` 인 행은, 아래를 모두 만족하는 기사 키 행이 있으면 서빙 입력에서 뺀다.

- 기자가 같다 — `journalist_directory` 로 정규화한 이름이 같거나, 정규화가 안 되면 바이라인 문자열의 네 글자 이상 영문 토큰이 겹친다.
- 발행 시각 차가 **2시간 이내**다.
- `article_players` 의 **주역 귀속** (`role` 이 `mention` 이 아닌 것) 이 하나 이상 겹친다.

**자리는 `run.serving_rows()` 다.**

- 그 함수가 이미 「렌더 입력만 거르고 DB 는 그대로 둔다」 를 하는 곳이라 의미가 맞는다 (fmkorea 무관 글 제외가 여기 있다).
- **`serve/render.py` 를 안 건드린다** — 안건 l-① · l-② · f-③ · x 가 그 파일에 몰려 있다.
- 행을 지우지 않으므로 규칙을 되돌리면 화면이 그대로 복구된다.

**소급이 따로 없다.**
서빙 규칙은 회차마다 렌더할 때 적용되므로 이미 쌓인 163행에도 그날부터 듣는다.
일회성 배치도, 삭제도, 되돌릴 수 없는 조작도 없다.

## 4. 소급과 전환

### 4.1 URL 재정규화는 선택이 아니라 필수다

`canonical_url` 을 바꾸면 저장된 URL 과 새로 계산한 키가 어긋난다.
`MartStore.seen()` 이 저장된 url 문자열로 조회하므로, 같은 기사를 다시 받으면 **기존 행을 못 찾고 두 번째 행을 만든다.**

그래서 정규화 변경과 같은 배포에 아래를 함께 돌린다.

- 저장 URL 재정규화 — 쿼리가 남아 있는 25행이 대상이고 그중 17행의 쿼리가 빈다.
- 5묶음 병합 — 본문 등급이 높은 행을 남기고 낮은 행의 `article_players` 귀속을 옮긴 뒤 잉여 행을 지운다.
- 오프라인이고 Gemini 호출 0 · 과금 0 이다.

**병합 전에 before 목록을 남긴다** (`article_players` 백업 포함).
소급 뒤 사라진 귀속 쌍은 현재 DB 만 봐서는 안 보인다.

### 4.2 트윗 행은 안 지운다

②가 서빙 규칙이라 이미 쌓인 163행을 손댈 이유가 없다.

### 4.3 전환 구간

`origin_url` 은 새 컬럼이라 배포 직후 전 행이 비어 있다.
그 구간에는 표시 조건이 `origin_url` 없음으로 떨어져 **지금과 같은 화면**이 나온다 (`url` 로 보낸다).
값은 다음 수집 회차부터 새로 교체되는 행에만 붙는다.

**그런데 이 전환 규칙은 링크의 목적지만 덮는다.**
전환 규칙은 **저장값을 읽는 자리**에만 걸리고 템플릿 변경은 그 바깥이라, 링크 텍스트나 표기를 함께 바꾸면 **컬럼이 비어 있어도 그 부분은 즉시 바뀐다.**

l-② 구현 회차가 같은 모양을 실제로 밟았다.
상세 페이지 원문 블록의 기자명을 저장값에서 정규화명으로 바꿨더니 소급 전인데 110개 페이지가 달라졌고, 조건을 공저 기사로 좁혀 0건으로 되돌렸다.

그래서 §2.2 에서 링크 라벨 판단을 구현 회차로 미룬 것이고, **라벨을 손대기로 한다면 그 변경만은 전환 규칙 밖이라는 것을 전제로 화면을 봐야 한다.**
절차는 `docs/troubleshooting/2026-08-14-transition-rule-does-not-cover-the-template.md` §4 의 세 벌 렌더 (현행 코드 · 소급 전 / 개정 코드 · 소급 전 / 개정 코드 · 소급 후) 를 쓴다 (PR #282).

### 7.2 선후 제약

**새 컬럼이 화면까지 가려면 두 자리를 지난다** — `SERVING_SELECT_SQL` 의 컬럼 나열과 상세 템플릿이다.
안건 l-② (공저자 다중 귀속) 의 `authors_json` 도 같은 두 자리를 지난다.

**l-② 구현 (PR #282) 과 대 본 결과 겹치는 줄은 사실상 없다.**

- `SERVING_SELECT_SQL` — l-② 는 `journalist` 뒤에 `authors_json` 을 얹는 한 줄만 바꿨다 · 같은 줄에 컬럼을 하나씩 얹는 것이라 해소가 자명하다.
**착수 시점의 나열은 `outlet,journalist,authors_json,team` 순이다** (PR #282 머지 뒤 기준) · 앞뒤 줄과 `linked_players` 를 만드는 `CASE` 블록은 안 바뀐다.
`origin_url` 은 그 줄 안 어디에 놓아도 되므로 머지 순서만 맞추면 재작성이 없다.
- `detail.html.j2` — l-② 는 15행 (기자 칸) 과 55행 (`.ometa`) 이고 **56행의 「원문 기사 보기」 링크는 안 건드렸다.**
`origin_url` 이 56행의 `href` 로만 간다면 겹치는 줄이 없다 · `.ometa` 안에 트윗 표기를 넣기로 하면 그때만 55행을 함께 본다.

**그래도 l-② 뒤에 착수한다 (권고 · 근거는 충돌이 아니다).**

새 컬럼은 배포 시점에 비어 있고 소급이 끝나야 찬다.
두 컬럼이 같은 배포에 실리면 그 빈 값 구간에 화면이 흔들릴 때 **어느 쪽 몫인지 가릴 수 없다.**
배치 4 에서 배포 두 건을 한 회차에 겹치지 않게 나눈 것과 같은 이유다.

**다만 「뒤에 한다」 로 풀리는 것은 l-② 의 소급이 실제로 도는 경우뿐이다.**

2026-08-14 시점에 l-② 는 PR #282 가 머지 대기이고 **소급 541행은 승인 전**이다.
소급은 오프라인이라 비용이 0 이지만 운영 DB 쓰기라 승인이 필요하고, 안 하기로 정해질 수 있다.
그러면 `authors_json` 은 신규 적재분만 차고 기존 행은 계속 비어 있어 **「빈 값 구간이 끝난 뒤」 라는 시점이 오지 않는다.**

| l-② 의 소급 | 이 회차가 할 일 |
| --- | --- |
| 돈다 | l-② 머지 + 소급 완료 뒤에 착수 · 빈 값 구간이 닫혀 있어 `origin_url` 의 델타만 남는다 |
| 안 돈다 | 선후로는 안 풀린다 · **컬럼별로 따로 채워 가며 재야 한다** (한 컬럼만 소급한 사본을 한 벌 더 만들어 세 벌 렌더) |

착수 전에 **어느 쪽인지 실물로 조회한다** · 전언으로 판정하지 않는다.

**판정은 채워진 행 수로 한다 — 빈 행 수로는 못 가린다.**

```sql
SELECT COUNT(*) FROM articles WHERE authors_json IS NOT NULL AND authors_json <> '';
-- 0 이면 소급 전 · 0 이 아니면 소급이 돈 것
```

소급이 끝나도 **바이라인이 원래 없는 행은 계속 빈다.**
2026-08-15 운영 조회에서 기사 732건 중 569 가 차고 163 이 비어 있었는데, 그 163 은 트윗 행이 아니라 fmkorea 135 · skysports 14 · goal 14 였다 (x 계열은 전 행 채워짐).
빈 행 수로 판정하면 소급이 끝난 상태를 **「안 돌았다」 로 읽는다.**

파일 이름이 아니라 이 두 자리로 적어 두는 이유는, 앞으로도 새 컬럼이 화면에 오를 때마다 같은 곳이 걸리기 때문이다.
런북 스니펫은 그 나열을 옮겨 적지 말고 `import` 해서 쓴다 (직접 옮겨 적어 어긋난 사례가 4회 있다).
