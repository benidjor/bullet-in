# 홈에 「선수 · 팀 뉴스」 구역을 두고 「기타」 칸을 「뉴스 종류」 필터로 바꾼다 (설계 2026-10-20)

비수기 수집 범위 설계 (2026-10-07 · #530 · 구현 #542) 의 마지막 조각이다.
수집은 넓혔는데 화면이 새로 받은 기사를 거의 보여 주지 않는 문제를 푼다.

## 1. 배경

### 1.1. 무엇이 문제인가

#542 로 이적 기사 말고도 선수 · 팀 소식과 경기 평점을 받기 시작했다.
그런데 이 기사들은 이적 단계를 받지 못해 「기타」 가 되고, 「기타」 카드는 최신 뉴스에서 기본으로 숨는다.

| 잰 것 | 값 | 출처 |
| --- | --- | --- |
| 배포 뒤 첫 실행의 새 기사 | 23건 중 22건이 「기타」 | 운영 DB `articles` · 2026-10-12 조회 |
| 배포 뒤 7일 네 소스 (Arsenal.com · BBC Sport · The Guardian · Sky Sports) 새 기사 | 61건 중 60건이 「기타」 | 운영 DB · 2026-10-19 15:26 UTC 조회 |
| 홈 최신 뉴스 첫 화면 (펼쳐 둔 날짜 셋) | 카드 2장 · 숨은 「기타」 17장 | 2026-10-20 00:27 KST 배포본을 로컬에서 렌더해 셈 |

받은 기사의 대부분이 홈 목록에 나오지 않아, 수집을 넓힌 효과가 화면에서 사라진다.

### 1.2. 지금 코드가 하는 일

| 자리 | 동작 |
| --- | --- |
| `serve/templates/_cards.html.j2:9` | 이적 단계 배지가 없는 카드 (`other` · 빈 값) 는 `display:none` · 선수 페이지 (`show_all`) 만 예외 |
| `serve/static/app.js` `applyFilters` | 「기타」 칸 (`data-group="bucket"`) 을 켜면 숨긴 카드를 더해서 보임 · 다른 이적 카드도 남음 · 조건이 생겨 대표 기사 구역이 사라지고 지난 날짜가 모두 펼쳐짐 |
| `serve/templates/index.html.j2:43-44` | 최신 뉴스는 날짜 묶음의 앞 셋만 펼침 · 날짜를 셀 때 「기타」 도 셈 |

| `serve/render.py` `cluster_events` | 같은 날 · 같은 선수 · 같은 단계를 한 묶음으로 · 「기타」 는 묶지 않고 낱개 카드 |

날짜를 셀 때는 「기타」 를 넣고 카드는 「기타」 를 숨겨서, 「기타」 뿐인 날짜는 빈 채로 펼쳐 둘 자리를 차지한다.
2026-10-20 의 첫 세 날짜 (10-19 · 10-18 · 10-17) 중 두 날짜가 그래서 사라지고 10-18 하나만 남았다.

설계 2026-10-07 §4 는 새 기사가 「최신 뉴스에 배지 없이 섞여 나온다」 고 적었지만 코드와 다르다 (§9.4 에서 고친다).

## 3. 홈 화면

### 3.1. 기사를 어느 구역에 두나

구역은 기사의 이적 단계 하나로 가른다.

| 기사 | 구역 |
| --- | --- |
| 표시하는 이적 단계가 있음 (오피셜 ~ 무산 · `is_displayable`) | 이적 뉴스 |
| 그 밖 (`other` · 빈 값) | 선수 · 팀 뉴스 |
| 공신력 최하 | 지금처럼 가십 (단계와 관계없음) |
| 대표 기사 · 주요 소식에 오른 기사 | 지금처럼 위쪽 띠에만 · 아래 구역에는 숨김 카드로만 |

같은 규칙을 사건 묶음 단위로 쓴다.
묶음은 단계를 섞지 않으므로 대표 카드의 단계가 곧 묶음의 단계다.

위쪽 띠 (대표 기사 · 주요 소식) 의 선정 규칙은 바꾸지 않는다.
이적 기사가 다섯이 안 되면 지금처럼 선수 · 팀 뉴스로 채운다.

### 3.2. 이적 뉴스 구역

- **날짜** — 이적 카드가 있는 날짜만 세어 앞의 셋을 편다
  → 「기타」 뿐인 날짜가 자리를 차지하던 문제가 사라진다
- **상한** — 펼친 세 날짜 안의 카드를 최신순으로 **6장** 까지 보이고, 나머지는 「이적 뉴스 더보기 · N건」 버튼 뒤로 둔다
- **이전 날짜** — 지금의 「이전 날짜 더보기」 를 그대로 쓴다 (상한을 푼 뒤에 나온다)
- **날짜 머리글** — 「묶음 N개 · 보도 M건」 을 이적 카드로만 센다

상한 6장은 데스크톱 두 열 기준 세 줄이다.
지금 (4장) 은 상한에 닿지 않고, 이적시장 마감 무렵 (28장) 에는 22장이 버튼 뒤로 간다.
값은 §9.2 화면 확인에서 데스크톱 · 모바일로 다시 보고 정한다 (사용자 확인 항목).

빈 날짜를 가십에서 꺼내 세우는 규칙 (`pick_empty_day_gossip`) 은 두 구역의 카드를 함께 보고 판단한다.
꺼낸 카드는 자기 단계에 맞는 구역으로 간다.

### 3.3. 선수 · 팀 뉴스 구역

- **자리** — 이적 뉴스 구역 아래 · 가십 위
- **모양** — 이적 구역과 같은 날짜 묶음 · 같은 상한 규칙 (날짜 셋 · 카드 6장 · 「선수 · 팀 뉴스 더보기」 · 「이전 날짜 더보기」)
- **카드** — 지금 숨김 카드와 같은 마크업을 숨기지 않고 보인다 · 단계 배지는 없다
- **구역 머리글** — 「선수 · 팀 뉴스」 · 오른쪽에 「오늘 N건」

두 구역이 같은 모양을 쓰면 상한 · 더보기 코드를 하나로 쓴다.

### 3.4. 맨 위 건수

최신 뉴스 머리글의 「오늘 뉴스 N건」 은 숨긴 「기타」 까지 세고 있었다 (`render_index` 의 `news_today` 가 숨김 카드의 묶음까지 셈).
지금 머리글은 「이적 뉴스」 로 이름을 바꾸고 「오늘 N건」 을 이적 카드로만 센다.
가십 바로가기 (「가십 N건」) 는 그 머리글에 그대로 둔다.
선수 · 팀 뉴스 머리글은 자기 카드로 「오늘 N건」 을 센다.

## 4. 사이드바와 필터

### 4.1. 배치

```
팀              □ Arsenal
뉴스 종류       □ 이적 뉴스   □ 선수 · 팀 뉴스      ← 새 묶음 (「기타」 칸 대신)
공신력          □ 전체  □ 구단 공식  …              ← 두 구역 공통
소스 (언론사)                                        ← 두 구역 공통
기자                                                 ← 두 구역 공통
이적 뉴스 · 영입 단계   □ 오피셜 … □ 무산           ← 맨 아래로 · 「기타」 칸 없음
```

검색칸은 상단 바에 있어 그대로 둔다.

### 4.2. 「뉴스 종류」 필터

| 고른 것 | 보이는 것 |
| --- | --- |
| 아무것도 안 고름 | 두 구역 모두 (지금의 기본 화면) |
| 이적 뉴스 | 이적 뉴스 구역만 · 선수 · 팀 뉴스 구역은 머리글째 감춤 |
| 선수 · 팀 뉴스 | 선수 · 팀 뉴스 구역만 |
| 둘 다 | 두 구역 모두 |

고르면 좁혀지는 필터다.
공신력 · 소스 · 기자 · 검색과 함께 고르면 두 조건을 모두 만족하는 카드만 남는다.
「영입 단계」 를 고르면 단계가 없는 선수 · 팀 뉴스는 감춘다 (단계가 없는 기사는 어느 단계에도 속하지 않는다).

건수는 기사 수로 센다.
이적 뉴스 = 표시하는 단계가 있는 기사 · 선수 · 팀 뉴스 = 그 밖 (공신력 최하 포함 · 지금의 「기타」 건수와 같은 규칙).

### 4.3. 없애는 것과 옛 주소

- **「기타」 칸 (`data-group="bucket"`)** — 없앤다
- **「소스 · 기자 · 공신력으로 좁히면 기타도 연다」 예외 (`app.js` · `narrowed`)** — 선수 · 팀 뉴스가 늘 보이므로 필요가 없어진다 · 없앤다
- **옛 주소 `?bucket=other`** — 「뉴스 종류 = 선수 · 팀 뉴스」 로 읽는다 · 새 주소는 `?kind=team` · `?kind=transfer`

### 4.4. 카드에 더하는 표시

카드와 같은 소식 줄에 `data-kind="transfer"` · `data-kind="team"` 을 단다.
`app.js` 는 이 값으로 「뉴스 종류」 를 판단한다 (`data-stage` 를 다시 해석하지 않는다).

## 5. 전체 기사 페이지 · 선수 페이지

- **전체 기사 (`all.html`)** — 이름대로 모든 기사를 보인다 · 「기타」 숨김을 푼다 · 날짜순 한 목록은 그대로 · 사이드바는 홈과 같다
- **선수 페이지** — 바꾸지 않는다 (이미 모든 기사를 보인다)
- **기사 상세** — 바꾸지 않는다

이적 이야기 16건 (전체 이야기 7 · 단계 누락 9) 이 선수 · 팀 뉴스 구역으로 간다.
이적 단계가 있는 117건과 합친 이적 이야기 133건 중 16건 (12%) 이 다른 구역에 놓이는 셈이다.
단계가 빠진 아홉 건 중 여섯은 한 기사에 여러 거래를 묶은 글이다 (「…및 …매각 추진」 · 「주요 이적설」 · 「마감일: …임박, …완료」).
단계 분류 프롬프트 (`enrich.py` `STAGE_PROMPT`) 에는 여러 거래를 묶은 글을 어떻게 매길지 정한 규칙이 없다.

### 6.2. 결정 · 구역 규칙은 그대로 두고 분류는 따로 고친다

| 안 | 내용 | 비용 |
| --- | --- | --- |
| **ⓐ 이 설계는 「단계 있음 = 이적 구역」 그대로 · 분류 개선은 따로 (권고)** | 비수기에는 이적 이야기가 「기타」 로 가는 일이 0건 · 겨울 이적시장 (2027-01-01 개장) 전에 분류 쪽 안건을 끝낸다 | 이 설계는 없음 |
| ⓑ 화면에서 제목 낱말로 이적 구역에 옮김 | 「합의」 · 「관심」 · 「이적시장」 같은 낱말이 든 「기타」 를 이적 구역으로 | 작음 · 배지 없는 카드가 이적 구역에 섞이고, 감독 재계약 같은 팀 소식도 옮겨진다 |
| ⓒ 화면에 확인 알림 | 선수 · 팀 뉴스로 간 기사 제목에 이적 낱말이 있으면 확인요청 채널 알림 | 중간 · 원인 (분류) 은 그대로 남는다 |

분류 개선 안건에서 정할 것 (이 설계 범위 밖) 은 둘이다.

- **여러 거래를 묶은 글** — 프롬프트에 「아스날이 당사자인 거래 중 가장 진행된 단계로 · 없으면 다른 거래 중 가장 진행된 단계로」 같은 규칙을 넣을지, 분류 뒤 제목 낱말 규칙으로 덮을지
- **이적시장 전체 이야기** — 단계 없이 둘지 (선수 · 팀 뉴스) · 「이적 일반」 같은 새 값을 둘지

위 24건은 사람이 나눈 정답이 있어 그 안건의 시험 재료로 쓴다.
배포 직후에는 첫 실행에서 두 구역 배치가 저장된 단계와 맞는지만 본다.

### 6.3. 함께 확인한 것 · 아스날과 무관한 기사

배포 뒤 「기타」 97건 중 12건은 서빙 단계에서 이미 빠진다 (fmkorea · 맨시티 · 맨유 · 첼시 등 다른 구단 글).
사이트에 실리는 85건 중 제목 · 요약 · 본문에 「아스날」 이 없는 기사는 5건이다.
셋은 아스날 이야기 (구단 공식의 감독 기사 둘 · 외데고르를 다룬 BBC Sport 기사 하나) 이고, fmkorea 둘은 예전 영입 후보 (알바레스) 와 다른 구단 선수 이야기다.
선수 · 팀 뉴스 구역이 생기면 이 둘이 보이게 되지만, 어떤 글을 받을지는 수집 범위의 몫이라 2주 `dropped` 검토 (설계 2026-10-07 §5.2 · 10-26 무렵) 에서 함께 본다.

## 7. 더 단순한 꼴과 버린 이유

| 더 단순한 꼴 | 버린 이유 |
| --- | --- |

| 선수 · 팀 뉴스 구역을 날짜 없이 카드 목록으로 | 카드의 시각이 「23:00」 처럼 시각만이라 날짜를 넘으면 언제 기사인지 모른다 · 이적 구역과 다른 모양이면 더보기 코드가 둘 |

## 8. 범위 밖

- **선수 필터** — 사이드바에서 선수로 고르기 · 써 보고 필요하면 따로
- **주제 분류 (부상 · 경기 · 인터뷰 …)** — 「종합 뉴스」 전환의 몫
- **수집 범위 (무엇을 받을지)** — §6.3 · 2주 `dropped` 검토의 몫
- **단계 분류 개선** — 여러 거래를 묶은 글 · 이적시장 전체 이야기 (§6.2) · 겨울 이적시장 전에 따로
- **선수 페이지 · 기사 상세** — 바꾸지 않음

## 9. 시험 · 배포 · 확인

### 9.1. 시험

| 대상 | 시험 |
| --- | --- |
| 구역 가르기 | 단계가 있는 묶음은 이적 구역 · 없는 묶음은 선수 · 팀 뉴스 · 공신력 최하는 가십 · 위쪽 띠 기사는 두 구역에 숨김 카드로만 |
| 날짜 셋 | 이적 구역이 「기타」 뿐인 날짜를 세지 않음 · 선수 · 팀 뉴스도 자기 카드로만 셈 |
| 상한 | 6장 넘는 카드가 버튼 뒤로 · 버튼 문구의 건수 |
| 건수 | 사이드바 「뉴스 종류」 두 건수의 합 = 전체 · 구역 머리글 「오늘 N건」 |
| 필터 (크로미움 · `test_filter_autocheck.py` 꼴) | 「뉴스 종류」 하나 고르면 다른 구역이 머리글째 감춰짐 · 「영입 단계」 와 함께 쓰면 선수 · 팀 뉴스가 감춰짐 · `?bucket=other` 가 「선수 · 팀 뉴스」 로 읽힘 |
| 전체 기사 | 「기타」 카드가 숨지 않음 |

지금의 「기타 숨김」 회귀 가드 (`tests/test_serve_render.py` 의 「기타」 숨김 · 「기타」 칸 · `narrowed` 예외 시험) 는 정책이 바뀌므로 새 규칙에 맞춰 고친다.
