# 방문 분석 이벤트 스키마 (2026-08-31)

공개 서비스가 GA4 로 내보내는 이벤트의 계약이다.
배선하고 도착을 증명하는 절차는 `docs/runbook/2026-08-24-wiring-analytics-and-proving-it-arrives.md` 에 있고 이 문서는 **무엇이 실려 나가는가** 만 적는다.

**지금 도는 것을 적은 문서이지 앞으로 만들 택소노미가 아니다.**
2026-08-24 에 계측을 붙이면서 이름 규칙만 열어 둔 채 본 택소노미 설계는 미뤘고 그 뒤로 정의가 `src/bullet_in/serve/static/app.js` 안에만 있었다.
저장소 어디에도 「이 이벤트가 무슨 값을 싣는다」 가 없어서 코드를 읽지 않으면 답할 수 없는 상태였다.

## 1. 언제 나가는가

측정 ID 는 `GA_MEASUREMENT_ID` 환경변수로 받고 기본값이 비어 있다 (`src/bullet_in/serve/render.py:34`).
값이 없으면 템플릿이 GA 스크립트를 아예 안 넣고 `track()` 은 `gtag` 가 함수가 아닌 것을 보고 조용히 돌아온다.
그래서 로컬 렌더나 목업은 운영 수치를 흐리지 않는다.

## 2. 모든 이벤트에 실리는 공통 필드

| 필드 | 값 | 왜 싣는가 |
| --- | --- | --- |
| `bi_cid` | `localStorage` 의 `bulletin_cid` · 없으면 새로 만드는 UUID · 저장이 막힌 브라우저면 `nostore` | 나중에 채울 수 없는 값이라 처음부터 싣는다 |
| `bi_ts` | 브라우저 시각 ISO 8601 문자열 | 세션을 나중에 어떤 정의로든 다시 만들기 위해서다 |

**세션 필드가 없는 것은 빠뜨린 것이 아니라 정한 것이다.**
식별자와 시각만 있으면 세션 경계는 나중에 다시 그릴 수 있고, 지금 정의를 굳히면 그때 바꾸기 어려워진다.

`bi_cid` 는 사람이 아니라 브라우저를 가른다.
같은 사람이 기기를 바꾸면 다른 값이 되고 저장이 막힌 브라우저는 전부 `nostore` 한 값으로 뭉친다.

## 3. 이벤트 네 종

세는 것을 고른 기준은 「이 값이 다르게 나오면 내가 다르게 행동할까」 였고 그렇지 않은 지표는 안 센다.

### 3.1. `bi_entry` — 유입 경로

페이지가 열릴 때 한 번 나간다.
어느 커뮤니티 글이 사람을 데려오는지가 다음에 어디에 알릴지를 정하는 근거다.

| 필드 | 값 |
| --- | --- |
| `entry_path` | `location.pathname` |
| `referrer` | `document.referrer` · 비어 있으면 `(none)` |
| `utm_source` · `utm_medium` · `utm_campaign` | 주소의 해당 질의 파라미터 · 없으면 빈 문자열 |

### 3.2. `bi_card_click` — 카드 클릭

기사로 들어가는 링크를 누를 때 나간다.
이적설을 보러 오는지 오피셜을 보러 오는지를 가른다.

| 필드 | 값 |
| --- | --- |
| `card_hash` | 기사 `content_hash` |
| `card_stage` | 영입 단계 표시값 |
| `card_tier` | 공신력 등급 |
| `card_outlet` | 언론사 |
| `card_surface` | 카드가 놓인 자리 (아래 다섯 중 하나) |

`card_surface` 는 링크의 첫 CSS 클래스를 그대로 싣는다.

| 값 | 자리 |
| --- | --- |
| `item` | 목록 카드 |
| `relitem` | 갈래 안에 접힌 관련 보도 |
| `mitem` | 첫 화면 「주요 소식」 대표 카드 |
| `pcard` | 선수 목록 카드 |
| `tltitle` | 선수 페이지 타임라인 제목 |

### 3.3. `bi_filter_apply` — 필터 사용

「적용」 을 누른 순간에만 나간다.
가장 공들인 축인 기자 · 언론사 · 단계가 실제로 쓰이는지를 본다.

| 필드 | 값 |
| --- | --- |
| `n_outlet` · `n_journalist` · `n_tier` · `n_stage` | 축별로 고른 개수 · `tier` 는 `all` 을 뺀 수 |
| `has_other` | 「기타」 를 켰으면 1 · 아니면 0 |
| `has_query` | 검색어가 있으면 1 · 아니면 0 |
| `axes` | 실제로 쓴 축 이름을 `+` 로 이은 문자열 · 아무것도 안 골랐으면 `(none)` |

**검색어 입력에는 붙이지 않았다.**
글자마다 `applyFilters` 가 불려서 거기에 붙이면 검색 한 번이 이벤트 수십 건이 된다.

`axes` 는 나머지 여섯 필드에서 다시 만들 수 있는 값이지만 따로 싣는다 — 축 조합을 세는 질의가 훨씬 짧아진다.

### 3.4. `bi_origin_exit` — 원문 이탈

원문으로 나가는 링크를 누를 때 나간다.
이 서비스가 탐색 도구로 기능하는지를 보는 값이고 색인 정책의 근거이기도 하다.

| 필드 | 값 |
| --- | --- |
| `card_hash` | 기사 `content_hash` |
| `card_outlet` | 언론사 |
| `exit_from` | `origin_button` (상세 페이지의 「원문 기사 보기」 버튼) · `excerpt_note` (발췌 안내문 안의 링크) |

## 4. 이 스키마가 답하지 못하는 것

- **읽은 시간과 스크롤 깊이가 없다** — 카드를 눌렀는지까지만 알고 그 뒤에 읽었는지는 모른다.
- **자체 수집 경로가 없다** — 값이 GA4 에만 쌓이고 저장소의 파이프라인은 이 이벤트를 읽지 않는다.
- **기기를 넘어가는 사람 단위 집계가 안 된다** — `bi_cid` 가 브라우저 단위라서다.
