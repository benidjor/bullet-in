# 링크 선수 워치리스트 정기 수집 · fmkorea 무관 글 필터 — 설계 (2026-08-01)

## 1. 배경 · 목적

fmkorea 수집은 고정 키워드 4개 (아스날 · "de roche" · 온스테인 · 아르테타 이적 시장) 로만 검색한다.
그래서 제목에 아스날이 없는 링크 선수 글 (예: 디오망데-PSG 협상 글) 은 구조적으로 못 잡는다.
반대로 온스테인 · "de roche" 는 제목 + 본문 검색이라 기자가 언급되기만 하면 아스날과 무관한 글도 들어온다 (실측: 온스테인 키워드 유입 124건 중 비아스날 47건).

이 설계는 두 문제를 같은 재료 (players DB) 로 푼다.

- **워치리스트 정기 수집**
— 확정 · 활성 이적축 선수의 ko_name 을 검색 키워드로 삼아, 정기 회차와 분리된 배치가 로테이션 검색한다.
- **무관 글 필터**
— 저장 직전에 "구단 키워드 또는 확정 선수명 포함" 검사로 무관 글을 차단한다.

착수 재료는 2026-08-01 시점에 전부 갖춰졌다.

- 검색 키워드로 신뢰 가능한 확정 표기 (ko_name) 87명 — 후보 표기는 오류율 11% 실측이라 쓰지 않는다.
- 활성 이적축 41명 (in_link 35 · out_link 6) — 상태 값을 DB 가 들고 있어 링크가 끝난 선수는 저절로 빠지고, 명단을 손으로 걷어낼 일이 없다.
- 수집한 글의 서빙 자리 — #186 "아스날 링크 선수" 라벨은 렌더 시점 EXISTS 계산이라, 나중에 선수를 확정하면 과거 기사에도 소급해 붙는다.

## 2. 확정 결정 (브레인스토밍 2026-08-01)

- **커버리지 = 전체 로테이션**: 잡으려는 모집단 (제목에 아스날 없는 글) 은 41명 전체에 드문드문 흩어져 나오므로, 기사수 상위 K 만 상시 검색하면 이미 잘 잡히는 선수에 예산을 쓰게 되어 기각.
- **실행 형태 = 전용 배치 · 정기 회차 +90분 오프셋 · 하루 4회 (보수안)**: 깨끗한 접촉 예산 창을 쓰고, 배치가 430 을 맞아도 정기 회차가 무사한 격리 확보. 관찰 후 8회 증량 검토.
- **비이적 글 (경기 활약 등) = 폭넓게 수집 후 하류 위임**: 기존 이적 단계 분류가 other 로 처리. 유입 비중이 크면 그때 이적 키워드 필터를 덧댐.
- **필터 인정 집합 = status='confirmed' 전체 (스쿼드 포함)**: 활성 링크만으로 좁히면 스쿼드 선수 글 (부상 소식 등) 이 걸러지는 회귀 발생. 신규 링크 첫 보도는 정의상 아스날 언급을 포함하므로 구단 키워드 조항이 발굴 경로를 보장.
- **구현 형태 = 전용 모듈 신설**: 라이브로 돌아가는 보충 수집 (collect_fmkorea) 은 factory 선택 인자 1개 외 무변경.

## 3. 구성 요소

### 3.1. watchlist_fmkorea.py (신규 · 배치 진입점)

`python -m bullet_in.watchlist_fmkorea` 로 실행한다.

- **명단 조회**: `status='confirmed' AND transfer_status IN ('in_link','out_link')` · id 순 정렬.
실행 시점 상태를 읽으므로 링크 성사 · 소멸 선수는 자동으로 빠진다.
- **로테이션 커서**: `~/.bullet-in/watchlist_cursor` 에 마지막 검색 선수 id 저장.
다음 배치는 그다음 id 부터 10명 슬라이스, 끝에 닿으면 처음으로 순환.
- **키워드 생성**: 슬라이스의 ko_name → `{keyword: ko_name, target: "title"}`.
- **공용 부품 재사용**: `build_fmkorea_adapter` · `persist` · `tunnel_alive` · 접촉 스탬프 함수를 collect_fmkorea 에서 import.
- **가드**: 터널 연결성 + 최근 접촉 (스탬프 · DB 워터마크 중 최신) 이 60분 이내면 스킵.
- **옵션**: `--dry-run` (적재 없이 검색 · 필터 결과만 출력) · `--force` (가드 무시).

### 3.2. 무관 글 필터 (adapters/fmkorea.py 수정)

생성자에 선택 인자 2개를 추가한다 — 구단 키워드 목록 · 선수명 집합.

- 판정: 제목 또는 본문에 구단 키워드 포함, **또는** 제목에 선수명 포함 → 통과. 둘 다 아니면 저장하지 않고 탈락 건수를 로깅.
- 적용 위치: 본문 fetch 후 저장 전 — 검색 · fetch 요청 수는 불변이라 접촉 예산 변화 없음.
- 인자 미주입 시 필터 없음 — 백필 등 기존 호출부 무영향.
- 정기 회차 (run.py) 와 워치리스트 배치 양쪽이 같은 인정 집합을 주입: 구단 키워드는 config, 선수명은 실행 시 players DB 의 confirmed 전체 ko_name.

### 3.3. 설정 (config/sources.yaml)

fmkorea 블록에 구단 키워드 키 추가 (예: `relevance_terms: ["아스날", "arsenal"]`).
구단명이 코드가 아니라 설정에 있어, 멀티 클럽으로 넓힐 때 코드에 박힌 값을 옮길 일이 없다.

### 3.4. collect_fmkorea.py (기존 · 최소 수정)

`build_fmkorea_adapter` 에 `search_keywords` 선택 인자 추가 — 생략하면 config 값 사용 (기존 동작 동일).

### 3.5. VM 타이머 (bullet-in-watchlist.timer + .service)

01:30 · 07:30 · 13:30 · 19:30 KST — 정기 회차 (3시간 간격 정시) +90분 · 6시간 간격 4회.
`OnFailure` 로 기존 `bullet-in-fail-notify` (Discord) 를 물린다.

## 4. 데이터 흐름 (배치 1회)

1. 타이머 발화 → 가드 (터널 · 최근 접촉 60분).
2. players 조회 → 커서 다음 10명 → 검색 키워드 생성.
3. 어댑터: 검색 10회 + 새 글 fetch (`max_posts=5` 상한 → 배치 총 요청 약 15 · 예산 창 약 18 이내).
4. 무관 글 필터 통과분만 적재 (Mongo raw + MariaDB mart · dedup) — 번역 · 분류 · 렌더 없음.
5. 커서 전진 + 접촉 스탬프 기록 (보충 수집 · 백필의 예산 판단이 이 접촉을 보게 됨).
6. 다음 정기 회차 (최대 3시간 뒤) 가 enrich 로 흡수 — 번역 · 요약 · 단계 분류 · 렌더 · 라벨.

## 5. 로테이션 · 예산 산수

- 일순 = 41명 ÷ (성공 배치 수 × 10명) — 하루 4배치 전부 성공 시 약 1.0일.
- fmkorea 접촉은 맥 릴레이 터널 경유라, 맥 슬립 시 그 배치는 통째로 스킵되고 일순이 늘어진다 (배치 1개 상시 결손 시 약 1.4일).
검색이 키워드당 최근 20건을 돌려주므로 늘어져도 유실은 드물다.
- 하루 추가 요청 약 40~60 (검색 40 + fetch 소수) — 일 총량이 약 150 → 약 200 으로 늘어나는 장기 위험은 실측이 없는 영역이라 보수안으로 시작해 관찰한다.

## 6. 에러 처리

- **터널 다운**: 배치 통째 스킵 (커서 무전진 · 스탬프 무기록) — 다음 배치가 이어받음.
- **검색 430**: 어댑터는 기존대로 해당 키워드만 강등 스킵. 검색 실패가 하나라도 있으면 **커서를 전진하지 않고** 같은 슬라이스를 다음 배치에 재시도 (성공 검색의 수집분은 적재 · 중복은 dedup 흡수). 어댑터에 검색 실패 카운터 노출 (소폭 추가).
- **활성 링크 0명**: 검색 0회 정상 종료 — 시장 폐장으로 일괄 archived 되면 배치가 자연 휴면.
- **DB · Mongo 접속 실패**: 로그 후 비정상 종료 → OnFailure 알림.
- **신규 0건 · 전량 탈락**: 정상 경로 — 접촉 스탬프는 기록 (가드 fail-open 방지).
- **커서 파일 부재 · 손상**: 처음부터 재시작. 커서 id 가 명단에서 사라졌으면 그다음 id 부터.
- **Gemini**: 배치는 호출하지 않음 — 새로 생기는 429 도 과금도 없음. 증가분은 정기 회차 enrich 의 신규 글 몇 건뿐.

## 7. 테스트

- **단위 (모킹 · TDD)**: 커서 (슬라이스 · 순환 · id 소실 · 파일 부재) · 키워드 생성 · 필터 (통과 3경로 · 탈락 · 미주입 시 무필터 회귀) · 가드 60분 · factory 인자 생략 시 기존 동작 · 검색 실패 시 커서 유지.
- **머지 전 라이브 검증** (셀렉터 드리프트 함정 — 모킹은 실검색을 못 잡음): 선수명 title 검색 1회 실측 + `--dry-run` 으로 필터 통과 · 탈락 표본 눈검증.
접촉 규율 준수 — 직전 회차 200 확인 · tee 필수 · 재실행 금지.

## 8. 배포 · 검증 · 관찰

- 첫 배치: journalctl 에서 검색 10회 · 적재 수 · 커서 전진 확인 → 다음 정기 회차에서 번역 흡수 · 화면 노출 · 라벨 확인.
- 며칠 관찰 3종: ① 배치 430 비율 (정기 회차 영향 포함) ② 무관 글 비중 (크면 이적 키워드 필터 덧댐) ③ 일순 주기 실측 (슬립 영향 포함) → 8회 증량 판단.
- 운영 런북 신설: 배치 관측 · 커서 리셋 · 증량 절차.

## 9. 범위 밖 (YAGNI)

- 이적 키워드 수집 필터 — 관찰에서 무관 글 비중이 클 때만 후속.
- 적극안 (하루 8배치) — 관찰 후 증량 판단.
- 후보 (candidate) 표기의 검색 · 필터 사용 — 표기를 믿기 어려워 확정 전에는 쓰지 않는다. 확정이 늦어지는 구간에서 생기는 무언급 글 공백은 구조적인 것으로 수용.
- 멀티 클럽 축 — 지금은 만들지 않되, 구단 키워드를 config 로 두어 "아스날 = 전부" 하드코딩을 피한다.
