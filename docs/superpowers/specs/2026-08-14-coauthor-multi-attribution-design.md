# 공저 기사의 저자 다중 귀속 설계 (2026-08-14)

공저 기사가 저자 한 명에게만 귀속돼 나머지 저자의 기자 필터에서 안 나오는 문제를 푼다.
안건 l-② 이고 이 문서는 설계까지다 — 코드 변경과 DB 쓰기는 다음 회차 몫이다.

사용자 요구는 2026-07-26 에 확정돼 있다.
공저 기사는 저자 각각에게 귀속돼야 하고, 기자 필터에서 「A and B」 같은 합성 항목으로 잡히면 안 되며, A 단독 · B 단독 · 둘 다 체크 세 경우 모두 그 기사가 나와야 한다.

---

## 1. 실측

### 1.1 잣대와 스냅샷

정기 회차가 돌 때마다 기사 수가 움직여서 (한 시간 사이 688 → 693) 운영 DB 를 한 시점으로 고정해 쟀다.

- 스냅샷 = 2026-08-13 09:10:53 UTC · 기사 693건 · 원문 본문 보유 529건.
- 읽기만 했고 운영 DB 에 쓰지 않았다 · 로컬 사본도 만들지 않았다.
- 「저자가 둘 이상」 의 정의 = mongo `raw_items.raw_payload.authors` 가 2개 이상 **또는** 저장된 `articles.journalist` 문자열이 여러 이름으로 쪼개지는 것.

이 정의를 여기 적어 두는 이유가 있다.
추출 범위 개정 스펙 (2026-08-12) §8.2 는 「원문 본문이 있는 502건 중 바이라인이 둘 이상인 것은 4건」 이라고 적었는데 그 4건의 잣대가 적혀 있지 않아 재현되지 않는다.
분모는 재현된다 — 08-12 시점으로 잘라도 509건이라 502 와 같은 잣대다.
분자는 21건이 나오고 **그 21건이 전부 08-12 이전 적재**다 (가장 늦은 것이 08-08).
데이터가 늘어서 생긴 차이가 아니라 세는 법이 달라서 생긴 차이다.

### 1.2 모집단이 둘이다

**① 원문 소스의 공저 — 21건**

| 소스 | 건수 |
| --- | --- |
| bbc_sport | 10 |
| skysports | 7 |
| guardian | 2 |
| goal | 1 |
| x_afcstuff | 1 |

21건 전부 원문 본문이 있다.
저자 정보는 mongo 의 `authors` 배열이나 저장된 `journalist` 문자열에 이미 들어 있다.

**② fmkorea 전재글 — 저자 둘 이상 12건 · 바이라인이 잡히는 글 35건**

원문 바이라인이 `journalist` 컬럼이 아니라 **본문 텍스트 앞머리**에만 있다.
이 트랙의 발단 기사 `8651f026` (「By David Ornstein and James McNicholas」) 이 여기 속하고 저장된 `journalist` 는 NULL 이다.
즉 발단 기사의 증상은 합성 항목이 아니라 **귀속이 아예 없는 것**이었다.

건수를 12로 잡은 근거는 직함을 걷어낸 뒤의 값이라는 것이다.
파싱 원본으로는 15건인데 `['KIERAN GILL', 'MAIL SPORT REPORTER']` 처럼 두 번째 자리가 사람이 아니라 직함인 글이 3건 있다.
두 모집단을 합치면 저자 둘 이상인 기사가 33건이다.

### 1.3 지금 화면이 깨지는 자리 셋

- **합성 항목 3개** — 사용자가 명시적으로 금지한 형태가 실제로 있다.
`Sam Blitz and Nick Wright (Sky Sports)` · `Will Magee, Niall McVeigh, Billy Munday and Yara El-Shaboury (The Guardian)` · `잭 로서, 사이먼 콜링스` 이고 각 1건이다.
셋 다 그 조합을 통째로 골라야만 걸린다 — `Sam Blitz` 를 따로 체크해도 그 기사는 안 나온다.
- **대표가 가로채는 경우** — `select_journalist()` 가 등재 기자를 우선해 다른 저자가 사라진다.
`9956234a` 는 Telfer 의 트로사르 기사와 Mokbel 의 촐리스 기사가 별도 바이라인으로 한 페이지에 실린 합본인데 Mokbel 기사로 분류돼 있다.
- **기자 미상 181건** — 기자 필터로 어떤 항목으로도 못 찾는 기사다.
대부분이 fmkorea 이고 본문에는 바이라인이 있다.

### 1.4 fmkorea 바이라인은 눈으로 봤을 때 깨끗하다

등재 기자 이름이 본문 앞머리에 있는 fmkorea 글 19건을 전수 눈검수했다.
**19건 전부 진짜 바이라인이고 본문 중 언급이 잘못 걸린 것은 0건이다.**

오염은 사람 이름이 아니라 직함과 날짜 조각이다.
202건에서 확장 정규식이 뽑는 이름 22종 중 비-이름은 셋뿐이다.

```
MAIL SPORT REPORTER × 2 · CHIEF FOOTBALL REPORTER × 1 · REPORTER × 1
```

셋 다 `REPORTER` 를 포함한다.

## 2. 설계

### 2.1 저장 — `articles.authors_json`

한 기사는 계속 한 행이다.
`articles.url` 에 UNIQUE 제약이 있어 같은 URL 로 두 행을 못 만들고, 만들 이유도 없다.

저자 목록을 `articles.authors_json TEXT` 에 JSON 배열로 싣는다.

```sql
ALTER TABLE articles ADD COLUMN IF NOT EXISTS authors_json TEXT;
```

- `images_json` 과 같은 자리 · 같은 방식이고 `MartStore.ensure_schema()` 가 멱등 적용한다.
- 담는 값은 **대표를 포함한 저자 전원**이다 — 등장 순서를 보존하고 중복을 제거한다.
노출할 이름만 담으면 노출 정책을 바꿀 때 소급을 다시 해야 한다.
- 노출 판정은 읽는 쪽 (`serve/render.py`) 에서 한다.

**조인 테이블 (`article_journalists`) 을 안 고른 이유**

`article_players` 가 조인 테이블인 것은 `players` 테이블이 실재해서 `player_id` 로 걸 수 있기 때문이다.
기자는 그런 테이블이 없다 — 원천이 `config/credibility.yaml` 이라 조인 키가 그냥 문자열이 된다.
서빙도 `SERVING_SELECT_SQL` 이 행을 한 번에 읽고 facet 계수는 파이썬에서 세므로 SQL 집계가 필요 없다.
테이블을 하나 늘리고 얻는 것이 없다.

### 2.2 추출 — 소스별로 이미 있는 재료를 쓴다

새 판정을 만드는 곳은 fmkorea 하나뿐이고 나머지는 이미 있는 값을 버리지 않고 싣기만 하면 된다.

**① html 계열 (`bbc_sport` · `skysports` · `guardian` · `goal` 등)**

`adapters/meta.extract_authors()` 가 이미 목록을 돌려준다.
지금은 `select_journalist()` 가 그 목록에서 대표 1명만 고르고 나머지를 버린다.
`to_articles()` 가 그 목록을 `Article.authors` 로 실어 mart 까지 보내면 끝이다.

한 가지 손질이 필요하다.
`_normalize_authors()` 의 구분자가 쉼표와 `&` 뿐이라 Sky Sports 의 「Lyall Thomas and Dharmesh Sheth」 가 한 사람으로 남는다.
구분자에 ` and ` 를 더한다.

**② fmkorea**

`adapters/fmkorea.extract_body_journalist()` 가 이미 본문 앞머리 200자에서 바이라인을 읽고 있고, 첫 저자에서 멈추도록 짜여 있다 (docstring 이 「공저는 첫 저자만 남긴다」 로 명시).
같은 자리에서 전체 목록을 돌려주는 `extract_body_authors()` 를 옆에 둔다.

정규식은 두 군데만 바꾼다.

```
구분자     이름 뒤에 ` and ` 와 ` , ` 를 허용한다
월 판정    「월 이름」 이 아니라 「월 이름 + 뒤에 숫자」 일 때만 이름에서 제외한다
```

**월 판정을 접두 일치로 하면 안 된다.**
축약형을 접두로 막는 초안은 `Mario` 를 `Mar` + `io` 로 읽어 사람 이름을 통째로 잃었다.
「뒤에 숫자가 오는 월 이름」 으로 좁혀야 `Aug. 2, 2026` 은 빠지고 `Mario Cortegana` 는 남는다.

직함은 `REPORTER` · `CORRESPONDENT` 를 포함한 토큰을 버리면 끝난다 (실측상 그 셋이 전부).

**문구를 더 넓히지 않는다.**
이 정규식은 초안 뒤 정정 2회로 확정했고 그것이 상한이다.
새로운 오염이 나오면 정규식을 또 넓히지 말고 **「등재 기자만 채택」 으로 좁힌다** — 직함과 날짜 조각은 등재될 일이 없으므로 그 한정만으로 오염이 0 이 된다.
경계 사례를 문구로 가르려다 시소에 걸린 전례가 있다 (`docs/troubleshooting/2026-08-08-prompt-wording-seesaw-on-boundary-cases.md`).

**③ 그 밖 (`x_afcstuff` 등)**

`authors` 도 없고 fmkorea 도 아니면 저장된 `journalist` 문자열을 구분자로 쪼갠다.
`잭 로서, 사이먼 콜링스` 가 이 갈래로 두 이름이 된다.

**④ 정규화**

- 등재 이름은 `journalist_directory` 로 정식명에 접는다 (`사이먼 콜링스` → `Simon Collings`).
- 미등재 이름은 표기 그대로 두되 **`norm_alias` 가 같은 이름이 이미 있으면 그 표기로 접는다**.
`JAMES SHARPE` 와 `James Sharpe` 가 같은 사람인데 항목이 둘로 갈리는 것이 실측 1쌍 있다.

### 2.3 facet — 항목은 「대표였던 이름」 에만 만든다 (정책 C)

기사 하나가 여러 이름에 걸리게 하되, **사이드바 항목은 어느 기사에서든 대표인 이름에만 만든다.**

**대표 선정은 현행 규칙을 그대로 둔다.**
소스 통칭 라벨 (`journalist_label`) 우선 · 조직 바이라인 접기 · 등재 기자 우선이라는 순서를 건드리지 않는다.
바꾸는 것은 두 갈래뿐이다.

```
저장 journalist 가 없으면   → 저자 목록의 첫 등재 기자 · 없으면 첫 저자
저장값이 합성 문자열이면    → 분해해서 같은 규칙으로 고른다
```

이 두 갈래가 합성 항목 3개를 없애고 fmkorea 의 기자 미상을 줄인다.

**이 규칙을 우회하면 안 된다.**
설계 초안은 대표를 저자 목록에서 새로 뽑았는데, 그러면 `journalist_label` 우선과 조직 접기가 죽어서 `BBC Sport` 27건 · `Arsenal Media` 5건 이 사이드바 첫 화면으로 올라왔다.
측정 코드를 실제 서빙 코드에 대 보고서야 드러났다.

**항목 생성 (정책 C)**

- 항목이 생기는 이름 = 어느 기사에서든 대표인 이름.
- 공저자로만 등장하는 이름은 항목을 안 만든다.
- 계수는 대표 · 공저 구분 없이 그 이름이 걸린 기사 전부를 센다.

**「등재 공저자에게도 항목을 준다」 (정책 B) 를 안 고른 이유**

B 와 C 를 같은 스냅샷에 돌려 보니 **한 글자도 다르지 않았다.**
현행 대표 선정이 이미 등재 기자를 우선하므로, 등재 기자는 자기가 낀 기사 어딘가에서 이미 대표다.
그래서 B 의 추가 조항이 지금 공집합이다.

결과가 같으면 조항이 하나인 쪽이 낫다.
다만 **구조적 보장은 아니다** — 어떤 등재 기자가 오직 공저로만 등장하면 C 에서는 항목이 안 생긴다.
현재 그런 기자가 0명이고, 실제로 생기면 그때 조항을 더한다.
감시 방법은 「등재 기자 중 대표인 기사가 0건인 사람」 을 세는 것이다.

**카드 · 필터 배선**

- 카드의 `data-journalist` 를 `|` 로 이은 다중 값으로 바꾼다.
`linked_players` 가 이미 `|` 를 구분자로 쓰고 있어 같은 관례다.
- `app.js` 의 `journalists.includes(d.journalist)` 를 「값 중 하나라도 걸리면 참」 으로 바꾼다.
- `_journalist_tier` 는 대표 기준을 유지한다 — 공신력 승격은 대표 기자 기준이라는 기존 결정을 안 바꾼다.

### 2.4 표시 — 대표 + 「외 N명」

- 카드 바이라인 = 대표 표시명 + 저자가 둘 이상이면 「외 N명」.
예 — `Sami Mokbel 외 1명`.
- 상세 페이지는 저자를 전원 나열한다.
- 전원 병기를 카드에서 안 하는 이유는 가디언 기사처럼 이름 4개가 한 줄에 들어가는 경우가 있어서다 (실측 최대 4명).

## 3. 기각한 대안

| 대안 | 기각 사유 |
| --- | --- |
| 합본 기사를 두 행으로 분리 | `articles.url` UNIQUE 제약에 걸린다 · 두 주제 합본은 실측 1건뿐이다 |
| 조인 테이블 `article_journalists` | 조인할 기자 테이블이 없어 키가 문자열이 된다 · 서빙이 SQL 집계를 안 쓴다 |
| 저자 전원에게 항목을 만든다 (정책 A) | 첫 화면이 19 → 27 로 늘고, 늘어난 8줄이 공저가 아니라 조직 바이라인과 저장 오염이다 |
| 등재 공저자에게도 항목 (정책 B) | 현재 데이터에서 C 와 결과가 동일하다 · 아무 일도 안 하는 조항을 미리 두지 않는다 |
| 등재 기자만 저장한다 | 노출 정책을 바꿀 때 소급을 다시 해야 한다 · 「외 N명」 의 N 이 소스마다 다른 뜻이 된다 |
| fmkorea 바이라인을 안 다룬다 | 트랙의 발단 기사가 그 모집단이고, 눈검수 결과 파싱 신뢰도가 충분하다 |

## 4. 소급과 전환

### 4.1 소급은 전량 오프라인이다

**Gemini 호출이 없다 · 과금 0 이다.**

- 원문 소스 — mongo `raw_items` 에 `authors` 가 이미 있다 (397건).
- fmkorea — 저장된 `body_source` 를 다시 파싱하면 된다.
- 그 밖 — 저장된 `journalist` 문자열을 쪼갠다.

대상은 스냅샷 기준 693건 전량이고, 절차는 `docs/runbook/2026-08-08-onetime-db-batch-via-tunnel.md` 를 그대로 쓴다.

### 4.2 빈 값 구간을 전환 규칙으로 덮는다

`authors_json` 은 신규 적재분부터 찬다.
소급 전까지 기존 행은 비어 있고 그 구간에 배포가 걸리면 화면이 흔들린다 (`docs/troubleshooting` 계열 교훈 · 세션 메모리 `new-field-empty-window`).

**전환 규칙** — `authors_json` 이 비어 있으면 현행 규칙 (단일 `journalist`) 으로 판정한다.
그러면 배포 시점에 화면이 안 바뀌고 소급이 끝나는 순간에만 바뀐다.

**검증은 빈 값 상태의 집합 대조다.**
소급 전 배포 상태에서 사이드바 항목 집합과 각 항목의 건수가 현행과 차집합 0 이어야 한다.

### 4.3 회수 조건

전환 규칙을 언제 걷어낼지는 「소급 완료」 가 아니라 **「정기 회차 몇 번에서 신규 적재분의 `authors_json` 미기입이 0 으로 유지되는지」** 다.
같은 형태의 판단이 안건 f-③ 으로 아직 열려 있으므로 그 관측과 함께 본다.

~~그 파일은 안건 u 세션이 건드리므로 그쪽 몫으로 넘긴다.~~
**정정 (구현 회차 2026-08-14)** — 안건 u 가 고친 파일은 `adapters/meta.py` 라 겹치지 않았고, 이 결함은 구현 회차가 함께 닫았다.
