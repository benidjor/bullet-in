# 전체 기사 · 선수 모아보기 설계 (serve 탐색 확장)

2026-07-26 브레인스토밍 확정본.
프론트 트랙 작업 2 — 필터 도달 복원 (#133) 위에서 탐색 화면을 확장한다.
사용자 확정 사항 (기능 선택 · 정렬 A안 · 소스별 귀속 · 타임라인 최신순 · 진입점) 을 단일 근거로 담는다.

## 1. 배경 · 목표

- 현재 서빙은 인덱스 (사건 묶음) 와 상세 페이지뿐이라, 선수 중심 탐색과 묶음 없는 전체 훑어보기가 불가능하다.
- 목표 A: 선수별 모아보기 + 이적 단계 타임라인 — 선수 하나의 보도 흐름을 한 화면에서.
- 목표 B: 평면 전체 목록 — 사건 묶음 없이 전 기사를 시간순 낱개 카드로.
- 목표 C: 인덱스 목록의 더보기 UX 정리 — 주 단위 펼침 · 접기 · 가십 2열.

## 2. 범위 · PR 분리 · 순서

- PR-1 (목록 개선): 전체 기사 페이지 `all.html` + 주 단위 더보기 · 접기 + 가십 2열.
- PR-2 (선수 트랙): 선수 색인 `players.html` + 선수 페이지 `player/*.html` + 네비 + ops 미매칭 목록.
- 순서는 PR-1 → PR-2.
PR-2 가 PR-1 의 평면 카드 목록 렌더를 재사용한다.
- 상단 네비 최종형: 홈 · 전체 기사 · 선수 · 소개.

## 3. 전체 기사 페이지 (all.html) — PR-1

- 사건 묶음 · 관련 보도 없이 전 기사를 날짜 그룹 + 시간순 낱개 카드로 나열한다 (인덱스 카드 매크로 재사용).
- 좌측 필터 사이드바를 그대로 재사용한다.
평면 목록이라 필터가 기사 단위로 완전하게 동작한다 (묶음에 가려 못 찾는 기사가 없는 보기).
- 주 단위 더보기 · 접기 (§4) 를 동일 적용한다.

## 4. 인덱스 목록 개선 — PR-1

- 주 단위 더보기: "더보기" 클릭마다 7일씩 추가 노출.
초기 노출은 최신 소식 = 최근 3일 그룹 (현행 유지), 가십 = 최근 7일 (현행 24묶음 개수 컷을 날짜 기준으로 교체).
- 접기: 전부 펼쳐지면 버튼이 "접기" 로 바뀌고, 누르면 초기 상태로 복귀한다 (그 구역 상단으로 스크롤 보정).
- 가십 배치: 3열 grid → 2열 (행 우선 유지).
- 필터 적용 시에는 현행대로 전체 자동 전개한다 (#133 동작 유지 — 필터 결과가 더보기에 가려지지 않게).

## 5. 선수 색인 (players.html) — PR-2

- 두 그룹으로 나눈다.
  - 이적 후보: 확정 단계 (§7) 가 있는 선수.
정렬 = 최신 확정 단계 순위 (오피셜 > 이적 합의 > 협상 중 > 개인 합의 > 관심 > 루머) → 기사 수 → 최근 보도일.
  - 스쿼드 · 기타: 확정 단계가 없는 선수, 기사 수순.
- 선수 카드: 이름 · 단계 배지 (확정 단계 있을 때만) · 기사 N건 · 최근 보도일.
- 정렬 근거가 카드에 그대로 보이도록 한다 (합성 점수 없음 — 사용자 확정 A안).

## 6. 선수 페이지 (player/<slug>.html) — PR-2

- slug = `name_map` 의 영문 성 소문자 (예: `player/eze.html`).
성 중복 시 렌더가 경고 로그를 남기고 한글키 해시 접미로 방어한다.
- 구성 (위 → 아래):
  1. 머리: 이름 · 현재 단계 (확정 단계의 최신값) · 기사 N건 · 최근 보도일.
  2. 타임라인 (최신순): 귀속 기사 전부를 노드로 쌓는다.
노드 = 날짜 · 그 기사의 저장 단계 배지 · 제목 링크 · 언론사.
단계는 저장값 그대로 노출한다 (없는 정보를 지어내지 않음 — 단계 없는 기사는 배지 생략).
  3. 기사 목록: 평면 시간순 카드.
사건 묶음은 쓰지 않는다 (타임라인이 이미 흐름을 제공).

## 7. 귀속 · 단계 계산 — 핵심 규칙 (PR-2)

### 7.1. 선수 사전

- 원천 = `config/name_map.yaml` (정규형 한글 키).
새 관리 파일을 만들지 않는다.
- 렌더 시점에 기사와 대조해 기사가 1건 이상 있는 선수만 색인 · 페이지를 만든다.
- 사전 밖 선수는 미귀속 — ops 미매칭 목록 (§8) 이 발굴 창구다.

### 7.2. 소스별 하이브리드 귀속

- X (afcstuff, 소스 설정 `credibility: x_mentions` 로 판별): 제목 + 요약 + 본문 전문 대조.
트윗은 별도 제목이 없어 title_ko 가 만들어낸 축약이라 (enrich.py 주석 명문화), 제목 기준 귀속은 신뢰할 수 없다.
실측: 6명 등장 트윗의 번역 제목에 3명만 담김 (기사 e1348256).
- 실제 언론사 · fmkorea: 제목 (title_ko) 대조.
언론사 기사 본문은 맥락 언급 (스쿼드 선수가 배경으로 스치는 것) 이 많아 전문 기준이 오히려 오염을 만든다.
제목 인명 유지는 번역 환각 게이트가 보장한다.
- 사건 묶음의 주인공 규칙 (`protagonist`) 은 선수 페이지 귀속에 쓰지 않는다 (클러스터링 전용으로 무수정 유지).

### 7.3. 단계 확정 (보수 규칙)

- 귀속 선수가 1명뿐인 기사만 그 선수의 단계 계산에 쓴다.
그 기사의 단계는 확실히 그 선수의 것이기 때문이다.
- 여러 명 귀속 기사 (라운드업 · 나열 제목) 는 기사 수 · 타임라인에만 반영한다.
저장 모델이 기사당 transfer_stage 1개라, 선수마다 단계가 다른 라운드업에서 남의 단계가 붙는 것을 막는다.
- 확정 단계가 하나도 없는 선수는 색인에서 스쿼드 · 기타 그룹으로 간다 (틀린 배지를 다느니 안 단다).

### 7.4. 구현 위치

- 귀속 · 단계 · 집계를 렌더 헬퍼 한 곳 (예: `player_index()`) 에 모은다.
- 후속 enrich 트랙 (§10) 이 오면 이 헬퍼의 데이터 원천만 교체한다 (화면 재설계 없음).

## 8. ops 미매칭 목록 — PR-2

- 조건: 영입 단계가 있는데 귀속 선수가 0명인 기사.
- ops 화면 (수집 현황) 에 최근 순 표 (제목 · 소스 · 날짜) 로 노출한다.
- 용도: `name_map` 에 추가할 신규 선수 발굴 (실사례: 스콧 · 부아디 · 바르콜라 트윗이 이 목록에 뜬다).

## 9. 알려진 한계

- afcstuff 안의 승격 기사 (x_backtrack — 트윗이 인용한 언론사 원문으로 제자리 승격) 는 본문이 기사 전문이라, 전문 귀속을 적용하면 맥락 언급이 섞일 수 있다.
실측 0건 (로컬 205건 · 라이브 인덱스 @핸들 18건 전수 확인) 이라 수용하고, §10 에서 자연 해소된다.
- 언론사 제목 기준은 조연이 제목에 오른 기사 (예: "기마랑이스 영입 통해 라이스 파트너 물색" 의 라이스) 를 걸러내지 못한다.
카운트 소폭 부풀림은 수용한다 (단계는 §7.3 보수 규칙이 보호).
- 사전 밖 선수는 페이지가 생기지 않는다.
사전 한 줄 추가로 다음 렌더부터 자동 해소되는 구조다 (코드 수정 불필요).

## 10. 후속 트랙 — enrich 선수 · 단계 추출 (이번 범위 아님)

- enrich 가 기사별 (선수, 단계) 쌍을 추출 · 저장 (스키마 추가 + 기존 기사 백필 + Gemini 과금).
- 완성되면 §7 헬퍼의 원천을 교체해 라운드업의 선수별 단계까지 정확해진다.
- 사전 밖 선수 자동 발굴은 링크 선수 워치리스트 트랙과 겹치므로 그쪽에서 함께 다룬다.
