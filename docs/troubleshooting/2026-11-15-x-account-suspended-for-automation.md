## 1. 무슨 일

2026-10-20 00:00 UTC 부터 2026-11-09 06:00 UTC 까지 163회차 연속으로 X 소스 두 곳 (`x_afcstuff` · `x_ornstein`) 의 수집이 실패했다.


트윗 요소 (`article[data-testid="tweet"]`) 가 20초 안에 나타나지 않았다는 뜻이다.

처음 조짐은 2026-10-19 21:00 UTC 회차에 있었다.
트윗 펼치기 두 건이 시간 초과로 실패했고 소스별 후보 수에서 x_afcstuff 가 빠졌다.

즉 우리 쪽 변경 없이 저절로 돌아왔다.

## 2. 왜 몰랐나

시간 초과가 났을 때 어댑터는 페이지 주소 · 제목 · 화면 캡처를 남기지 않았고 로그 줄도 쓰지 않았다.
남는 것은 실행 기록의 `errors` 필드뿐이라 로그만 봐서는 원인을 가릴 수 없었다.

알림은 나갔다.
발행 로그에 「알림 대기 … [x_afcstuff 48.0h — 다음 알림까지 24h]」 같은 반복 알림 보류 기록이 있다.
그러나 같은 알림이 반복되기만 했고 20일 동안 아무도 조치하지 않았다.

## 3. 원인

수집에 쓰던 X 계정은 프로젝트 소유자의 개인 계정이고 쿠키도 그 계정의 것이다.
X 가 「Your X account has been suspended」 메일을 보냈다 (2026-11-08 21:08 에 확인).
사유는 가짜 행동 (inauthentic behaviors) 금지 규칙 위반, 곧 자동화된 활동이었다.
소유자가 계정 잠금을 풀었고 수집은 2026-11-09 에 돌아왔다.

메일은 정지를 피하려고 새 계정을 만들면 그 계정도 정지된다고 경고한다.

## 4. 고친 것

| 변경 | 내용 |
| --- | --- |
| 실행 시각 제한 | 이적시장 기간에는 UTC 9 · 12 · 15 · 18 · 21시 다섯 회차, 그 밖에는 12 · 21시 두 회차만 X 를 돈다 (`config/sources.yaml` 의 `run_hours_utc`) |
| 이적시장 일정 공유 | 기간 목록을 `src/bullet_in/transfer_windows.py` 로 분리해 사이트의 이적 타이머와 함께 쓴다 |
| 늦은 재시도 | Airflow 가 늦게 다시 돌린 회차는 원래 3시간 칸의 회차로 센다 |
| 건너뜀 표시 | 건너뛴 회차는 깔때기에 `{"skipped": "schedule"}` 을 남긴다 |
| 판정 이어받기 | 신선도 판정은 직전 상태를 이어받고, 끊김 알림은 건너뛴 소스를 무시한다 |
| 운영 화면 | 「일정상 건너뜀」 을 보인다 |
| 본 트윗 재사용 | 이미 본 트윗은 `state/x_cache_<source>.json` 의 첫 펼치기 텍스트와 역추적 결과를 쓰고 페이지를 다시 열지 않는다 (기자 타임라인이 실패한 트윗은 기억하지 않는다) |
| 오류에 단서 | 시간 초과 때 `트윗이 안 보임 · url=… · title=… · <원래 오류의 첫 줄>` 을 남긴다 |

### 4.1. 알려진 한계

- 끊김 알림이 건너뛴 소스를 무시하므로 X 는 사실상 이 알림의 대상에서 빠진다.
- X 실패는 X 회차가 연달아 두 번 실패한 뒤 신선도 판정의 「끊김」 으로 잡힌다.
- 이적시장 밖에서는 이 판정까지 최대 24시간 안팎이 걸린다.

## 5. 다시 생기면

1. X 소스가 계속 실패하면 오류의 `url=` · `title=` 부터 본다. 로그인 · 정지 안내 화면이면 계정 문제다.
2. 소유자 메일함에서 X 의 정지 · 잠금 메일을 확인한다.
3. 메일의 안내에 따라 브라우저에서 직접 잠금을 푼다.
4. 풀린 뒤 다음 X 회차에서 오류가 0 이 되고 `scraped` 가 다시 나오는지 본다.

새 계정을 만들어 돌리지 않는다.
X 는 정지를 피하려고 새 계정을 만들면 그 계정도 정지된다고 경고한다.
대응은 접근량을 줄이는 것이고, 탐지를 피하는 방법은 찾지 않는다.
