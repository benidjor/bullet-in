# 소스가 죽었다고 세 번 말했는데 상자를 안 열어 봤다 (2026-08-28)

「afcstuff 가 옮겨 적은 온스테인 속보를 수집에서 빼도 되나」 라는 질문 하나에 **틀린 답을 세 번 냈다.**
세 번 다 「없다」 를 말하면서 **어디까지 찾고 하는 말인지를 안 밝혔고, 실제로는 아무 데도 안 열어 봤다.**

사용자가 세 번 다 되물어서 갈렸다.
자동 검사는 하나도 안 걸렸다 — 셋 다 「조회를 안 했다」 이지 「조회가 틀렸다」 가 아니라서다.

## 1. 세 번의 오답

### 1.1. 저장된 행만 보고 「소스가 사실상 놀고 있다」 고 했다

`articles` 테이블에서 `x_ornstein` 이 7행이었다.
같은 기간 `x_afcstuff` 는 250행이었다.

여기서 **「x_ornstein 은 백업이 못 된다 · 사실상 놀고 있다」** 고 단정하고, 그것을 근거로 수집 제외에 반대했다.

Mongo `raw_items` 를 열어 보니 **22건이 있었다.**
그중 넬슨 계약 해지 트윗도 있었다 — 「못 받았다」 고 말한 바로 그 건이다.

```
fetched_at  2026-08-27T18:02:21
text  EXCL: Reiss Nelson agrees deal with Arsenal to terminate his contract by
      mutual consent. ... 26yo winger leaves #AFC now as free agent ...
```

22건의 행방을 추적하니 이렇다.

```
본인 이름의 행           7건
fmkorea 행으로 합쳐짐   14건   ← 카드 링크가 The Athletic 원문 주소라 같은 URL
행이 안 됨              1건   (같은 소식이 이미 본인 행으로 있다)
```

`resolve_card_urls` 가 트윗의 링크 카드를 원문 주소로 바꿔 저장하고, fmkorea 가 같은 원문을 전재하면 한 행으로 합쳐진다.
**소스가 일한 결과가 남의 이름으로 적혀 있었다.**

**이 프로젝트 메모리에 이미 적혀 있는 함정이다.**
안건 θ 의 교훈이 「저장 0 을 수집 0 으로 읽지 말 것 — 흡수되는 소스는 매일 수집돼도 저장이 안 움직인다」 인데, 그것을 그대로 밟았다.

### 1.2. 한글 표기를 빠뜨린 대조로 「짝이 없다」 고 했다

「afcstuff 속보에 짝이 되는 원문이 있나」 를 세면서 `journalist LIKE '%Ornstein%'` 하나로 조회했다.
결과가 11/16 이었고 그것을 「5건은 짝이 없다」 로 보고했다.

fmkorea 의 온스테인 바이라인은 **일곱 가지 표기**로 저장돼 있었다.

```
온스테인 32 · David Ornstein 5 · 데이비드 온스테인 3 · 데이비드온스테인 2
데이비드온스테인& 샘 리 외 1 · 제이콥 탠스웰,온스테인 1 · 데이비드 온스테인. 1
```

한글 표기를 넣어 다시 세니 **14/16** 이었다.
제목까지 대 보면 짝이 맞는 것이 10/16 이고, 속보 · 논평으로 가르면 **속보 12건은 12건 다 짝이 있었다.**

라틴 문자 하나로만 조회한 것이 원인이고, 이 저장소는 **바이라인 표기가 갈리는 것을 이미 안건 α 로 다뤘다** (기자명표기 · 2026-08-20 종결).
그 사실을 알면서도 조회를 라틴 문자로 짰다.

### 1.3. 이미 있는 장치를 안 찾고 「그건 못 한다」 고 했다

「다른 기자 (Mokbel · Romano · Jacobs) 는 본인 X 계정을 우리가 안 받으니 같은 방법을 못 쓴다」 고 했다.

`config/backtrack.yaml` 이 있었다.

```yaml
params:
  window_min: 360        # afcstuff 가 기자 원본을 인용하기까지 시간창
  timeline_depth: 25     # 기자당 스크레이프 트윗 수
  max_journalists: 15    # 실행당 기자 스크레이프 상한
```

`x_backtrack.backtrack_promote` 가 **회차마다 인용 기자의 타임라인을 최대 15명까지 긁어** 원본 트윗을 찾고, 그 트윗의 링크 카드에서 원문 URL 을 얻어 승격한다.
승격되면 fmkorea 전재와 같은 행이 된다 — 내가 「없다」 고 말한 그 기능이다.

왜 안 듣는지도 저널에 그대로 남아 있었다.

```
최근 7일
  매칭 실패              105
  near-miss (카드 없음)    92
  페이월 (Athletic)       16   ← 넬슨 중복의 정체
  미등록 도메인             8
```

**넬슨 건은 원문을 제대로 찾고도 「The Athletic 은 페이월」 이라 버린 것이다.**
`backtrack_promote` 는 본문까지 가져와야 승격하는데, 자매 함수 `resolve_card_urls` 는 본문 없이 URL 만 바꾼다 (주석에 「본문은 저장하지 않는다」 라고 적혀 있다).
같은 일을 한쪽만 하고 있었다.

## 2. 무엇이 공통인가

셋 다 **「없다」 를 말하면서 찾은 범위를 안 밝혔다.**

| 오답 | 실제로 본 것 | 안 본 것 |
| --- | --- | --- |
| 소스가 놀고 있다 | `articles` 한 테이블 | Mongo `raw_items` · URL 이 어디로 갔나 |
| 짝이 없다 | 라틴 문자 바이라인 | 한글 표기 여섯 종 |
| 그건 못 한다 | `config/sources.yaml` | `config/backtrack.yaml` · `x_backtrack.py` · 저널 |

**셋 다 「한 곳을 보고 전체를 말했다」 이고, 그 한 곳은 마침 가장 먼저 떠오른 곳이었다.**

그리고 셋 다 **이 저장소가 이미 아는 것**이었다 — θ 의 교훈 · α 의 표기 갈림 · 이미 구현된 역추적.
모르는 것을 몰라서 틀린 게 아니라, **아는 것을 찾아보지 않아서 틀렸다.**

## 3. 규율

**「없다」 에는 찾은 범위를 붙인다.**
「x_ornstein 은 7건뿐이다」 가 아니라 **「`articles` 테이블 기준 7건이다 · Mongo 는 안 봤다」** 라고 적는다.
범위를 적으면 그 자리에서 「그럼 Mongo 는」 이 나온다.

**층이 여럿인 파이프라인에서는 층을 세고 시작한다.**
이 저장소의 층은 넷이다 — 원본 수집 (Mongo `raw_items`) · 저장 (`articles`) · 서빙 필터 · 렌더.
저장에서 안 보이는 것이 수집에서 없었다는 뜻이 아니다.

**문자열 조회는 그 값의 표기가 몇 가지인지부터 센다.**
`SELECT DISTINCT journalist ... WHERE journalist LIKE '%...%'` 를 먼저 돌려 표기 목록을 보고 나서 계수를 짠다.

**「그 기능이 없다」 고 말하기 전에 `config/` 를 훑는다.**
이 저장소는 동작을 설정 파일로 빼는 관례가 있고 (`sources.yaml` · `backtrack.yaml` · `club_map.yaml` · `credibility.yaml`), 그 파일들이 기능의 존재를 알려 준다.

**저널은 실패의 이유를 이미 적고 있다.**
`grep -o "backtrack[^\"]*" | sort | uniq -c` 한 줄로 네 갈래가 나왔다.
「왜 안 되는지 모르겠다」 고 말하기 전에 이 한 줄을 돌린다.
