# 코드블록 도식이 보는 사람의 폰트에 따라 어긋난다

날짜 2026-09-22.
README 개편 작업 중 코드블록 도식을 새로 그리다 발견했다.
같은 결함이 지금 `main` 의 README §2 에도 있다.

## 증상

README §2 의 Airflow DAG 도식에서 분기 화살표가 `publish` 아래 서야 하는데, 보는 환경에 따라 오른쪽으로 밀린다.

```
advance ─▶ collect ─▶ enrich ─▶ publish ─▶ gate ─▶ deploy_site ─▶ judge
                                   └─▶ warehouse_load (publish 뒤 병렬)
```

## 원인

`→` · `·` · `▶` · `─` · `│` · `↑` 는 유니코드 East Asian Width 가 **Ambiguous** 다.
폰트에 따라 한 칸으로도 두 칸으로도 렌더된다.

`publish` 앞 문자열 `advance ─▶ collect ─▶ enrich ─▶ ` 에는 `─▶` 가 세 쌍, 즉 ambiguous 문자가 여섯 개 들어 있다.

| 폭 계산 기준 | `publish` 가 시작하는 열 |
| --- | --- |
| Ambiguous = 1칸 | 32 |
| Ambiguous = 2칸 | 38 |

분기 화살표의 들여쓰기는 고정된 공백 수라 어느 한쪽에만 맞는다.
**결과적으로 최대 6칸이 어긋난다.**

## 더 깊은 원인

Ambiguous 문자를 전부 걷어내도 끝이 아니다.
**ASCII 와 한글을 같은 정렬 열에 섞는 것도 안전하지 않다.**

모노스페이스 폰트는 대개 라틴 문자만 담고 있고 한글은 폴백 폰트가 그린다.
폴백 폰트의 한글 폭이 라틴 문자의 정확히 두 배라는 보장이 없다.
GitHub 의 기본 모노스페이스 스택에서도 환경에 따라 비율이 달라진다.

그래서 아래 표는 같은 열에 `brainstorming` (ASCII) 과 `스펙` (한글) 이 섞여 있어 구조적으로 맞출 수 없다.

```
단계                            주체
brainstorming                   사람이 승인
스펙                            AI 초안, 사람이 승인
```

## 잣대가 두 번 헛돌았다

이 회차에서 「폰트 독립을 확인했다」 고 두 번 말했는데 두 번 다 틀렸다.

- **1차** — 검사기가 `→` 앞쪽 폭만 쟀다.
  화살표 뒤의 정렬과, 한 줄에 ambiguous 문자가 여러 개일 때 누적되는 어긋남은 보지 못했다.
- **2차** — 「줄 앞 40칸 안에 ambiguous 문자가 있는가」 라는 임의의 창을 썼다.
  정렬 기준점이 어디인지와 무관한 숫자라, 기준점 뒤의 안전한 `·` 까지 경고로 잡고 기준점 앞의 위험은 창 밖이면 놓친다.

**잣대가 「무엇을 재는지」 를 정하지 않은 채 숫자만 본 것이 공통 원인이다.**

## 규칙

1. **정렬이 필요한 열에는 같은 문자 종류만 둔다.**
   한글끼리 (W 로 확정) 또는 ASCII 끼리 (Na 로 확정) 는 폭이 확정된다.
2. **Ambiguous 문자는 정렬 기준점 앞에 두지 않는다.**
   기준점 뒤 자유 텍스트에서는 써도 된다 (`·` 를 나열 구분자로 쓰는 것은 문제없다).
3. **섞을 수밖에 없으면 코드블록을 버리고 마크다운 표로 옮긴다.**
   표는 브라우저가 레이아웃하므로 글자 폭을 가정하지 않는다.
   순서가 있는 목록이면 번호 열을 함께 둔다.
4. **오른쪽 테두리를 두르지 않는다.**
   왼쪽 가장자리 (`|` · `+--`) 만 쓰면 맞출 자리가 하나로 줄어든다.

## 검사 방법

블록마다 정렬 열을 정하고, 그 열까지의 폭을 Ambiguous = 1칸과 2칸 두 가지로 계산해 **두 값이 같은지** 본다.
같으면 폰트와 무관하게 정렬이 유지된다.

```python
import unicodedata

def width(s, ambiguous):
    return sum({"W": 2, "F": 2, "A": ambiguous}.get(
        unicodedata.east_asian_width(c), 1) for c in s)

# 정렬 기준점까지의 접두사를 두 기준으로 재서 같은지 본다
prefix = "advance ─▶ collect ─▶ enrich ─▶ "
assert width(prefix, 1) == width(prefix, 2)   # 실패한다 (32 vs 38)
```
