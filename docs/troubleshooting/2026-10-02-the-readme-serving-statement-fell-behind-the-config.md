# README 의 서빙 서술이 설정 개정과 #209 를 따라가지 못했다 (2026-10-02)

- **영역**: 문서 정합 / 상세 페이지 서빙 범위 / 저작권 고지
- **관련 안건**: ω 본문전문서빙
- **결정 기록**: `docs/superpowers/specs/2026-07-20-deployment-mvp-track-design.md` §2.3.1
- **결론**: 서비스 동작은 그대로 두고 README 를 실제에 맞췄다

## 1. 증상

README 를 현재 코드와 설정에 대 보던 중 (2026-10-01) 서빙 범위를 설명하는 세 줄이 실제와 다르다는 것을 찾았다.

| 자리 | README 가 쓴 것 | 실제 |
| --- | --- | --- |
| 21행 (기사 상세 캡처 설명) | 언론사는 발췌 + 원문 링크, X 와 공식 발표는 전문 | 10개 소스 전부 본문 전체 |
| 583행 (윤리 및 법적 고지) | 원문 전체를 재배포하지 않고 메타데이터 · 요약 · 원문 링크 중심 | 본문 전체를 한국어로 싣는다 |
| 584행 (같은 절) | 퍼가기를 금지한 커뮤니티 글은 헤드라인만 | 본문은 다시 써서 싣고 게시글 이미지만 뺀다 (#209) |

`config/sources.yaml` 의 10개 소스는 모두 `serving: full` 이다.
상세 페이지의 발췌는 렌더 시점에 소스 단위로 걸리는데 (`serve/render.py` 의 `serving_mode` → `excerpt_paras`), 지금 이 경로를 타는 소스는 하나도 없다.
fmkorea 글은 원문 기사에 접속되면 원문을 번역하고, The Athletic 이거나 원문 접속이 막히면 게시자가 옮긴 본문을 채택한다 (`adapters/fmkorea.py`).
게시글 본문을 쓸 때 퍼가기 금지 표식이 있으면 게시글 이미지만 뺀다.
본문은 재작성으로 표현을 바꿀 수 있지만 이미지는 바꿀 수 없어 위험의 성격이 다르다고 봤다 (#209 의 E안).

같은 날 README 의 다른 서술 여덟 곳을 고친 PR #512 에서는 이 세 줄을 일부러 뺐다.
문장만 고칠지 서비스 동작을 문장 쪽으로 되돌릴지를 먼저 정해야 했기 때문이다.

#209 는 같은 README 문장의 다른 절반 (퍼가기 금지 글) 을 바꿨다.
그 PR 도 README 는 건드리지 않았다.

#333 은 상세 페이지가 아니라 소개 페이지 문구를 실제에 맞췄다.
「매체별 정책에 따라 어떤 소식은 요약과 앞부분만 보여 준다」 를 「매체에서 요청이 오면 해당 기사의 본문을 내리고 제목과 링크만 남긴다」 로 바꿨다.
같은 사실을 서술하는 README 두 줄은 이때도 남았다.

#496 은 README 전체를 다시 쓴 개편이었지만 목적이 구조와 문체였다.
「원문 전체 재배포가 아니라」 가 「원문 전체를 재배포하지 않고」 로 바뀌었을 뿐 사실은 대조하지 않았다.

## 3. 왜 따라가지 못했나

- **README 문장이 정본을 가리키지 않았다.**
서빙 범위의 정본은 `config/sources.yaml` 의 `serving` 값과 spec §2.3.1 이다.
README 는 그 값을 풀어서 썼고 어디서 왔는지 적지 않았다.
그래서 설정을 바꾸는 PR 에서 `serving` 으로 검색해도 README 가 걸리지 않았다.
- **한 문장이 두 층을 묶고 있었다.**
서빙 범위는 렌더 시점의 `serving` 값과 수집 시점의 퍼가기 금지 분기, 두 층에서 정해진다.
README 584행은 둘을 한 문장에 담았고 #104 와 #209 는 각자 한 층만 바꿨다.
어느 PR 도 「이 문장 전체가 아직 맞는가」 를 볼 자리에 있지 않았다.
- **같은 사실을 쓴 자리가 셋이었다.**
README 21행 · 583 ~ 584행과 소개 페이지다.
#333 이 그중 하나만 고쳤다.
- **정정 작업용 메모도 낡아 있었다.**
2026-10-01 에 README 를 대조하며 적어 둔 메모에는 584행의 고칠 값이 「퍼가기 금지 글은 헤드라인만」 이라고 적혀 있었다.
#209 이전 상태다.
고칠 값을 적어 둔 메모도 코드에 다시 대 봐야 했다.

## 4. 정한 것과 고친 것

서비스 동작은 바꾸지 않는다.
2026-07-20 개정 (spec §2.3.1) 에서 번역 전문 게시의 저작권 위험을 알고 받아들였고 문제가 제기되면 소스 단위로 `serving: excerpt` 로 되돌리거나 기사를 내리기로 했다.
그 결정을 유지하고 문서를 실제에 맞췄다.

- **README 21행** — 「3줄 요약, 한국어로 옮긴 본문, 원문 링크, 기자 바이라인」
- **README 583 ~ 587행** — 원문 링크 표기와 요청 시 본문 내림 · 전 소스 `serving: full` 과 위험을 받아들인 결정 · 되돌리는 설정 · 에펨코리아 경유 글의 본문 출처와 퍼가기 금지 글의 이미지 제외
- **fmkorea 런북** (`docs/runbook/2026-07-13-fmkorea-search-adapter-ops.md`) — 로그 해석의 `헤드라인만 저장` 을 현재 로그 문구 `본문 채택 · 이미지 제외` 로, 표식 드리프트의 신호를 「body 전건 채움」 에서 「이미지 전건 채움」 으로

README 의 새 문장에는 `config/sources.yaml` 의 `serving: full` 과 결정 기록 링크를 함께 적었다.
설정을 바꾸는 다음 PR 이 `serving` 으로 검색하면 README 가 걸린다.

## 5. 고치지 않은 것

- `docs/runbook/2026-06-29-serving-ui-verification.md` 의 「차등 서빙 · 잔여 페이지 정리 검증 (SP-B, 2026-07-20)」 절은 그날의 검증 기록이라 그대로 둔다.
- 2026-07-19 트러블슈팅 두 편의 「헤드라인-온리」 서술도 그때의 사실이다.

## 6. 되짚을 자리

- 설정 값을 서술하는 README 문장에는 그 값이 사는 자리 (파일 · 키) 를 함께 적는다.
- 서빙 범위처럼 두 층에서 정해지는 사실은 층마다 따로 쓴다.
- 문서 개편 PR 이 옛 문장을 옮길 때는 문체와 별개로 사실 대조를 한 번 거친다.
