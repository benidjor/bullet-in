# README 가 LLM 경로 하나의 게이트를 전체의 구조로 적고 있었다 (2026-10-08)

- **영역**: 문서 (README §6.3 번역 품질 게이트)
- **관련 PR**: #538 (정정)
- **고친 것**: README §6.3 을 경로별 표로 교체 · 이 문서
- **남은 일**: 없음

## 1. 증상

README §6.3 「번역 품질 게이트」 는 LLM 산출물 전체에 아래 구조가 적용되는 것처럼 적고 있었다.

- 검사 여섯 가지 (숫자 누락 · 수치 주입 · 인용 보존 · 구단명 주입 · 인명 주입 · 원문 복제)
- 하나라도 걸리면 사유를 붙여 최대 두 번 다시 생성
- 세 시도 중 위반이 가장 적은 것을 채택

README 를 코드에 대 보는 리뷰에서, 이 구조가 LLM 경로 둘 가운데 하나에만 해당한다는 것이 드러났다.

## 2. 실제 구조 — 경로가 둘이다

`enrich.partition_by_body_level` (`src/bullet_in/enrich.py:577`) 이 본문 출처 등급으로 행을 가른다.
등급 1 (`POST_BODY_LEVEL`) 은 이미 한국어인 커뮤니티 게시글 본문이라 번역이 아니라 재작성 대상이다.

| | 번역 경로 | 게시글 재작성 경로 |
| --- | --- | --- |
| 함수 | `finalize_translation` (`enrich.py:456`) | `rewrite_rows_guarded` (`enrich.py:752`) |
| 대상 | 영문 원문을 번역하는 기사 | 이미 한국어인 커뮤니티 게시글 본문 |
| 검사 | 제목의 원문에 없는 인명 · 제목 오역 (인명 누락 · 근거 없는 「임대」) · 라운드업 단신 누락 · 원문에 없는 구단명 | 숫자 누락 · 수치 주입 · 인용 보존 · 구단명 · 인명 · 원문 복제 (글자 8-gram 잔존율 0.75 초과) |
| 걸렸을 때 | 다음 실행에서 사유 (`retry_note` · 구단명 · 인명) 를 붙여 한 번 다시 번역 · 그래도 걸리면 채택하고 경고 | 같은 실행 안에서 최대 세 번 생성 · 위반이 가장 적은 것 채택 · 위반이 남으면 다음 실행에서 한 번 더 (`rewrite_requeue`) |

README 가 적은 여섯 검사와 「세 시도 중 최선 채택」 은 오른쪽 열에만 해당했다.
수집 현황 대시보드의 「재작성 잔존율 확인 대상」 표도 오른쪽 경로에서만 나오는 값이다.

## 3. 원인

README 의 절 이름이 「번역 품질 게이트」 라서 그 아래 적힌 설명이 번역 전체에 걸리는 것으로 읽혔다.
그런데 그 설명은 게시글 재작성 게이트 (스펙 `2026-07-29-translation-trust-design.md` · `883c83a` · 2026-07-30) 의 내용이었다.
번역 경로의 검사는 그보다 먼저 다른 함수에 들어와 있었다 (`detect_title_hallucination` · `detect_title_mistranslation` · `detect_roundup_omission` 은 2026-07-19, `detect_club_injection` 은 07-20).
나중에 들어온 재작성 게이트의 설명이 먼저 있던 번역 경로까지 포함하는 이름 아래 놓였다.

같은 「게이트」 라는 이름 아래 코드 진입점이 둘 있는데, 문서는 하나만 보고 썼다.
README 를 마지막으로 고친 #534 · #536 은 수치와 소스 설명만 대조했고 동작 설명은 다시 대 보지 않았다.

## 4. 해결

#538 이 §6.3 을 경로 · 대상 · 검사 · 걸렸을 때의 네 열 표로 바꿨다.
마지막 문장도 「재작성 잔존율이 임계를 넘은 기사가 대시보드 「확인 대상」 표에 오른다」 로 범위를 밝혔다.

## 5. 예방

- 동작을 설명하는 문장에는 그 동작을 하는 함수 이름을 함께 적는다.
  함수 이름이 하나로 안 모이면 경로가 둘 이상이라는 신호다.
- 「○○ 게이트」 처럼 이름 하나로 묶인 장치를 문서로 옮기기 전에, 그 이름이 가리키는 코드 진입점이 몇 개인지 먼저 센다.
- README 대조는 수치만이 아니라 동작 설명 (무엇을 검사하고 걸리면 무엇을 하는가) 도 코드에 대 본다.
  이번에는 수치는 맞았는데 동작 설명이 틀렸다.
