# 원문이 200 으로 오류 안내를 주면 그대로 본문이 된다 (2026-08-02)

분류를 두 번 고쳐도 제자리로 돌아오지 않는 행이 하나 있어 파고들었더니, 원인이 분류가 아니라 수집이었다.
원문 URL 이 정상 응답 (200) 과 함께 "이 블로그는 이용할 수 없다" 는 안내를 돌려줬고, 그 문장이 언론사 본문으로 저장됐다.

## 1. 증상

- `5afe41a2` 행이 두 차례 재분류에서 모두 `interest` 를 받았다.
- 화면에 보이는 한국어 제목은 `아스날 관련 기사 서비스 일시 중단` 이고 요약도 같은 취지였다 — 기사가 아니라 공지로 보였다.
- 그런데 원문 제목은 멀쩡한 이적 기사였다.

| 필드 | 값 |
| --- | --- |
| `title_original` | `[Sky] 라이프치히, 리버풀의 관심 속 디오망데 이적료 £112M 요구` |
| `body_source` | `Sorry, this blog is currently unavailable. Please try again later.` |
| `body_level` | 2 (언론사 본문으로 채택됨) |
| `url` | Sky Sports 트랜스퍼 센터 라이브 블로그 (`?postid=…`) |

## 2. 원인

fmkorea 어댑터는 페이월이 아닌 소스면 원문 URL 을 받아 `extract_article_body` 로 본문을 뽑고 등급 2 를 준다.
게시글 본문 (등급 1) 으로 물러서는 폴백은 **`httpx.HTTPError` 가 났을 때만** 동작한다.

- Sky 라이브 블로그는 만료된 `postid` 에 대해 오류 코드가 아니라 **200 과 안내 문구**를 돌려줬다.
- 예외가 없으니 폴백이 걸리지 않았고, 안내 문구가 등급 2 본문으로 저장됐다.
- 번역 · 요약은 본문을 재료로 삼으므로 제목 (이적 기사) 과 본문 (안내) 이 서로 다른 글을 가리키게 됐다.
- 분류기는 `title_original` (이적 기사) 과 `summary_ko` (안내) 를 함께 받는다 — 모순된 입력에서 이적 쪽을 택한 판정이라 분류기 잘못으로 보기 어렵다.
- 기존 게이트는 재료의 **유무**만 본다.
재료가 아예 없으면 본문 생성을 막지만 (`partition_generatable`), 재료가 엉뚱한 글이면 통과시킨다.
길이도 방어가 되지 않는다 — 이 안내 문구는 한 문장이지만 등급 2 라서 길이 기준 검사 대상이 아니었다.

## 3. 조치 — 게시글 본문으로 복구 (2026-08-02)

fmkorea 게시글 본문은 멀쩡했다 (920자 · 정상 이적 기사 · 퍼가기 금지 표식 없음).
어댑터가 밟았어야 할 폴백을 사람이 대신 밟는 방식으로 이 행만 복구했다.

1. 게시글을 한 번 받아 `_body_text` · `strip_publish_datetime` 로 본문을 뽑는다 (VM 의 SOCKS 터널 경유 · 접촉 1회).
2. `body_source` 를 교체하고 `body_level` 을 2 에서 1 로 내린다.
등급 하락은 평소 금지지만 (레벨이 오를 때만 교체), 등급 2 값이 오류 안내라 근거가 없으므로 의도적으로 내렸다.
3. 번역 4필드와 분류 2필드를 NULL 로 되돌린다 — 다음 enrich 가 게시글 본문 기준으로 재생성한다.
4. enrich 전용 패스로 번역 · 분류를 재생성하고 (`docs/runbook/2026-07-19-enrich-only-pass.md` §3), 사이트를 다시 만들어 배포한다 (§4).

결과: 제목이 `라이프치히, 디오망데 이적료로 £112M 요구` 로 바뀌고 본문 · 요약도 실제 기사 내용으로 복구됐다.

## 4. 예방 — 계통 처리는 E안 몫

이 행 하나는 손으로 고쳤지만, 같은 함정은 원문이 오류를 200 으로 돌려주는 소스마다 재발한다.

- **원문 본문을 채택하기 전에 안내 · 오류 페이지인지 판정한다.**
상태 코드만으로는 부족하다 — 길이가 비정상적으로 짧거나, 제목의 고유명사 (선수 · 구단) 가 본문에 하나도 없으면 원문 채택을 포기하고 게시글 본문으로 물러서야 한다.
- 이 판정은 E안 (fmkorea 퍼가기 정책 개정) 의 게이트 4축 (구단 · 인명 · 수치 · 인용) 이 이미 겨냥하는 범위다.
사용자 확정 (2026-08-02) 에 따라 계통 수정은 E안 착수 때 함께 다룬다.
- 급하면 "제목 ↔ 본문 고유명사 대조" 만 떼어 작은 가드로 먼저 넣을 수 있다 — players 사전이 있어 인명 축은 바로 쓸 수 있다.

## 5. 진단 방법 (같은 유형을 찾을 때)

분류가 이상한데 프롬프트를 고쳐도 안 바뀌면, 판정을 의심하기 전에 **입력 필드를 나란히 본다**.

```sql
SELECT content_hash, source_id, body_level, title_original, title_ko, LEFT(body_source, 120)
  FROM articles WHERE content_hash LIKE '5afe41a2%';
```

- `title_original` 과 `body_source` 가 다른 사건을 말하고 있으면 분류 문제가 아니라 재료 문제다.
- 같은 유형을 훑을 때는 본문이 짧은 등급 2 행을 먼저 본다 — 정상 언론사 본문은 이렇게 짧을 수 없다.

```sql
SELECT content_hash, source_id, LEFT(body_source, 80)
  FROM articles WHERE body_level = 2 AND CHAR_LENGTH(body_source) < 200;
```
