# 손익을 비교할 때 잃는 자리를 하나로 셌는데 다섯이었다 (2026-08-14)

설계 문서가 두 안을 저울에 올려 하나를 골랐는데, 저울에 적힌 손실이 실제의 5분의 1이었다.
배포 뒤 사용자가 화면에서 손실을 보고 다시 발제해 결정이 뒤집혔다.

- 원 결정 — `docs/superpowers/specs/2026-08-12-arsenal-official-collection-revision-design.md` §3.3
- 뒤집은 개정 — 같은 문서 §7 (PR #275)

## 1. 무슨 일이 있었나

구단 공식 홈페이지가 이적 발표에 이적 태그를 빠뜨린 일이 있어 제목의 이적 어휘로도 기사를 줍는 경로를 새로 넣었다.
그때 「제목으로만 걸린 기사는 구단 공식 발표로 고정하지 않는다」 는 규칙을 함께 넣었다.
제목에 이적 어휘만 우연히 든 기사가 오피셜 배지를 다는 것을 막기 위해서였다.

설계 문서는 두 안의 손익을 이렇게 적었다.

> 오탐 기사는 배지를 완전히 잃는 반면 진짜 발표는 표기 하나만 잃는다.
> 손익이 대칭이 아니므로 고정 제외가 유리하다.

**「표기 하나」 가 실제로는 다섯 자리였다.**

- 메인 목록과 전체 목록의 기사 카드 배지.
- 기사 상세 페이지의 카드 배지.
- 선수 색인의 선수 카드 배지.
- 선수 페이지 머리 배지.
- 선수 페이지 사다리 최상단 줄의 단계 라벨.

## 2. 왜 하나로 셌나

설계 문서도 화면을 보고 썼다.
「로컬 렌더로도 확인해 봤다」 고 적혀 있고 실제로 확인한 내용이 남아 있다.

**본 것은 남아 있는 것이었고 사라진 것이 아니었다.**
그 절은 「진짜 발표는 사다리에서 최상단 · 이적 완료 · 구단 공식 표기를 그대로 유지한다」 고 적는다.
페이지를 열어 무엇이 아직 있는지는 확인했지만 무엇이 없어졌는지는 세지 않았다.

**한 값이 화면 여러 자리를 만든다는 것이 설계 시점에 안 보였다.**
단계 값 하나가 목록 카드 · 상세 카드 · 색인 카드 · 머리 배지 · 사다리 줄을 각각 만든다.
그중 머리 배지와 사다리 줄은 값을 직접 읽지 않고 **그 값을 가진 귀속 행이 있는지**로 갈린다 (`render.current_stage` 의 첫 갈래).
제목 채택 경로는 그 행을 아예 안 만들기 때문에 두 자리가 조용히 따라갔다.

## 3. 저울에 올리기 전에 자리를 세는 법

**코드를 짜기 전에도 셀 수 있었다.**
이 손실은 데이터 값 하나에서 나오므로, 운영 사본에서 그 값을 바꿔 전후를 렌더하면 자리가 그대로 나온다.

```sql
-- 사본에서 값 하나만 바꾼다 (운영이 아니라 사본이다)
UPDATE articles SET transfer_stage='official' WHERE content_hash LIKE '7dc5f8e5%';
UPDATE article_players ap JOIN articles a ON a.content_hash=ap.content_hash
   SET ap.stage='official' WHERE a.content_hash LIKE '7dc5f8e5%';
```

전후 두 벌을 렌더해 어느 파일이 달라졌는지 세면 자리 목록이 나온다.
절차와 함정은 `docs/runbook/2026-08-11-premerge-screen-check-with-prod-copy.md` §2.4 에 있다.

- **구현이 필요 없다** — 규칙을 고치지 않고 값만 바꿔도 화면 결과는 같다.
- 2026-08-13 에 이 방법으로 잰 결과는 파일 5건이었고 그것이 결정을 뒤집은 두 입력 중 하나였다.
- 다른 하나는 사용자가 그 손실을 화면에서 직접 봤다는 것이다.

## 4. 다음에 확인할 것

설계 문서에서 「잃는 것은 X 하나」 처럼 손실을 세는 문장을 쓸 때 다음을 지킨다.

- **남아 있는 것이 아니라 사라지는 것을 센다** — 페이지를 열어 확인한 것이 어느 쪽인지 문장으로 구분해 적는다.
- **한 값이 만드는 화면 자리를 전부 찾는다** — 값을 직접 읽는 자리뿐 아니라 **그 값을 가진 행의 존재로 갈리는 자리**까지 본다.
후자는 값 이름을 grep 해도 안 나온다.
- **셀 수 있으면 센다** — 사본에서 값 하나를 바꿔 렌더하면 되고 이 확인에 구현은 필요 없다.
- 저울이 틀렸다고 결정이 자동으로 뒤집히지는 않는다 — 이번 건도 개정 뒤 고정 제외 자체는 남았고 승격 조건이 하나 더 붙었을 뿐이다.
