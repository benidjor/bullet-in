# 자동 체크된 기자가 공신력 필터를 좁혔다 (2026-09-19)

- **영역**: 서빙 / 필터 (`app.js`)
- **관련 문서**: `docs/superpowers/specs/2026-07-21-ui-redesign-design.md` §7.2 · §8

## 1. 증상

전체 기사 페이지에서 공신력 「최상」 하나만 고르고 적용하면 상태줄이 「조건 5개 · 123건」 이다.
사이드바의 최상 건수는 125 인데 결과는 둘이 적고, 고른 것은 하나인데 조건은 다섯이다.
사용자가 2026-09-19 아침에 짚었다.

## 2. 원인

공신력을 고르면 그 등급의 소스 · 기자가 자동으로 체크된다 (스펙 §7.2).
최상을 고르면 기자 넷 (Ornstein · Mokbel · Horncastle · HandofArsenal) 이 체크되고, 코드는 그 체크를 조건으로 셌다.

```js
const srcActive = outlets.length || journalists.length;   // 자동 체크도 조건이 됐다
const conds = outlets.length + journalists.length + tiers.length + …;
```

그래서 등급은 최상인데 체크된 기자가 없는 기사 둘이 빠졌다.
The Athletic 의 기자 미상 기사 한 건과 Conor O'Neill · Jon Mackenzie 공저 한 건이다.
The Athletic 은 소스 선택지가 아니라 (설정 소스가 아니고 X · 커뮤니티 경유로 들어온다) 소스 축으로도 살아나지 못했다.

스펙은 이미 답을 적어 두었다.
「자동 체크는 결과를 바꾸는 장치가 아니라 그 등급에 무엇이 들어가는지 보여 주고 거기서 좁혀 가게 하는 출발점이다.」
2026-08-28 의 코드 주석도 같은 증상 (최상 94 → 91) 을 알고 있었지만, 기타 단계 쪽만 고치고 소스 조건은 그대로 두었다.

## 3. 처방

- 소스 · 기자는 사용자가 손댔을 때 (`userTouchedSrc`) 만 조건이 된다.
  조건 수도 그때만 센다.
- 주소 (`?journalist=…`) 로 받은 소스 · 기자는 사용자가 고른 것으로 친다.
- 라이브 HTML 에 고친 `app.js` 를 끼워 재현하니 「조건 1개 · 125건」 이고, 자동 체크된 기자 하나를 손으로 풀면 「조건 4개 · 61건 · 직접 고름」 으로 좁혀진다.
- 회귀 테스트는 `tests/test_filter_autocheck.py` 다.
  카드 넷짜리 페이지에서 실제 브라우저로 `app.js` 를 돌려 사이드바 건수와 결과가 같은지 본다.

## 4. 배운 것

- **보여 주는 체크와 거르는 체크는 상태가 달라야 한다.**
  같은 체크박스라도 누가 켰는지 (자동 · 사용자) 를 들고 있어야 결과가 스펙대로 된다.
- **주석에 남은 「실측 불일치」 는 미해결 버그의 표지다.**
  08-28 주석은 원인을 절반만 짚고 닫혔다.
