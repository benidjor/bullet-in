# 화면에 무엇이 보일지 두 번 잘못 셌다 (2026-10-20)

- **영역**: 화면 설계 · 측정 (서빙 렌더 · 운영 DB 조회)
- **관련 PR**: #542 (비수기 수집 범위 확대) · #547 (홈 구역 설계) · #548 (홈 구역 구현)
- **고친 것**: 설계 2026-10-07 §4 의 틀린 문장 정정 (#548) · 설계 2026-10-20 §6 의 수치를 사이트에 실리는 기사로 다시 셈 (#547) · 이 문서
- **남은 일**: 없음

## 1. 증상

비수기 수집 범위를 넓힌 뒤 (#542), 화면에 무엇이 보일지를 두 번 잘못 말했다.
두 번 모두 화면을 만드는 층을 건너뛰고 그 앞의 층을 보고 답한 것이 원인이었다.

| 언제 | 말한 것 | 실제 |
| --- | --- | --- |
| 설계 2026-10-07 §4 (#530) | 새로 받는 기사는 대부분 「기타」 가 되어 최신 뉴스에 배지 없이 섞여 나온다 | 「기타」 카드는 최신 뉴스에서 기본으로 숨는다 · 배포 뒤 첫 실행의 새 기사 23건 중 22건이 숨었다 (2026-10-12) |
| 홈 구역 설계 중 측정 (2026-10-20) | 배포 뒤 「기타」 97건 중 제목에 이적 낱말 5건 · 그중 셋은 아스날과 무관 (첼시 · 맨유) | 사이트에 실리는 「기타」 는 85건 · 이적 낱말 2건 · 둘 다 구단 소식이었다 · 첼시 · 맨유 글은 사이트에 아예 실리지 않는다 |

## 2. 원인

### 2.1. 설계 문장이 카드 템플릿을 읽지 않았다

「배지 없이 섞여 나온다」 는 이적 단계 배지가 없으면 배지만 빠진다고 짐작한 문장이다.
실제 카드 템플릿은 배지가 없는 카드를 숨겼다.

```jinja
{# src/bullet_in/serve/templates/_cards.html.j2 (#548 이전) #}
{% if hidden or (not show_all and not a._stage_disp) %} style="display:none"{% endif %}
```

최신 뉴스는 날짜 묶음의 앞 셋을 펼치는데, 날짜를 셀 때는 「기타」 를 넣었지만 카드에서는 「기타」 를 숨겼다.
그래서 「기타」 뿐인 날짜는 빈 채로 펼칠 자리를 차지했다.
2026-10-20 배포본에서는 첫 세 날짜 중 두 날짜가 그렇게 사라져, 최신 뉴스 첫 화면에 카드가 2장만 남았다.

### 2.2. DB 를 셌는데 화면 앞에 거르는 단계가 하나 더 있었다

홈 구역 설계에서 「이적 이야기인데 단계가 없는 기사」 를 운영 DB 의 `articles` 에서 셌다.
그런데 렌더 전에 서빙 단계가 fmkorea 글을 한 번 더 거른다.

```python
# src/bullet_in/run.py — publish
rows, hidden, stale = serving_rows(rows, relevance_terms=fm.relevance_terms,
                                   player_names=fm.player_names, linked=linked)
```

제목에 아스날 관련 말이 없는 fmkorea 글은 확정 명단 선수에게 주체로 연결되지 않는 한 렌더 입력에서 빠진다.
배포 뒤 「기타」 97건 중 12건이 여기서 빠졌고, 「아스날과 무관」 으로 센 첼시 · 맨유 글이 모두 그 12건 안에 있었다.

예시 기사의 링크를 붙이려고 사이트의 상세 페이지를 찾다가, 일부 기사에 페이지가 없는 것을 보고 알아챘다.

## 3. 해결

- **설계 2026-10-07 §4** — 「배지 없이 섞여 나온다」 를 「기본으로 숨어 화면에 거의 나오지 않았다」 로 고치고 새 설계 (2026-10-20) 를 가리켰다 (#548)
- **설계 2026-10-20 §6** — 사이트에 실리는 기사만 다시 셌다 · 여름 이적시장 마감 무렵 「기타」 24건은 전부 제목 · 요약을 읽고 나눴다 (#547)
- **화면** — 홈을 「이적 뉴스」 · 「선수 · 팀 뉴스」 두 구역으로 나누고 「기타」 를 늘 보이게 했다 (#548 · #549)

## 4. 예방 — 화면에 보일 것을 세는 법

| 묻는 것 | 세는 자리 | 세면 안 되는 자리 |
| --- | --- | --- |
| 이 기사가 화면에 보이나 | 카드 템플릿의 숨김 조건 · 배포 산출물 (또는 그 산출물을 브라우저로 연 결과) | 저장값 (`transfer_stage`) 만 |
| 사이트에 몇 건이 실리나 | 서빙 입력 (`SERVING_SELECT_SQL` → `serving_rows`) · 배포본 `site/article/<해시>.html` 이 있는지 | `articles` 전체 |
| 어떤 기사가 섞여 보이나 | 위 서빙 입력에서 뽑은 표본 | DB 에서 뽑은 표본 |

- 배포본으로 빠르게 대 보는 법: VM 의 `~/bullet-in/site/article/` 에 그 해시의 파일이 있으면 사이트에 실린 기사다.
- 화면을 바꾸기 전에는 운영 사본으로 렌더해 본다 (`docs/runbook/2026-08-11-premerge-screen-check-with-prod-copy.md`).
  렌더한 서빙 기사 수가 배포본 사이드바의 「전체 N건」 과 같은지 먼저 확인한다 (2026-10-20 · 1,297건 일치).

## 5. 교훈

- 두 번 모두 「DB 에 있다」 와 「화면에 나온다」 사이에 단계가 하나 더 있었다 (카드 숨김 · 서빙 필터).
  화면에 대한 문장은 화면을 만드는 마지막 층에서 확인한다.
- 숨겨져 있던 데이터를 보이게 하는 변경은 그 안에 섞여 있던 품질 문제도 함께 드러낸다.
  #548 뒤로는 분류 오류 (경기 명단 트윗에 「루머」) 와 영입 대상 선수의 다른 구단 근황이 화면에 드러났다.
