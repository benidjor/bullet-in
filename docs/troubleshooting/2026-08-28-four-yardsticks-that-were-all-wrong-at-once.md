# 새 수집 코드를 확인하려다 잣대 넷이 한꺼번에 틀렸다 (2026-08-28)

2026-08-28 에 fmkorea 수집 코드 둘을 바꿨다 — 원문 접속이 막힐 때 게시글 이미지를 쓰는 폴백과, 게시글 본문 상한을 2000 자에서 4000 자로 올린 것이다.
다음 회차에 「이게 실제로 도는가」 를 확인하려고 적어 둔 검증 절차가 있었는데, 그 절차의 **네 자리가 전부 틀려 있었다.**
그대로 돌렸으면 「상한 상향이 이미 돌고 있다」 는 반대 결론이 나왔을 것이다.

데이터는 멀쩡했다.
틀린 것은 전부 재는 쪽이었다.

## 1. 자를 시각 — 다른 PR 의 시각을 적어 두었다

절차에는 `fetched_at > '2026-08-28 12:00:00'` 이라고 적혀 있었다.
12:00 은 화면 고침 PR (#368) 이 VM 에 올라간 시각이다.
정작 수집 변경 둘은 **#367** 에 들어 있었고 그것은 한 시간 반 앞서 들어갔다.

```
316d622 HEAD@{2026-08-28 21:00:24 +0900}: pull --ff-only   ← #368 (화면)
abb6eb6 HEAD@{2026-08-28 19:30:35 +0900}: pull --ff-only   ← #367 (수집 · 검증 대상)
```

기준선은 `git log` 가 아니라 **VM 의 `git reflog`** 에서 나온다.
머지 시각과 반영 시각은 다르고, 도는 것은 반영 시각 쪽이다.

## 2. 길이 함수 — `LENGTH()` 는 문자가 아니라 바이트다

상한은 파이썬 슬라이스 (`[:4000]`) 라 **문자 수**다.
그런데 검증 질의는 `LENGTH(body_source)` 를 썼고 MariaDB 의 `LENGTH` 는 바이트를 돌려준다.
한글은 UTF-8 에서 한 자가 3바이트라 값이 2.4 ~ 3배로 부푼다.

```
LENGTH      로 보면   최대 4912   → 「2000 도 4000 도 이미 넘었다」
CHAR_LENGTH 로 보면   최대 2000   → 「옛 상한에 정확히 붙어 있다」
```

**부푼 값이 그럴듯한 크기였던 것이 함정이다.**
4912 는 「4000 상한이 도는 중」 으로도 읽히는 숫자라, 데이터를 의심하게 되지 도구를 의심하게 되지 않는다.

## 3. 대상 경로 — 상한이 하나가 아니었다

`_BODY_MAX_CHARS = 4000` 은 **게시글 본문 경로에만** 걸린다.
원문 기사 경로는 `extract_article_body` 의 8000 을 따로 쓴다.
두 경로를 섞어 세면 8000 짜리 행이 표본에 들어와 상한 판정을 흐린다.

가르는 열은 `body_level` 이다 — 1 이 게시글 본문, 2 가 원문이다.

## 4. Mongo 비교 — 타입이 안 맞으면 오류 대신 0건이 나온다

`raw_items.fetched_at` 은 BSON 날짜가 아니라 ISO 문자열이다.
`{"fetched_at": {"$gt": datetime(...)}}` 는 타입이 달라 **아무것도 안 맞고, 오류도 안 난다.**
「배포 이후 0건」 이라는 답이 나오는데 그 0 은 조회가 실패했다는 뜻이었다.

같은 자리에 겹이 하나 더 있었다 — 본문은 문서 최상위가 아니라 `raw_payload` 안에 있어서, `d.get("body")` 는 전건 빈 문자열을 돌려줬다.
`chars=0` 이 170행 내리 찍히는데도 그것이 「본문이 없다」 로 읽힌다.

## 교정한 잣대와 그때 나온 기준선

```sql
SELECT content_hash, image_url IS NOT NULL, CHAR_LENGTH(body_source), fetched_at
FROM articles WHERE source_id = 'fmkorea' AND body_level = 1
  AND fetched_at > '2026-08-28 10:30:35' ORDER BY fetched_at DESC;
```

```
fmkorea 등급 1 · 170행 전량 — 최대 2000자 · 2000 초과 0건
                              1990 ~ 2000 구간에 34행 (20%) 이 붙어 있다 = 잘린 행
```

새 코드가 돌면 이 34행 자리가 2000 위로 올라간다.
그게 아직 안 생겼으므로 판정은 「안 된다」 가 아니라 **「아직 안 왔다」** 다.

## 「한 번도 안 돌았다」 와 「돌았는데 남은 게 없다」 는 다르다

저장이 안 늘었다고 코드가 안 돈 것은 아니다.
보충 수집기는 `adapter.fetch()` 가 끝난 뒤에만 접촉 스탬프를 찍는다.

```python
raw = await adapter.fetch()
write_last_contact(STATE_PATH, now)  # 신규 0 이어도 접촉 스탬프
```

VM 의 `~/.bullet-in/fmkorea_last_contact` 이 `2026-08-28T10:33:13` 이었다 — 반영 3분 뒤에 새 코드로 한 번 접촉했고, 새 글이 없어 저장이 안 됐을 뿐이다.
**같은 함정을 반대 방향으로 밟은 사례가 이미 있다** (`2026-08-28-we-called-a-source-dead-without-opening-the-box.md`).

## 남길 것

- **잣대는 단위 · 층 · 범위 · 타입 네 자리에서 어긋난다** — 이번엔 그 넷이 한 번에 나왔다 (바이트 · 경로별 상한 · PR 시각 · BSON 타입).
- **부푼 값이 그럴듯하면 더 위험하다** — 자릿수가 맞으면 도구가 아니라 데이터를 의심하게 된다.
- **조용히 0건을 내는 조회를 경계한다** — 「없다」 와 「못 물었다」 가 같은 모양으로 나온다 (`2026-08-23-we-asked-the-journal-a-question-it-could-not-answer.md` 와 같은 겹).
- **반영 시각은 VM `git reflog` 에서 얻는다** — 머지 시각으로 자르면 다른 PR 을 재게 된다.
