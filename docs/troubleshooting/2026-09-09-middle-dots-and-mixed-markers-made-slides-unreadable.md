# 가운뎃점과 두 종류의 화살표가 슬라이드를 못 읽게 만들었다 — 외부 독자용 문장 규칙 (2026-09-09)

- **영역**: 문서 / 외부 독자용 산출물 (슬라이드 · 소개 자료)
- **관련 산출물**: 프로젝트 소개 슬라이드 4 ~ 20장 · 세션 메모리 `external-audience-terms`
- **관련 안건**: 없음 (작업 규율)

## 배경

2026-09-09 통독에서 사용자가 여러 장에서 같은 말을 반복했다.
「이 문장이 무슨 말인지 모르겠다」 였다.
문장을 하나씩 뜯어 보니 낱말이 어려운 것이 아니라 **기호와 표식의 쓰임이 흔들려서** 문장의 경계가 안 보였다.
저장소 안 문서 (`docs/`) 에서는 통하던 습관이 슬라이드에서는 통하지 않았다.

## 드러난 것 셋

### 1. 가운뎃점 「`·`」 을 쉼표 자리에 썼다

「매일 01:30 UTC 자동 실행 · VM 이 꺼져 있었으면 재기동 뒤 놓친 백업을 1회 실행 · 실패하면 Discord 사고 채널로 알림」 같은 줄이 장마다 있었다.
「`·`」 은 짧은 명사를 나란히 적는 기호인데 절과 절 사이에 쓰니 어디서 문장이 끝나는지 알 수 없었다.
사용자가 「`·`」 을 쉼표 대신 쓴 것이냐고 물었고, 그 뒤로 규칙을 하나로 했다.
「`·`」 은 `RSS · REST API · 정적 HTML` 처럼 짧은 명사 나열에만 쓰고, 절과 절 사이는 「`,`」 로 잇는다.

### 2. 자동 표식과 글자 화살표가 섞였다

목록 CSS 가 하위 항목 앞에 작은 회색 「`⇒`」 를, 그 아래 단계에 「`→`」 를 자동으로 찍고 있었다.
거기에 내가 문장 앞에 「`⇒`」 를 또 넣어 「`⇒ ⇒`」 가 되었고, 문장 안의 「`→`」 와 표식의 「`→`」 는 크기와 색이 달랐다.
사용자는 같은 기호가 두 모양으로 보이는 이유를 물었다.
표식을 「`·`」 (항목) 과 「`→`」 (하위 항목) 둘로 줄이고 본문과 같은 크기 · 색으로 맞췄다.
문장 첫머리에는 화살표를 두지 않는다.
「`⇒`」 는 문장 안의 결론 자리에만 남긴다.

### 3. 항목 안에서 임의로 줄을 끊었다

긴 항목을 `<br>` 로 끊어 두 줄로 만들었더니, 둘째 줄에 표식이 없어 「같은 항목이 이어지는 것인지 새 항목인지」 알 수 없다는 지적이 나왔다.
이어지는 내용은 「`→`」 하위 항목으로 빼고, 항목 안의 `<br>` 은 쓰지 않는다.
남는 줄바꿈은 한 문장이 폭에 맞춰 감긴 것뿐이어야 한다.

## 같은 회차에 사용자가 못 알아본 말

저장소 안에서 석 달을 산 말이라 쓰는 쪽은 어색한 줄 몰랐다.
재계수, 픽스처, advance, judge, 훅, 문서 지도, 폴백, 백필, 재큐, 세그폴트, 라우팅, 논리 덤프, 매니페스트, 세대 보관, blocked, PSS, RSS, 유닛, 임계 경로, 컴팩션, 멱등성, 워터마크, 귀속, 「고아 0건」, 「배운 것」, 「완료는 실측으로만」, 「경계를 어긴 사고」 가 그것이다.
전부 풀어 썼고 목록은 세션 메모리 `external-audience-terms` 에 있다.
「오경보」 는 「오탐」 으로, 「귀속」 은 「매핑」 으로, 「고아」 는 「고아 데이터」 로 정했다.

## 배운 것

- 슬라이드는 한 줄이 한 항목이다.
  줄 안에서 문장을 여러 개 잇는 순간 기호가 문장 부호 노릇을 해야 하는데, 「`·`」 은 그 일을 못 한다.
- 표식은 두 가지를 넘기지 않고, 표식과 본문의 기호를 같은 모양으로 맞춘다.
- 프로젝트 소유자가 못 알아본 말은 면접관도 못 알아본다.
  소유자가 되묻는 것이 가장 싼 검사다.
