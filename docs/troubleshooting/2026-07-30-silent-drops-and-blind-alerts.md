# 조용히 새는 수집과 그것을 못 보는 알림 (2026-07-30)

"배포판에 오늘 기사가 하나도 없다" 는 질문에서 시작해 세 가지가 드러났다.
수집한 트윗을 필터가 버리고 있었고, 같은 행이 하루 여덟 번 헛되게 재번역되고 있었고, 신선도 알림은 그 손실을 가리키면서도 원인을 틀리게 지목하고 있었다.

공통점은 **드롭이 로그에도 카운트에도 남지 않는다**는 것이다.
`drop 집계` 는 `to_articles` 단계만 세므로 그 앞에서 버려지면 흔적이 없다.

## 1. afcstuff 인용 필터가 형태 하나만 알고 있었다

### 1.1. 증상

사용자가 "2시간 전에 올라온 트윗이 왜 배포판에 없나" 고 물었다.
스노플레이크 ID 로 계산하니 게시 시각이 17:19:45 KST 였고, 18:03 회차가 44분 뒤에 돌았는데도 DB 에 없었다.

`errors: {}` · `success_rate 1.0` 이라 어댑터는 예외를 던지지 않았다.
Playwright 는 httpx 처럼 요청 로그를 남기지 않으므로 로그만 봐서는 어댑터가 무엇을 했는지 알 수 없었다.

### 1.2. 진단 — 스크랩 단계와 필터 단계를 분리해서 잰다

어댑터를 단독으로 돌려 두 단계를 갈랐다.

```
타임라인 렌더 O (쿠키 4개 유효 · 로그인 벽 아님)
① 스크랩한 트윗 30건 · 지목 트윗 포함 O
② 인용 필터 통과 8건 · 지목 트윗 버려짐   ← 여기가 원인
```

쿠키 문제도 셀렉터 문제도 아니었다.
가져온 뒤 버리고 있었다.

### 1.3. 원인

`parse_afcstuff_tweets` 가 대괄호 인용만 인정했다.

```python
_CITE_RE = re.compile(r"\[\s*@([A-Za-z0-9_]{1,15})\s*\]")
```

afcstuff 는 인용을 두 형태로 쓴다.

| 형태 | 예 | 이전 결과 |
| --- | --- | --- |
| 대괄호 | `Eddie Howe has quit… [@David_Ornstein]` | 통과 |
| 멘션 + 콜론 | `@JacobsBen : "I think Arsenal have grown in optimism…"` | **버려짐** |
| 이름 + 괄호 핸들 | `Bruno Andrade (@ESPNBrasil): "Speaking to someone involved…"` | **버려짐** |

버려지는 쪽이 기자 발언 relay 로 ITK 가치가 가장 높았다.

### 1.4. 규모 — 버려짐과 잘못 버려짐을 구분해야 한다

라이브 30건을 분류했다.

```
대괄호 인용   8건  → 이전에도 수집
콜론형 인용   4건  → 잘못 버려지던 것
인용 없음    18건  → 제외가 맞다
```

처음에 "30건 중 22건이 버려지니 73% 손실" 이라고 말했는데 과장이었다.
18건은 생일 축하 · 훈련 사진 · 인스타 언급 · 기자회견 발언 · afcstuff 자체 보도로, 인용 주체가 없어 `x_mentions` 신뢰도 모델로 tier 를 매길 수 없다.
**실제 결함은 4건 (13%)** 이다.
다만 afcstuff 가 회차당 2~4건을 내던 상황이라 4건이면 수집량이 사실상 배가 된다.

### 1.5. 조치와 검증 (PR #163)

콜론 앞까지 공백 · 개행 · 닫는 괄호만 허용해 문장 중간 멘션을 오탐하지 않게 했다.
대괄호 인용이 있으면 그것만 쓴다 — 합치면 본문 중간 멘션이 대표 기자를 밀어내 tier 가 오귀속된다.

머지 · VM 반영 뒤 첫 회차에서 `x_afcstuff` 가 2건에서 7건으로 늘고 지목된 트윗이 적재됐다.

### 1.6. `x_ornstein` 은 정상이었다

같은 세션에서 함께 쟀다.
본인 트윗 경로는 `#AFC` 태그를 요구하고 30건 중 3건만 통과한다.
버려진 27건은 뉴캐슬 · 첼시 · 리즈 · 레알 등 아스날 무관 기사였다
— 온스테인은 전 구단을 다루고 `#AFC` 가 아스날 표식이므로 제외가 맞다.

## 2. 트위터 계정 없는 기자가 매체 계정으로 인용된다

Bruno Andrade 는 계정이 없어 afcstuff 가 소속사 계정으로 인용한다.
등재 전에는 `fallback_tier` 4 로 떨어져 **같은 보도가 경로에 따라 공신력이 갈렸다**.

```
ESPN Brasil 원문 (questão de honra)
  ├─ afcstuff 트윗 [@ESPNBrasil]        → tier 4.0 (공신력 최하)
  └─ fmkorea 퍼온 글 [ESPN-브루노 안드라데] → tier 2.0 (공신력 중)
```

`config/credibility.yaml` 에 매체 핸들을 별칭으로 등재해 해소했다.
표시명에 소속을 넣은 이유는 핸들이 개인이 아니라 매체 계정이라 독자가 발화자를 알 수 없기 때문이다.

```yaml
- {name: Bruno Andrade (ESPN), tier: 2, outlet: ESPN,
   aliases: ["@ESPNBrasil", "Bruno Andrade", "브루노 안드라데", "안드라데"]}
```

**주의** — 매체 계정을 개인 별칭으로 쓰므로 같은 매체의 다른 기자를 인용한 트윗도 이 이름으로 귀속된다.
실측 범위에서는 해당 핸들 인용이 전부 Bruno Andrade 보도였다.

### 2.1. 설정을 바꿔도 기존 행은 안 바뀐다

`tier` 는 수집 시점에 계산돼 컬럼에 저장된다.
표시명은 렌더 시점에 레지스트리를 다시 조회하므로 자동으로 고쳐지지만, `tier` 와 `confidence_score` 는 DB 를 고쳐야 한다.
안 고치면 화면에 **이름은 새 표시명인데 공신력은 옛 값**으로 나온다.

델타만 고친다 (전건 재 resolve 는 과거 드리프트를 건드려 금지 — `2026-07-23-tier-recompute-stale-drift.md`).
계산은 파이프라인과 같은 함수를 재사용한다.

```
후보 2행
  [변경] 605f108e · x_afcstuff · @ESPNBrasil   · tier 4.0 → 2.0 · conf 0.0 → 0.5
  [동일] a6d6b098 · fmkorea    · 브루노 안드라데   · tier 2.0 → 2.0
```

## 3. 같은 행이 하루 여덟 번 재번역 큐에 다시 들어간다

goal 기사 `White flag: Arsenal give up on Vinicius Junior deal` 이 회차마다 재큐되고 있다.

```
Jul 30 00:02 · 03:04 · 06:04 · 09:05 · 12:04 · 15:03 · 18:05 · 21:06
→ 전부 content_hash=3740329594… 의심=['인명 누락:White']
```

제목의 `White` 는 **"백기 (white flag)" 라는 관용구**인데 게이트가 선수 Ben White 의 인명 누락으로 오판한다.
재시도 횟수 상한이 없어 매 회차 Gemini 를 헛되게 부른다.
오늘 하루만 8회이고 이전 날짜까지 합치면 더 많다.

**미해결** — 상한을 두거나 관용구 예외를 넣어야 한다.
다음 세션 착수 항목이다.

## 4. 신선도 알림이 원인을 틀리게 지목한다

경고 4건 (arsenal_official 149h · bbc_sport 69h · guardian 177h · x_ornstein 81h) 을 받고 원인 후보를 확인했다.

`notify.py` 가 어댑터 종류만 보고 고정 문구를 붙인다.

```python
hint = ADAPTER_HINTS.get((sources.get(b.source_id) or {}).get("adapter"))
```

`adapter: html` 이면 무조건 "셀렉터 드리프트 · 사이트 개편" · `x_playwright` 면 무조건 "쿠키 만료 · 핸들 변경" 이다.
진단이 아니라 사전에 적어 둔 추측이고, 실측하니 **둘 다 사실이 아니었다**.

- **bbc_sport 셀렉터 배제** — 단독 검증: `item_selector` 21건 → 중복 제거 18 → 제목 확보 7 → 키워드 통과 **4건**.
후보 4건이 전부 기존 기사여서 신규가 0이었다.
제목 요소를 못 찾은 11건은 `Read more on…` 같은 본문 내 인라인 링크로, `title_selector` 가 헤드라인 카드와 인라인 링크를 가르는 가드로 제대로 작동한 것이다.
- **x_ornstein 쿠키 배제** — 같은 쿠키 파일을 쓰는 `x_afcstuff` 가 같은 날 적재했다.
- **guardian · arsenal_official** — 각각 총 5행 · 6행짜리 저빈도 소스다.

### 4.1. 근본 원인은 후보 건수를 기록하지 않는 것

`source_counts` 는 신규 적재만 센다.
그래서 두 상태가 똑같이 0으로 보인다.

- 후보 0건 = 수집이 실제로 끊김 (알려야 함)
- 후보는 있으나 전부 중복 = 정상 (알릴 필요 없음)

`arsenal_official` 에만 퍼널 지표가 있다 (`coverage`: 후보 · Men · accept).
전 소스로 일반화하면 알림이 사실 기반이 된다.
**어댑터 예외가 없다는 것은 정상 동작의 증거가 아니다** — 셀렉터가 0건을 찾아도 예외는 안 난다.

별도 트랙으로 분리했다 (세션 메모리 `slo5-freshness-alert-track`).

### 4.2. 부수 — Guardian API 키가 로그에 평문으로 남는다

`journalctl` 의 `content.guardianapis.com/search?...&api-key=...` 요청 URL 에 키가 그대로 보인다.
위험도는 낮지만 위생 문제다.
