# 낡은 문서를 한 줄 고쳤더니 CI 가 그 파일 전체를 검사했다 (2026-09-01)

- **영역**: CI / 문서 서식
- **관련 PR**: #406

## 증상

문서 정정 PR 이 CI 의 「문서 서식」 잡에서 떨어졌다.
지적된 여섯 줄 가운데 **내가 이번에 쓴 줄은 하나도 없었다.**

```
문서 서식 위반 (컨벤션 §2.2)
  docs/runbook/2026-05-27-daily-operations.md    line 31
  docs/runbook/2026-05-27-dbt-quality-gate.md    line 7 · 9 · 10 · 11 · 58
```

여섯 줄 다 **여는 괄호 앞 공백**이 빠진 자리이고, 두 문서 다 서식 규약보다 오래된 2026-05-27 자 문서다.
걸린 모양은 이렇다.

```
`unique`(중복 0) · `not_null`(필수 필드) · `accepted_values`(tier 0~4)
```

**이 문서를 쓰면서도 같은 검사에 한 번 걸렸다** — 위 예시를 산문에 그대로 실었더니 검사기가 그것을 위반으로 읽었다.
위반 예시는 코드 블록 안에 둔다 (검사기가 코드 펜스를 건너뛴다).

## 원인 — 게이트가 재는 축이 내가 잰 축과 달랐다

CI 는 이렇게 돈다.

```bash
for f in $(git diff --name-only --diff-filter=d "$BASE_SHA" HEAD -- 'docs/**/*.md'); do
  ... | python3 .claude/hooks/check-doc-format.py
```

**바뀐 파일을 고른 다음 그 파일을 통째로 검사기에 넣는다.**
줄 단위 델타가 아니다.

나는 게시 전에 `origin/main` 사본과 대조해 **「전 5건 · 후 5건 · 내 변경이 만든 위반 0건」** 을 확인했고, 프로젝트 지침의 「인접 코드를 개선하지 않는다」 를 근거로 그대로 뒀다.
**두 잣대가 다른 것을 재고 있었다.**

## 해결

여섯 줄에 여는 괄호 앞 공백만 넣었다.
문장은 손대지 않았다.

```
`unique`(중복 0)  →  `unique` (중복 0)
```

## 예방

- **`docs/` 아래 낡은 문서를 건드리면 그 파일 전체를 통과시켜야 한다.**
  고칠 범위는 서식뿐이고 문장은 그대로 둔다.
- **게시 전 검증도 CI 방식으로 한다.**
  바뀐 docs 목록을 `git diff --name-only ... -- 'docs/**/*.md'` 로 뽑고, 그 파일들을 **통째로** 검사한다.
  델타를 재지 않는다.

## 더 넓은 교훈

**「내가 나빠지게 만들지 않았다」 와 「게이트가 통과시킨다」 는 다른 명제다.**
규율끼리 부딪히면 기계가 강제하는 쪽이 이긴다 — 인접 수정 금지는 사람의 약속이고 CI 는 차단이다.
