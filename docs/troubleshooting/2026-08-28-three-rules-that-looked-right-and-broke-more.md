# 그럴듯한 규칙 셋을 실측에 대 봤더니 고치는 것보다 깨는 것이 많았다 (2026-08-28)

한 회차에 **규칙 셋을 짜서 운영 데이터 전체에 대 봤고, 셋 다 처음 모양으로는 못 썼다.**
셋 다 「말로는 맞는」 규칙이었고, 틀린 것은 규칙이 아니라 **그 규칙이 걸리는 실제 문자열의 분포**였다.

건진 것은 규칙이 아니라 **절차**다 — 고치기 전에 전량에 대 보고 바뀌는 것을 전수로 읽는다.

## 1. 규칙 A — 「성 앞이 붙어 있으면 다른 사람이다」

「맨체스터 유나이티드 · 웨스트햄, 레스터 시티 **벤 넬슨** 영입 주시」 가 아스날 **리스 넬슨**의 사건 묶음에 들어와 있었다.

사건 묶음은 제목에서 선수 이름을 부분 문자열로 찾는다 (`protagonist`).
서빙 사건 사전 97개 중 **87개가 성만** 담고 있어, 같은 성을 쓰는 다른 사람이 제목에 나오면 걸린다.

첫 규칙은 이랬다 — **성 바로 앞이 한글 · 하이픈으로 붙어 있으면 다른 이름의 꼬리다.**

전 기사 913건에 대 보니 주인공이 바뀌는 기사가 5건이었다.

```
화이트 -> None   아스날, 깁스-화이트 영입 경쟁… PSG 가세          ← 맞음
두에  -> None   인터밀란, 겔라두에 영입 가속화                   ← 맞음
크루피 -> None   니코 오라일리 대신 엘리 주니오르크루피가 …         ← 우리 선수다
크루피 -> None   아스날, 주니오르크루피 여름 이적 타겟 낙점…        ← 우리 선수다
크루피 -> None   엘리 쥐니오르크루피, 중족골 골절상으로 …           ← 우리 선수다
```

**우리 선수의 이름을 공백 없이 붙여 쓴 제목이 있었다.**
「엘리 주니오르 크루피」 를 「주니오르크루피」 로 쓰면 이 규칙이 그를 남으로 만든다.
고치는 것 둘 · 깨는 것 셋이라 순손해다.

## 2. 규칙 B — 「성 앞말이 우리 선수의 이름이 아니면 다른 사람이다」

풀네임을 알고 있으니 (`ko_full_name`) 「벤 넬슨」 의 「벤」 이 「리스」 가 아닌 것을 보면 된다.

전 기사에 대 보니 **46건이 함께 사라졌다.**

```
콘사   -> None   아스날, 아스톤 빌라 수비수 콘사 영입 위한 추가 협상 돌입
은와네리 -> None   AC 밀란, 아스날 유망주 이선 은와네리 영입 관심
촐리스  -> None   아스날, 그리스 공격수 촐리스 3,400만 파운드에 영입
업슨   -> None   아스날, 토트넘 유망주 업슨 자유 계약 영입 합의
```

**한국어 제목은 성 앞에 보통명사를 자주 붙인다** — 「수비수 콘사」 · 「유망주 은와네리」 · 「공격수 촐리스」.
게다가 이름 표기가 흔들린다 — 「흐리스토스 촐리스」 · 「일랑 멜리에」 · 「줄리안 알바레스」 · 「이단 은와네리」.
풀네임이 세 토막인 경우도 규칙이 못 버틴다 (「엘리 주니오르 크루피」 의 앞말은 「주니오르」 다).

## 3. 규칙 C — 「추출이 그 선수를 안 붙였으면 남의 기사다」

세 번째는 우리가 이미 돈을 내고 얻는 신호를 쓰자는 것이었다.
추출 (`article_players`) 은 그 벤 넬슨 기사에 넬슨을 안 붙였다 — 정답을 이미 냈다.

전 기사에 대 보니 **제목이 정한 주인공을 추출이 안 붙인 기사가 21건**이었고, **그중 8건이 비니시우스**였다.

```
비니시우스 영입 불발된 아스날, 대체 자원 물색 나서
비니시우스 주니오르, 레알 마드리드와 2032년까지 재계약…아스날 영입 희망 무산
아스날, 비니시우스 주니오르 영입 가능성 타진
```

**제목이 맞고 추출이 놓친 것이다.**
사전 차이도 아니었다 — 서빙 사전 97 · 추출 사전 97 로 같았다.
거부권으로 쓰면 고치는 3건보다 깨는 8건 이상이 많다.

## 4. 채택한 것 — 사람이 확인한 목록

자동 규칙을 접고 **전체 913건을 전수 대조해 실제로 걸린 남의 이름을 셌다.**
넷이었다.

```python
_NOT_OUR_PLAYERS = ("벤 넬슨", "리 딕슨", "깁스-화이트", "겔라두에", "겔라 두에")
```

제목 매치 전에 이 문자열을 같은 길이의 공백으로 지운다.
문자열 치환이라 목록에 없는 제목은 손대지 않고, 적용 후 주인공이 바뀌는 기사도 **정확히 그 넷뿐**이다.

```
화이트 -> None    아스날, 깁스-화이트 영입 경쟁… PSG 가세
넬슨  -> None    맨체스터 유나이티드·웨스트햄, 레스터 시티 벤 넬슨 영입 주시
두에  -> None    인터밀란, 겔라두에 영입 가속화
딕슨  -> 래시포드   아스날 레전드 리 딕슨, 마커스 래시포드… 스왑딜 제안
```

마지막 줄이 덤이다 — 리 딕슨 (해설자) 을 지우니 그 기사의 진짜 주인공이 드러났다.

## 5. 같은 회차의 네 번째 — 정렬 키에 축을 끼우는 자리

같은 날 별개의 자리에서 한 번 더 밟았다.

묶음 대표를 고르는 `pick_representative` 가 「최신」 을 시각 하나로 봐서, **집계 계정이 2분 늦게 올린 트윗이 The Athletic 원문을 이겼다.**
「본문이 있는 쪽을 앞세우자」 는 축을 넣었는데, 최신보다 **앞에** 뒀더니 7월 기사가 8월 소식의 대표가 됐다.

```
전: 아스날, 리스 넬슨과 계약 해지 합의        (2026-08-28)
후: 아스날 리스 넬슨, 해외 구단들 영입 관심     (2026-07-21)   ← 본문이 있다는 이유로
```

**정렬 키에서 축의 순서가 곧 규칙이다.**
「본문 우선」 은 「같은 날 안에서」 라는 범위가 붙어야 뜻이 통한다.
최신을 **날짜 → 본문 → 시각** 세 단계로 나누니 전수 대조에서 대표가 바뀌는 묶음이 둘로 줄었고 (스콧 · 은와네리) 둘 다 트윗에서 본문 있는 원문으로 바뀌었다.

## 6. 규율

**규칙을 짰으면 운영 데이터 전량에 대 보고 「바뀌는 것」 을 전수로 읽는다.**
계수만 보면 안 된다 — 규칙 A 는 「5건 바뀜」 이었고 그 5건을 읽어야 셋이 오작동인 것이 보인다.

**바뀌는 것이 적다는 것은 안전하다는 뜻이 아니다.**
규칙 A 는 5건 중 3건이 손해였다.

**한국어 제목에서 「이름 앞에 무엇이 오는가」 로 사람을 가르려 하지 않는다.**
보통명사 · 구단명 · 직책이 모두 그 자리에 온다.

**모델이 낸 신호를 거부권으로 쓸 때는 그 신호의 미탐률을 먼저 센다.**
추출은 정확할 때 정확하지만 놓칠 때도 있고, 거부권은 **놓친 자리에서 손해를 낸다.**

**전수 대조로 얻은 목록은 규칙보다 낫다 — 대신 자라지 않는다.**
그래서 같은 회차에 「목록에 없는 것을 스스로 찾아 알리는」 관측을 함께 넣었다 (미등재 구단 · PR #364).
동명이인 목록에는 아직 그 관측이 없다.
