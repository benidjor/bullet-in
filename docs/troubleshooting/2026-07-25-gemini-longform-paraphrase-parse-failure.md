# Gemini 장문 paraphrase 응답 파싱 실패 반복 (cce02acc · 미해결 · 후속 트랙 이관)

fmkorea 보충 수집 (PR #130) 으로 들어온 The Athletic 장문 기사 1건이 번역 단계에서 회차마다 같은 지점에 실패해 큐에 잔존하는 사례다.
2 회 연속 동일 실패로 일시 오동작이 아닌 구조적 문제로 판정했고, 조치는 후속 트랙으로 이관했다 (2026-07-25 사용자 확정).

## 1. 증상

- 대상 행: `cce02acc…` — "[디 애슬레틱] 아스날 스쿼드 구축, 센터포워드: 훌리안 알바레스 혹은 엘리 주니오르 크루피…" (fmkorea 경유 · 원문 2026-07-17 발행).
- 06:02 · 09:02 KST 회차 (2026-07-25) 에서 연속으로 동일 로그:
  `Gemini 응답 파싱 실패, 스킵 content_hash=cce02acc…`
- `title_ko` 가 NULL 로 남아 매 회차 (하루 8 회) 재시도 → 재실패를 반복한다.
- 429 (rate limit) 아님 — 호출 자체는 성공하고 응답 해석 단계에서 실패한다.

## 2. 동작 배경 (설계 확인)

- The Athletic 은 페이월 소스라 enrich 가 **paraphrase 모드**로 돈다 — 본문 전체 재작성을 요구해 출력이 번역 모드보다 길다.
- `_extract_full` (enrich.py) 은 응답에서 `{…}` JSON 블록을 정규식으로 찾아 4 개 필드 (title_ko · summary_ko · summary3_ko · body_ko) 를 꺼낸다.
  블록 부재 · JSON 파손 · 필드 누락 어느 경우든 행 단위 스킵 후 다음 회차가 재선별한다 (per-row 백오프 없음 · 설계 의도).
- 실패해도 사이트에는 노출되지 않는다 (번역 전 상태 미노출 설계). 피해는 회차당 Gemini 호출 1 회 낭비.

## 3. 진단

- 이 행은 실패 조건이 겹치는 최악 케이스다:
  장문 전술 분석 (딜 속보 대비 김) + 본문이 저장 상한 2,000 자를 꽉 채움 + paraphrase 모드 (본문 전체 재작성).
- 유력 가설 — 출력 JSON 이 `max_output_tokens=8192` 상한에서 절단되면 닫는 중괄호가 사라져 정규식이 매치되지 않는다.
  이 경우 정확히 관측된 로그가 난다.
- 진단 한계 — 파싱 실패 시 응답 원문을 로깅하지 않아, 절단인지 형식 이탈 (키 누락 등) 인지 로그만으로는 구분할 수 없다.

## 4. 상태 · 후속 조치 후보 (미해결)

- 현 트랙에서는 조치하지 않고 후속 트랙으로 이관했다.
- `babab294` (할루시네이션 게이트 반려 반복 — 원문에 없는 구단명 잔존 오탐) 와 같은 "매 회차 실패 큐 잔존" 패턴이므로, 같은 트랙에서 함께 다룬다.
- 조치 후보:
  - 파싱 실패 시 응답 앞부분 (예: 200 자) 을 WARNING 으로 로깅해 절단 · 형식 이탈을 구분 가능하게 (진단성 · 최우선).
  - `max_output_tokens` 증액 또는 장문 건의 입력 본문 축소.
  - 반복 실패 행의 재시도 상한 (무한 재시도 방지).
