# 기사 축만 재분류하면 선수 페이지가 옛 어휘로 남는다 (2026-08-11)

기사 단위 이적 단계 재정의를 적용하면서 겪은 문제다.
DB 값은 전부 의도대로 바뀌었는데 화면 한 곳이 따라오지 않았고, 그 자리에서 같은 기사가 다른 단계로 보였다.
단계 · 배지처럼 두 곳에 저장되는 값을 소급할 때 같은 함정을 피하도록 남긴다.

## 1. 증상

- 소급 재분류로 `articles.transfer_stage` 를 새 체계 (이적 완료 · 무산 신설) 로 바꾸고 재렌더 · 배포까지 마쳤다.
- 목록 · 상세 화면은 기대대로였다 — 사이드바에 이적 완료 37 · 무산 33 이 잡히고 카드에도 새 배지가 붙었다.
- **선수 페이지의 진행 단계 사다리에는 새 단계가 하나도 나오지 않았다.**
소급으로 무산이 된 기사가 여러 건 걸려 있는 선수 페이지인데도 종결 표시 줄이 0이었다.
- 더 나쁜 것은 같은 기사가 자리마다 다르게 보인 것이다.
「비니시우스 주니오르, 레알 마드리드와 재계약 합의」 기사가 목록 카드에서는 무산 배지를 달고, 그 선수의 페이지 사다리에서는 이적 합의 줄로 나왔다.

## 2. 원인 — 단계는 두 곳에 저장된다

- 기사 단위 단계는 `articles.transfer_stage` 이고, 선수 단위 단계는 `article_players.stage` 다.
같은 기사라도 여러 선수가 각기 다른 단계로 다뤄질 수 있어 일부러 나눠 둔 값이다.
- 선수 페이지의 사다리 · 배지는 `article_players.stage` 만 읽는다 (`render.build_player_entries` 가 `page_player_links()` 의 stage 를 쓴다).
- 소급 재분류는 기사 축 두 컬럼만 다시 썼으므로 선수 축은 옛 어휘 8종 그대로 남았다.
새 단계가 없으니 사다리에 나올 수 없고, 옛 값이 그대로 그려져 카드와 어긋난다.

## 3. 규모 (2026-08-11 실측)

| 기사 축 (소급 후) | 선수 축 (옛 값) | 귀속 행 수 |
| --- | --- | --- |
| 이적 완료 | 기타 | 115 |
| 무산 | 기타 | 46 |
| 이적 완료 | 이적 합의 | 42 |
| 이적 완료 | 관심 | 13 |
| 무산 | 관심 | 13 |
| 무산 | 협상 중 | 10 |
| 무산 | 이적 합의 | 7 |
| 이적 완료 | 협상 중 | 3 |
| 무산 | 메디컬 | 1 |

- 기사 축이 신설 단계가 된 기사 중 선수 귀속이 있는 것은 **72건**이다.
- 선수 축이 기타인 귀속 (161행) 은 선수 페이지 목록에서 아예 빠지므로 화면에 어긋남이 드러나지 않는다.
눈에 보이는 어긋남은 나머지 89행이다.

## 4. 판단 — 이번 회차에서는 고치지 않았다

- 선수 축을 맞추려면 `article_players` 재추출이 필요하고 그것은 별도 Gemini 호출 · 별도 승인 사항이다.
- 화면이 깨지는 것이 아니라 한쪽이 낡은 것이라, 급히 되돌릴 이유는 없다고 판단했다.
- 다만 **선수 축에 이적 완료 · 무산이 들어오면 명단 축 낡음 관측 알림 (PR #246) 의 종결 방아쇠가 처음 활성화되므로**, 착수할 때 그 트랙에 고지해 발화 패턴을 함께 본다.
- 처음에는 "지금 어긋난 49행 (기사 축 완료 · 무산 ↔ 선수 축 이적 합의) 이 그 알림의 신호원이라, 선수 축을 맞추면 신호가 사라진다" 고 적었으나 **오판이었다** (병렬 세션 지적 · 코드로 재확인).
`quality.ROSTER_COMPLETION_STAGES` 가 이적 합의 계열과 종결 계열을 함께 담고 있어, 링크 선수의 방아쇠는 어느 쪽 어휘로 와도 똑같이 걸린다.
신호는 사라지는 게 아니라 경로만 옮겨 가고, 오히려 선수 축 자체가 종결을 말하게 되므로 판정 근거가 더 정확해진다.
- 따라서 **그 알림은 선수 축 소급의 순서 제약이 아니다.** 착수 시점은 화면 일관성 · 비용으로만 정한다.

## 5. 재발 방지

- **소급 대상 컬럼을 정할 때 "이 값이 다른 테이블에도 저장되는가" 를 먼저 확인한다.**
단계는 두 곳, 배지 · 축 값도 선수 테이블에 따로 있다.
- **DB 분포만으로 성공을 판정하지 않는다.**
이번에도 분포는 완벽했다 (역전 해소 · 신설 단계 정상 적재).
어긋남은 라이브 선수 페이지를 열어 사다리 줄을 세어 보고서야 드러났다.
- 소급 뒤 검증 목록에 **"같은 기사를 두 자리에서 본다"** 를 넣는다 — 목록 카드의 배지와 선수 페이지 사다리의 라벨이 일치하는지 한 건이라도 대조한다.
- 예고를 남길 때도 어느 축의 이야기인지 밝힌다.
이번에 병렬 세션에 "소급하면 선수 페이지에 종결 줄이 생긴다" 고 예고했다가 정정했다 — 두 축을 구분해야 한다고 스스로 강조해 놓고 예측에서 섞었다.
