# PR 제목을 고쳤는데 main 에는 옛 제목이 남았다 (2026-10-25)

- **영역**: git · PR 컨벤션 (squash merge 제목)
- **관련 PR**: #555 · #556 (옛 제목이 남음) · #557 (커밋 제목을 함께 고쳐 맞음)
- **고친 곳**: `docs/conventions/2026-06-11-commit-pr-convention.md` §1.1 의 틀린 문장 · 이 문서
- **남은 일**: 저장소 설정을 「항상 PR 제목」 으로 바꿀지 (사용자 판단 · §4.2)

## 1. 증상

#555 와 #556 의 제목이 「~게」 로 끝나 문장이 중간에 끊긴 느낌이라는 지적을 받았다.
머지 전에 `gh pr edit` 로 PR 제목을 명사형으로 고쳤다.
그런데 머지 뒤 `main` 의 커밋에는 고치기 전 제목이 남았다.

| PR | 고친 PR 제목 | `main` 에 남은 제목 |
| --- | --- | --- |
| #555 | `fix(glossary): 「외데가르드」 를 통용 표기 「외데고르」 로 교정` | `53f62be fix(glossary): 「외데가르드」 를 통용 표기 「외데고르」 로 바꾸게 (#555)` |
| #556 | `fix(serve): 영입설이 끝난 보관 선수의 기사는 이적 기사일 때만 화면에 표시` | `2dee466 fix(serve): 영입설이 끝난 보관 선수 기사는 이적 단계가 있을 때만 화면에 남기게 (#556)` |

PR 제목을 고칠 때 「squash merge 는 PR 제목을 쓰니 이것으로 된다」 고 안내했다.
확인하지 않고 한 말이었다.

## 2. 원인

이 저장소의 squash merge 제목 기본값은 「커밋이 하나면 커밋 제목, 여럿이면 PR 제목」 이다.

```bash
gh api repos/benidjor/bullet-in --jq '.squash_merge_commit_title'
# COMMIT_OR_PR_TITLE
```

GitHub 의 저장소 설정값 `squash_merge_commit_title` 은 둘 중 하나다.

- **`PR_TITLE`** — 늘 PR 제목을 쓴다.
- **`COMMIT_OR_PR_TITLE`** — 커밋이 하나뿐이면 그 커밋의 제목을, 여럿이면 PR 제목을 쓴다.

#555 와 #556 은 커밋이 하나였다.
그래서 머지 화면에 커밋 제목 (고치기 전) 이 기본값으로 채워졌고 그대로 머지됐다.

컨벤션 §1.1 의 「squash merge 라 PR 제목이 곧 `main` 에 남는 커밋 제목이 됨」 은 커밋이 여럿인 PR 에서만 맞는 문장이었다.
이 저장소에서 머지된 PR 553건 가운데 348건 (63%) 이 커밋 하나라 (2026-10-25 GitHub GraphQL 의 `commits.totalCount`) 그 문장이 틀리는 경우가 더 흔하다.

머지된 PR 전체에서 「PR 제목과 `main` 제목이 다른 PR」 도 세어 봤지만 이 문서의 근거로는 쓰지 않는다.
커밋이 여럿인 PR 에서도 다른 경우가 나왔는데, 머지한 뒤 PR 제목을 바꾼 경우 (예: 제목 규정을 명문화한 #293 무렵) 와 가를 방법이 없었다.

## 3. 해결

#557 에서는 PR 제목과 커밋 제목을 처음부터 같게 했다.
본문을 고칠 때도 `git commit --amend` 로 커밋 하나를 유지하고 `git push --force-with-lease` 로 올렸다.
머지 커밋 `b168382` 의 제목이 PR 제목과 같다.

이미 머지된 #555 · #556 의 `main` 제목은 그대로 둔다.
`main` 의 이력을 다시 쓰는 일이라 얻는 것보다 위험이 크다.

## 4. 예방

### 4.1. 제목을 고칠 때 커밋 수를 먼저 본다

```bash
gh pr view <번호> --json commits -q '.commits | length'
```

- **1 이면** — `gh pr edit --title` 과 함께 커밋 제목도 고친다 (`git commit --amend` 로 제목만 바꾸고 `git push --force-with-lease`).
- **2 이상이면** — PR 제목만 고쳐도 된다.

### 4.2. 저장소 설정을 바꾸는 길

설정을 `PR_TITLE` 로 바꾸면 커밋 수와 관계없이 PR 제목이 기본값이 된다.

- **좋은 점** — PR 제목 하나만 관리하면 된다.
- **아쉬운 점** — 커밋 제목을 공들여 쓴 경우에도 PR 제목이 그 자리를 차지한다 · 저장소 설정이라 사용자가 정할 일이다.

### 4.3. 컨벤션 문장 정정

§1.1 의 문장을 「커밋이 하나면 커밋 제목, 여럿이면 PR 제목이 `main` 에 남는다」 로 고쳤다.

## 5. 배운 것

PR 제목을 고치면 `main` 이 따라 바뀐다고 안내하기 전에, 저장소 설정 한 줄 (`gh api repos/<저장소> --jq '.squash_merge_commit_title'`) 을 확인했어야 했다.
「squash 는 PR 제목을 쓴다」 는 GitHub 의 기본 동작처럼 들리지만 저장소마다 설정이 다르다.
