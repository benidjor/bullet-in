# VM 원격 렌더 · 배포의 조용한 실패 2건 (비대화형 SSH)

언론사 표기 픽스 (#140) 와 기자 "단독" 오파싱 정정 (#141) 을 라이브에 반영하며 겪은 함정 기록이다 (2026-07-26).
두 건 모두 명령이 성공한 것처럼 끝나면서 결과만 어긋나는 유형이라, `ssh ... 'bash -s'` 로 VM 작업을 흘려보낼 때마다 재발할 수 있다.

## 1. uv PATH 부재 — 렌더가 죽었는데 구산출물이 그대로 배포됨

### 증상

- 원격 스크립트에서 `uv run` 이 `command not found` 로 실패했는데, 뒤이은 `./infra/deploy-site.sh` 는 정상 실행됐다.
- 결과: 재생성되지 않은 기존 `site/` 가 그대로 배포됐다 (이번엔 내용 변화가 없어 무해했지만, 검증 grep 이 옛 값을 보여 주는데도 배포가 이어진 것은 우연이었다).

### 원인 · 예방

- 비대화형 SSH 셸은 로그인 프로파일을 읽지 않아 `~/.local/bin` 이 PATH 에 없다.
  systemd 유닛이 절대 경로 (`/home/ubuntu/.local/bin/uv`) 를 쓰는 것과 같은 이유다.
- 예방 ①: 원격 스크립트 서두에 `export PATH="$HOME/.local/bin:$PATH"` 를 고정으로 넣는다.
- 예방 ②: 산출물 grep 검증을 배포 **앞에** 두고, 기대값이 안 나오면 배포까지 가지 않게 구성한다
  (예: `grep -q "<기대값>" site/... && ./infra/deploy-site.sh`).
  검증과 배포를 한 스크립트에 순서만 나열하면, 검증이 실패해도 배포가 실행된다.

## 2. `docker exec -i` 의 stdin 삼킴 — 스크립트 후반이 통째로 증발

### 증상

- `bash -s` 로 흘려보낸 원격 스크립트에서 `docker exec -i ... mariadb -e "..."` 한 줄이 실행된 뒤,
  뒤따르는 echo · 렌더 · 배포 단계가 전부 무실행 · 무출력으로 끝났다.
- 앞 단계 (UPDATE) 는 성공해서, 로그만 보면 "일부만 하고 조용히 멈춘" 상태가 된다.

### 원인 · 예방

- `-i` 는 컨테이너 stdin 을 호출 측 입력 스트림에 연결한다.
  `bash -s` 실행 중에는 그 스트림이 **남은 스크립트 본문**이라, `-e` 로 입력이 필요 없는 명령인데도 이후 줄들을 stdin 으로 소비해 버린다.
- 예방: `-e` 단문 실행에는 `-i` 를 붙이지 않는다.
  stdin 이 실제로 필요한 경우 (heredoc `<<'SQL'`) 에만 `-i` 를 쓰고, heredoc 으로 소비 범위를 명시한다.
- 기존 런북 스니펫이 전부 heredoc 형인 것은 이 함정을 이미 피해 간 형태다 — heredoc 없이 `-i` 만 옮겨 쓰면 재발한다.
