# 슬라이드가 넘친 원인은 문장이 아니라 CSS 였다 — 그리드 비율, 상자 여백, 규칙 순서 (2026-09-09)

- **영역**: 문서 / 슬라이드 조립 (저장소 밖 소개 자료 · `v9_build`)
- **관련 산출물**: 프로젝트 소개 슬라이드 41장 (HTML) · 조립 도구 `build_v9.py` · 측정 도구 `shoot.py` · `cols.py`
- **관련 안건**: 없음 (작업 규율)

## 배경

2026-09-09 새벽에 사용자 통독을 세 차례 받으며 소개 슬라이드 4 ~ 20장의 문장을 전부 다시 썼다.
문장을 고칠 때마다 `shoot.py` 가 몇 px 씩 넘침을 보고했고, 처음에는 문장을 줄여 맞췄다.
그런데 문장을 줄여도 같은 값이 그대로 남는 장이 셋 있었다.
원인은 세 번 다 문장이 아니라 CSS 였다.

## 증상과 원인

### 1. 요약 띠와 본문의 오른쪽 끝이 24px 어긋났다

사용자가 「요약 띠가 아래 코드 블록과 안 맞는다」 고 짚었다.
재 보니 띠는 1232px 에서 끝나고 본문은 1256px 까지 갔다.
본문 그리드가 두 열을 `53% 47%` 로 잡고 그 사이에 `gap:24px` 를 더해서, 합이 컨테이너보다 24px 넓었다.
v8 부터 열네 장에 같은 값이 있었고 아무도 눈치채지 못했다.
`minmax(0,53fr) minmax(0,47fr)` 로 바꾸니 열네 장 전부 1232 에서 끝났고 새 넘침은 없었다.

### 2. 문장을 줄여도 9px 가 그대로였다

18장 (대시보드) 이 9px 넘쳤다.
문장 둘을 한 줄로 줄이고 다시 재도 9px 였다.
열별 바닥을 재는 `cols.py` 를 만들어 보니 왼쪽 열 내용은 705 에서 끝나는데 열 바닥은 715 였다.
지표 상자 묶음 `.metrics` 에 `margin:10px 0` 이 있어 아래 여백 10px 이 열을 밀고 있었다.
앞선 장에서 몇 px 씩 남던 넘침도 같은 뿌리였다.
bullet-in 장 공통 규칙으로 `.metrics{margin-bottom:0}` 을 두어 한 번에 풀었다.

### 3. 공통 규칙을 넣었는데 한 장만 적용되지 않았다

하위 항목 앞 표식을 「→」 로 통일하는 규칙을 스타일 블록에 추가했다.
그런데 13장 (당시 12장) 의 번호 항목 ① ② 만 한 단 더 들여져 있었다.
그 장은 `roomy` 변형이라 `.slide.roomy .ul-list li.sub{padding-left:28px}` 규칙이 뒤에 있었고, 같은 우선순위에서는 뒤에 온 규칙이 이긴다.
내 규칙을 스타일 블록 맨 끝으로 옮기니 풀렸다.

## 배운 것

- 넘침 값이 문장을 줄여도 그대로면 문장이 아니라 여백 · 비율 · 규칙 순서를 의심한다.
- 슬라이드 전체 넘침 (`scrollHeight`) 만 재면 어느 열 · 어느 요소가 밀었는지 모른다.
  열별 바닥과 자식의 바닥을 같이 찍는 도구 (`cols.py`) 가 있어야 원인이 한 번에 보인다.
- 「빈칸」 을 재는 도구 (`fill.py`) 는 아래 여백을 24px 로 가정한 공식을 쓰므로, 여백을 14px 로 줄인 장에서는 음수가 나와도 실제 잘림이 아니다.
  잘림 판정은 `shoot.py` 의 `scrollHeight` 만 믿는다.
- 공통 규칙은 변형 클래스 (`roomy` 등) 의 규칙보다 뒤에 둔다.
