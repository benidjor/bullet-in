# 덱은 「공신력 순 정렬」 이라 했고 스펙은 「정렬은 넣지 않는다」 고 했다 (2026-09-18)

- **영역**: 소개 자료 / 문서 정합
- **앞선 회차**: `2026-09-15-drawing-one-architecture-diagram-found-four-mismatches.md` · `2026-09-17-three-deck-sentences-disagreed-with-code-and-two-numbers-had-no-method.md`

소개 자료 4 ~ 13장을 처음으로 전부 다시 검토한 회차다.
검토 질문에 코드로 답하는 규칙을 지키다 보니, 문장이 코드 · 스펙 · 설정과 어긋난 자리가 다섯 나왔다.
전부 「말이 되는 문장」 이라 읽어서는 못 잡는 것들이었다.

## 1. 「공신력 순 정렬」 은 스펙이 기각한 안이다

4장 헤더에 「3시간마다 병렬 수집 → 공신력 순 정렬 → LLM 번역 · 요약」, 5장 본문에 「기사마다 등급이 붙어 공신력 순으로 정렬」 이 있었다.
5장을 두 장으로 가르는 목업을 만들며 공신력이 화면에서 무엇을 하는지 스펙을 열었다.

`docs/superpowers/specs/2026-07-21-credibility-hierarchy-event-clustering-design.md` §3 은 **「공신력 순 정렬은 넣지 않는다」** 고 결정했다.
등급 순으로 세워 봐도 실데이터 날짜 그룹 넷에서 순서가 달라지는 곳이 0개였기 때문이다.
`src/bullet_in/serve/render.py` 의 정렬 키도 시각 (`_sort_ts`) 뿐이다.
공신력이 하는 일은 등급별 표시 (구단 공식 · 최상은 배경, tier 3 · 4 는 요약문 생략) · 필터 (`?tier=`) · 가십 분리 셋이다.

4장은 「공신력 등급 부여」 로, 새 6장은 「등급별 화면 표시 · 필터 · 가십 분리」 로 고쳤다.
`credibility.py` 로 확인한 것도 하나 넣었다.
명단에 없는 기자는 이름만 표시하고 등급은 소스 등급을 유지한다 (등재 기자가 소속과 일치할 때만 승격).

## 2. 「활성 9」 는 플래그 값이었고 수집은 8종이다

5장 「소스 10종 (활성 9)」 의 9 는 `config/sources.yaml` 에서 `enabled: true` 인 수다.
그런데 Goal 은 `enabled: true` 이면서 `collect: false` 다 (08-15 수집 중단 · 공신력 최하 · 주역 귀속 쌍의 72% 가 타 소스와 중복).
`enabled` 를 끄면 이미 적재된 171건의 매체 이름 · 등급 · 서빙 범위가 함께 사라져 켜 둔 것이다.
읽는 사람 기준의 「지금 수집하는 소스」 는 8이라 「소스 10종 (수집 8)」 로 고쳤다.
Goal 의 마지막 원본 수집은 08-14 다.

## 3. 「Dedup Rate 98%」 와 「중복 적재율 0%」 는 반대가 아니다

7장 오른쪽 수집 현황 대시보드 캡처의 둘째 타일 「Dedup Rate 98%」 가 왼쪽 표의 SLO-3 「중복 적재율 0%」 와 나란히 보여 되물음이 나왔다.
`src/bullet_in/serve/ops_view.py` 기준으로 Dedup Rate 는 「중복 차단 ÷ (신규 + 중복)」, 곧 가져온 후보 중 이미 있는 기사라 걸러진 비율이다.
3시간마다 같은 목록을 다시 읽으니 90% 대가 정상이다.
SLO-3 은 dbt `unique` 테스트로 재는 「저장된 표에 남은 중복」 이다.
「98% 를 걸러서 0% 가 남았다」 는 앞뒤 관계라, 캡션에 한 줄을 넣었다.

## 4. 「3회 관측」 은 2주 전 값이었다

12장 「비결정적 세그폴트, 3회 관측」 을 확인하려 VM 을 봤더니 덤프 넷과 재시도 로그 넷이 있었다.

13장의 303시간을 확인하려 `source_freshness` 와 `raw_items` 를 대조했다.
경위는 [`2026-09-18-a-stored-row-yardstick-misread-a-live-source.md`](2026-09-18-a-stored-row-yardstick-misread-a-live-source.md) 에 있다.

## 6. 표지 숫자에서 밟은 것

표지 상자 셋을 「데이터 엔지니어의 역량을 보여 주는 수」 로 다시 고르다 잣대 둘이 나왔다.

- **결과값과 입력값** — 「dbt 테스트 21종」 은 만든 것의 수 (입력) 고 「중복 적재율 0%」 가 결과다.
  큰 숫자는 결과값으로 두고 21종은 설명 줄로 내렸다.
- **절감과 대안 비용** — 18장의 「매니지드 Iceberg 테이블 월 약 12만원」 은 낸 적도 아낀 적도 없는 돈이다.
  설계 시점에 고려한 대안의 예상 비용이라 「월 12만원 절감」 이라 쓰면 거짓이 된다.
  큰 숫자는 관측값 「0원」 으로, 12만원은 「(예상) 대신」 으로 설명 줄에만 두었다.

## 7. 교훈

- **문장이 자연스러울수록 코드를 연다.**
  「공신력 순 정렬」 은 누구도 의심하지 않을 문장이었고, 스펙이 기각한 안이었다.
- **플래그 값과 사실은 다르다.**
  `enabled` 9 는 설정의 진실이고 「수집 8」 이 읽는 사람의 진실이다.
- **관측값 · 예상값 · 대안값을 같은 자리에 두지 않는다.**
  0원은 관측, 12만원은 대안의 예상, 21종은 입력이다.
