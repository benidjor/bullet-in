# 조율로 확정한 계약도 실측에 걸어 봐야 한다 (2026-07-30)

본문 출처 등급 가드 (PR #156) 의 계약은 두 세션이 여러 차례 오가며 확정한 것이었고, 착수 지시에도 "재협의 불요" 로 적혀 있었다.
정규식과 시험 사례까지 계약에 들어 있어 그대로 옮겨 적으면 끝날 것처럼 보였다.

그런데 구현 전에 계약을 실제 데이터와 실제 자료 구조에 걸어 보니 결함이 둘 나왔다.
둘 다 그대로 구현했다면 조용히 잘못된 값을 쓰거나 회차가 죽었을 것이다.

## 사례 1 — 정규식이 개행을 넘어 다음 줄 단어를 이름으로 삼는다

계약의 기자명 추출 규칙은 이름 토큰 사이를 `\s+` 로 이었다.
로컬 배포판 사본 (`bulletin_mock` · 2026-07-27 · fmkorea 본문 98건) 에 그대로 돌려 보니 19건이 추출됐고 그중 두 건이 이렇게 나왔다.

```
7b0411c1  '메일'        계약 원안 = 'JAMES SHARPE\n\nPublished'   구현본 = 'JAMES SHARPE'
ee4d5d0e  '데일리 메일'   계약 원안 = 'SIMON JONES\n\nPublished'    구현본 = 'SIMON JONES'
```

건수 정정 — PR #156 본문에는 이것을 3건으로 적었으나 실측은 2건이다.
문서를 쓰면서 같은 쿼리를 다시 돌려 확인했다.

`\s+` 는 개행을 포함하므로 바이라인 다음 줄의 `Published` 가 이름에 붙었다.
데일리 메일 계열은 바이라인 다음 줄에 `Published: 17:30 GMT, 20 July 2026` 이 따라온다.

- **왜 계약 단계에서 안 잡혔는가** — 계약에 붙어 있던 시험 사례 7개가 전부 한 줄짜리였다.
개행이 있는 형식은 표본에 없었다.
- **처리** — 토큰 사이 구분자를 공백만 (`[ ]+`) 으로 좁혔다.
월 이름과 `Updated` 는 이름 토큰에서 배제해 뒤따르는 날짜에서 끊는다.
- **왜 위험했는가** — 엉뚱한 이름이 `journalist` 에 들어가면 등급 산출이 그 이름을 별칭으로 훑는다.
계약대로 구현하면 계약이 막으려던 것 (등급 오상승) 이 오히려 일어나는 구조였다.

## 사례 2 — 별칭 목록에는 공백 변종이 의도적으로 들어 있다

계약은 "기자 별칭 조회의 공백 정규화" 를 요구했다.
가장 단순한 구현은 사전 키를 정규화 형태로 **교체**하는 것인데, 이렇게 하면 `load_registry` 가 시작부터 죽는다.

```
ValueError: duplicate alias: 드로셰
```

`config/credibility.yaml` 의 별칭 목록에 표기 변종이 나란히 들어 있기 때문이다.

| 항목 | 별칭 | 정규화 후 |
| --- | --- | --- |
| Art de Roché | `드 로셰` · `드로셰` | 둘 다 `드로셰` |
| Foot Mercato | `Foot Mercato` · `footmercato` | 둘 다 `footmercato` |

`_build` 는 서로 다른 항목이 같은 별칭을 쓰는 것을 오류로 잡는다 (`Jacob` · `Jacobs` 부분 매칭 함정 때문에 넣은 검사다).
키를 정규화 형태로 바꾸면 **같은 항목 안의 변종** 이 그 검사에 걸린다.

- **처리** — 교체가 아니라 덧붙이기로 갔다.
`Registry.__init__` 이 공백 무시 키를 `setdefault` 로 더하고, 조회 쪽이 `norm_alias` 를 쓴다.
원 별칭 키가 남으므로 기존 조회와 중복 검사가 그대로 동작한다.
- **함께 확인한 것** — 이 변경으로 지금 새로 매칭되는 행은 0건이다 (사본의 `journalist` 값 93종 대조).
표기가 흔들릴 때 열리는 경로를 미리 닫은 것이지, 지금 깨진 것을 고친 것이 아니다.

## 사례 3 (문서 쪽) — 계획서에 적은 코드 참조가 실물과 달랐다

같은 세션에서 번역 신뢰성 계획서 (PR #157) 를 쓰면서, 기억으로 적은 코드 참조 둘이 실물과 어긋났다.

| 계획서 초안 | 실물 |
| --- | --- |
| `render_detail(row, [], sources, now)` | `render_article(article, neighbors, current_hash, sources, now)` |
| `build_fmkorea_adapter(pages=..., exclude_titles=...)` | `build_fmkorea_adapter(cfg, proxy, *, pages=..., exclude_titles=...)` |

저장 전에 `grep -n "def render_detail"` · `grep -n "def build_fmkorea_adapter" -A12` 로 대조해 고쳤다.
계획서는 다음 세션이 그대로 실행하는 문서라, 여기서 어긋나면 구현자가 없는 함수를 찾게 된다.

## 예방

- **순수 함수 · 규칙은 구현 전에 배포판 사본에 읽기 전용으로 걸어 본다.**
절차는 `docs/runbook/2026-07-30-column-backfill-preflight.md` 1절에 있다.
계약의 시험 사례는 그 결과에서 뽑는다.
- **정규식은 실제 문자열 형태를 보고 고른다** — 개행 · 전각 공백 · 연속 공백이 표본에 있는지 확인한다.
한 줄 예시만으로 만든 정규식은 개행에서 깨진다.
- **기존 자료 구조에 규칙을 얹을 때는 그 구조가 이미 무엇을 전제하고 있는지 읽는다.**
별칭 목록의 변종은 실수가 아니라 의도였다.
- **문서에 적은 코드 참조는 저장 전에 `grep` 으로 대조한다** — 함수명 · 인자 순서 · 상수 위치.
