# 「저자 미상」 은 원본에 저자가 없다는 뜻이 아니었다 (2026-08-15)

공저자 다중 귀속을 배포한 뒤 기자 필터로 도달되지 않는 기사가 159건 남았다.
그 묶음을 「원본에 저자가 없는 기사」 로 보고했는데 **틀렸다.**
사용자가 목록을 받아 원문을 직접 열어 보니 저자가 있었고, 우리 추출의 사각지대가 셋 드러났다.

관련 = `2026-07-16-json-ld-author-extraction-traps.md` (파서가 규격을 못 읽는 계열) · 잔여 안건 메모리의 안건 y.

---

## 1. 무엇을 잘못 말했나

`authors_json` 이 비어 있는 행을 「저자 미상」 으로 불렀고, 그 라벨을 **사실처럼** 보고했다.

- 근거로 든 것은 「수집 시점 원본의 구조화 정보에 `author` 키가 없었다」 하나였다.
- 그것이 증명하는 것은 **우리가 읽는 자리에 없었다**이지 **원문에 없다**가 아니다.
- 사용자가 「웬만한 기사에는 저자가 함께 표시되지 않나」 로 되물었고 그 반문이 맞았다.

**우리 파이프라인의 상태 이름 (미상 · 미기입 · 잔존) 은 데이터가 어떻다는 말이 아니라 우리 처리가 어떻다는 말이다.**
보고할 때 그 둘을 구분하지 않으면, 고칠 수 있는 결함이 데이터의 한계로 굳는다.

## 2. 드러난 사각지대 셋

원문을 직접 대조하니 세 가지가 나왔다.

### 2.1 원문 페이지를 받아 놓고 저자만 안 읽는다

fmkorea 어댑터는 원문에 접속해 대표 이미지 · 본문 이미지 · 발행 시각을 뽑는데 `extract_authors` 를 부르지 않는다.

```python
image  = extract_og_image(ro.text)
images = extract_body_images(ro.text, base_url=orig)
pub    = extract_published_at(ro.text)
# extract_authors(ro.text) 가 없다
```

같은 함수가 다른 소스에서는 잘 돌고 있어서 함수의 결함이 아니라 **호출이 빠진 자리**였다.
실물 = BBC `cwy42yqwk30o` (Sami Mokbel) · AS `pubill-f202608-n` (Jorge García Hernández).

### 2.2 원문 본문을 채택하는 순간 게시글의 바이라인을 버린다

전재글은 원문 접속에 성공하면 본문을 원문 것으로 **교체**한다.
그때 게시글에 있던 「글: 로리 휘트웰, 베렌 크로스」 같은 표기가 함께 사라지고 바이라인을 찾는 코드는 교체된 뒤의 영문 본문만 본다.

**재료를 버리는 시점과 그 재료를 쓰는 시점이 어긋나 있었다.**
읽는 쪽을 고쳐도 안 되고 **버리기 전에 읽어 두어야** 한다.

### 2.3 바이라인 정규식이 한글 이름을 못 읽는다 — 이것만 오프라인으로 회수됐다

게시자가 저자를 한글로 번역해 적은 글이 있는데 정규식이 영문 대문자로 시작하는 이름만 찾았다.
**재료는 이미 저장돼 있어서 규칙만 넓히자 9건이 되살아났다** (외부 접속 0 · 과금 0).

## 3. 한글 바이라인의 경계 판정

한글에는 대소문자가 없어 **이름이 어디서 끝나는지 알 수 없다.**
영문은 대문자로 시작하는 토큰만 이어 붙이면 되지만 한글은 그 신호가 없다.

**쉼표로 쪼개 오른쪽 끝을 경계로 쓰면 무너진다** — 본문에도 쉼표가 있기 때문이다.

```
By 데이비드 온스테인 크리센시오 서머빌이 … 체결했으며, 이적료는 7,000만 유로다.
→ ['데이비드 온스테인 크리센시오 …', '이적료는 7', '000만 유로다']
```

**되는 규칙은 왼쪽부터 읽는 것이다.**

- 쉼표로 쪼갠 뒤 앞에서부터 본다.
- 이름만 있는 조각 (한두 어절 · 짧음 · 숫자 없음 · 종결어미 없음) 은 그대로 저자로 쓴다.
- **본문이 붙기 시작한 조각에서 멈추되 그 조각의 앞 두 어절을 마지막 저자로 본다** — 음역된 서양 이름이 일관되게 두 어절이다.

실측 11건 전건에서 오검출이 없었고 사용자가 원문에서 확인한 이름과 글자까지 일치했다.

**정규식을 더 넓히는 쪽으로 가지 않았다.**
새 오검출이 나오면 문구를 넓히지 말고 「등재 기자만 채택」 으로 좁힌다 (공저 귀속 설계 §2.2).

## 4. 다음에 쓸 절차

**「미상」 을 보고하기 전에 원문을 표본으로 열어 본다.**
우리가 읽는 자리 (구조화 정보 · 저장된 본문) 에 없다는 것만으로 「원본에 없다」 고 쓰지 않는다.

**분류는 「왜 못 읽었나」 로 한다.**
그러면 각 묶음에 회수 경로가 붙고 「불가」 로 묶여 조사가 끝나 버리는 일이 없다.

| 재료 | 회수 경로 |
| --- | --- |
| 원문 본문을 갖고 있다 | 원문 재접속 후 구조화 저자 · 게시글 바이라인 |
| 원문 접속에 실패했다 | 재접속 재시도 (당시 실패가 일시적일 수 있다) |
| 구조화 정보에 저자가 없다 | 화면 바이라인 폴백 |
| 게시글 본문만 있고 바이라인이 없다 | 남은 경로 없음 |

**「불가」 라고 쓸 때는 무엇을 확인했는지 함께 적는다.**
이번에 86건을 불가로 묶었다가 근거를 다시 보니 그중 둘은 아직 써 보지 않은 경로였다 — 재접속 재시도와 화면 바이라인이다.
그중 재접속 대상 58건에서 페이월은 30건이고 나머지 28건은 접근 가능한 매체였다.

## 5. 같은 함정을 한 번 더 밟았다 — 표지 목록으로 세면 목록 밖은 0 으로 나온다 (2026-08-19)

회수 회차에서 「저장된 본문에 아직 못 읽은 바이라인이 남아 있나」 를 셌다.
`By` · `글:` · `기자:` 같은 표지 여섯 개를 목록으로 만들어 훑었고 **미상 행에서 0건**이 나왔다.
그래서 「저장된 재료로는 더 얻을 것이 없다」 고 보고했는데 틀렸다.

사용자가 「fmkorea 기사 중 저자를 못 찾은 것이 많지 않았나」 로 되물었고, 본문 앞머리를 그냥 눈으로 훑으니 바로 나왔다.

```
(데이비드 온스테인, 제이콥 탠스웰) 알 힐랄이 아스톤 빌라의 공격수에게…
The Athletic-데이비드 온스테인 맨체스터 유나이티드는…
플로리안 플라텐버그: 바이어 레버쿠젠은 현재 아스날의…
```

실제로 게시자들이 더 자주 쓰는 형태가 셋이었고 전부 내 목록에 없었다.
규칙을 넓히자 **11건**이 되살아났다 (외부 접속 0 · 과금 0 · 이미 저자가 있던 행의 값 변화 0).

### 5.1. 왜 검사가 통과했나

**찾을 줄 아는 형태를 세는 검사는 모르는 형태를 「없음」 으로 낸다.**
0 이 나온 것이 데이터에 없다는 뜻인지 내 목록이 좁다는 뜻인지 그 검사로는 구분되지 않는다.

**같은 축의 다른 사례가 있다** — 세는 **패턴**이 좁아서 못 보는 것이 이 문서이고,
세는 **층**이 위여서 이미 가공된 값을 보는 것이 `2026-08-20-rendered-values-are-not-raw-data.md` 다.
둘 다 「무엇을 세고 있는지」 를 안 밝히면 0 과 「내가 못 봤다」 가 구분되지 않는다.
「없음」 을 확인하는 검사가 아예 안 돌아도 「없음」 을 내는 것과 같은 계열이다 (`2026-08-14-verification-that-silently-passes.md`).

§1 에서 「우리가 읽는 자리에 없다」 를 「원문에 없다」 로 쓴 것과 뿌리가 같다.
그때는 **읽는 자리**가 좁았고 이번에는 **찾는 형태**가 좁았다.
둘 다 내 처리의 한계를 데이터의 사실로 옮겨 적었다.

### 5.2. 다음에 쓸 절차

**「없다」 를 보고하기 전에 목록을 안 쓰는 방법으로 한 번 더 본다.**
표본 몇 건의 원문을 그대로 찍어 눈으로 읽는 정도면 충분하다.
이번에는 미상 행의 본문 앞머리 150자를 전건 출력해 훑는 데 1분이 걸렸고, 그 1분이 11건을 살렸다.

**형태를 넓힐 때는 경계가 있는 것과 없는 것을 갈라 다룬다.**
괄호 · 콜론 · 하이픈은 이름의 끝을 알려 주므로 감싼 조각이 **전부** 이름 모양이어야 채택한다.
하나라도 어긋나면 통째로 버려야 괄호 안 편집자 주 (`(이 기사는 원래 6월 26일에 게재됐으며…)`) 와 포메이션 표기 (`(4-2-3-1)`) 가 이름으로 안 샌다.
`By` 처럼 끝을 모르는 표지는 §3 의 왼쪽부터 읽는 규칙을 그대로 쓴다.

**넓힌 규칙은 저장된 전건에 대 보고 두 방향을 함께 센다.**
새로 얻는 건수만 보면 기존 값이 흔들리는 것을 못 본다.
이번에는 전재글 231행에 대어 새로 얻는 것 11 · 기존 값 변화 0 을 함께 확인했다.
그 대조에서 처음에 9건이 「값이 달라짐」 으로 나왔는데 **저장값은 말머리 기자를 앞에 붙인 목록**이라 내 비교 대상이 틀렸다 — 잣대를 맞추자 0 이 됐다.
