# 세션 메모리에서 옮긴 수치가 저장소와 어긋났다 (2026-09-06)

- **영역**: 문서 / 검증
- **관련 산출물**: 저장소 밖 프로젝트 소개 자료 (슬라이드 · 이 저장소의 사실을 옮겨 적는 문서)
- **관련 안건**: 없음 (작업 규율)

## 증상

저장소를 소개하는 슬라이드 초안을 만들고 두 번 읽었는데, 모델을 바꿔 다시 검토하니 사실 오류가 일곱 나왔다.
전부 「그럴듯한 값」 이라 읽는 동안에는 걸리지 않았고, 저장소를 열어 대 봐야 드러나는 종류였다.

| 슬라이드에 적힌 것 | 어디서 왔나 | 실제 |
| --- | --- | --- |
| 「중복 병합 920 → 909 · 묶음 11 → 0」 | 세션 메모리의 한 줄 | 저장소 문서 어디에도 없다. 런북에 있는 것은 「병합 17묶음 · 신원 이전 107행 · 8행」 이다 |
| 「실제로 값이 잘못 바뀐 사고를 겪고도 되짚지 못했다」 | 쓰면서 지어낸 동기 | 레이크하우스 스펙의 동기에 그런 사고가 없다 |
| 「주기를 좁히면 비용이 8배」 | 근거 없는 수 | 없다 |
| 게이트 코드 발췌 `_rewrite_once` · `_gate` · `_feedback_for` | 그럴듯하게 쓴 의사 코드 | `enrich.py` 에 없는 함수다. 실제는 `MISSING_RETRY` 같은 사유 프롬프트를 이어 붙인다 |
| `src/bullet_in/store.py` | 짐작한 경로 | `src/bullet_in/storage/mariadb.py:92` |
| 「18.5% 를 게이트가 차단」 | 코드 주석을 반대로 읽음 | 게이트 3회 **뒤에도** 남은 잔존율이고, 그래서 재큐를 붙인 근거다 |
| 「공개 이후 롤백 오경보 0」 | 범위를 안 잼 | 배포 자동화는 09-03 가동이다. 실측은 판정 18회 · 롤백 0 |

## 원인

**세션 메모리에 적힌 문장을 저장소로 대 보지 않고 옮겼다.**
메모리는 세션이 자기 편의로 적은 요약이라 낡거나 틀린 값이 섞여 있고, 그건 이미 알고 있던 사실이다 (`2026-09-01` 에 메모리의 틀린 값 둘을 발견한 기록이 있다).
그런데도 슬라이드를 쓸 때는 메모리를 관측처럼 취급했다.

코드 발췌와 경로는 더 나쁘다.
「이런 모양일 것이다」 로 쓴 의사 코드에 실제 파일 이름을 라벨로 붙이면, 읽는 사람은 그 파일을 여는 순간 참인 주장까지 함께 의심한다.

같은 모델이 두 번 읽고도 못 본 것은 우연이 아니다.
초안을 쓴 눈은 자기가 지은 문장을 「아는 것」 으로 읽는다.

## 처방

- **저장소 밖 문서에 넣는 모든 수치는 저장소 문서나 같은 날 실측에 닿아야 한다.**
메모리에만 있는 값은 문서에서 다시 찾고, 없으면 쓰지 않는다.
- **코드 발췌는 실제 파일에서 복사한다.**
함수명 · 경로는 짓지 않고 `grep` 으로 존재를 확인한다.
- **리뷰 잣대는 「맞는 말인가」 가 아니라 「읽는 사람이 저장소를 열면 확인되는가」 다.**
- **검토는 다른 모델 · 다른 세션으로 한다.**
같은 눈은 같은 것을 놓친다.
- 문체 점검은 문장만 보고 사실은 보지 않는다.
사실 검토는 별개의 단계다.

## 교훈

- 메모리는 관측이 아니다.
