# 도구가 버린 입력을 「없다」 로 보고한 네 자리 (2026-10-08)

- **영역**: 작업 절차 (대화 기록 조사 · 문장 짝짓기 · 검사 훅 시험 · 문서 집계)
- **관련 안건**: 없음 (작업 방식)
- **고친 것**: 작업 메모의 잘못된 결론 정정 · 이 문서
- **남은 일**: 없음

## 1. 증상

한 세션에서 네 번, 내가 만든 도구의 결과를 그대로 「없다 · 특정할 수 없다 · 작동하지 않는다」 로 보고했다.
네 번 모두 사용자가 되묻거나 내가 한 단계 더 들여다보자 결론이 뒤집혔다.

| 보고 | 실제 |
| --- | --- |
| 사용자가 붙여넣기로 지적한 README 문장은 원문을 특정할 수 없다 | 대화 기록에 54개 문장이 그대로 있었다 |
| README 지적 가운데 3개는 반영 결과와 짝을 못 찾았다 | 3개 모두 #496 에서 고쳐져 있었다 |
| MEMORY.md 줄 길이 경고 훅이 울리지 않는다 · 세션이 설정을 다시 읽지 않은 탓이다 | 훅은 정상이었고 시험 줄이 정확히 150자였다 |
| 계획서의 작업 원칙 줄이 7월 이후 끊겼다 | 「Karpathy」 낱말로만 셌다 · 원칙 이름 「수술적 변경」 은 그 뒤 계획서 6개에 있었다 |

## 2. 원인

네 자리 모두 도구가 입력의 일부를 버렸고 나는 버린 것을 적지 않은 채 결과를 옮겼다.

### 2.1 추출 단계가 입력을 잘랐다

대화 기록 (`*.jsonl`) 에서 사용자 발화를 뽑는 스크립트가 붙여넣기 블록 (`<pasted_content>`) 을 「[붙여넣기]」 로 바꿨다.
사용자가 직접 쓴 문장만 보려던 선택이었다.
그 결과를 받은 조사 에이전트에게는 「1. [붙여넣기] 2. [붙여넣기]」 처럼 지적 대상이 빠진 발화만 보였다.
에이전트는 「특정 불가」 로 보고했고 나는 그 말을 그대로 전했다.
원문을 되살리는 데는 정규식 한 줄이면 충분했다.

### 2.2 문자열 유사도는 짧은 조각을 짝짓지 못한다

지적 전 문장과 반영 뒤 문장을 `difflib.SequenceMatcher` 비율로 짝지었다.
이 비율은 두 문자열 전체 길이 대비 겹친 정도라서 몇 낱말짜리 조각 (「아스날 소식을 챙기려면」) 을 긴 문장과 짝지으면 점수가 낮게 나온다.
고친 뒤에는 바로 그 낱말이 바뀌어 (챙기려면 → 확인하려면) 겹치는 글자가 거의 남지 않았다.

지적 대상이 git 에 없는 초안이었다는 점도 겹쳤다.
그 문장은 같은 세션이 README 를 통째로 다시 쓴 파일 쓰기 (Write) 안에만 있었다.
키워드로 찾으니 세 조각 모두 #496 에서 고쳐진 문장이 바로 나왔다.

### 2.3 시험 입력이 경계 위에 있었다

MEMORY.md 줄 길이 훅은 「150자를 넘는 줄」 에 경고한다.
시험용으로 넣은 줄이 정확히 150자여서 처음부터 경고 대상이 아니었다.
경고가 안 뜨자 원인을 설정 재로딩에서 찾았고 같은 줄로 두 번 더 시험했다.
스크립트에 실행 기록을 남기게 하자 훅은 매번 불리고 있었고 183자 줄에서는 경고가 떴다.

### 2.4 낱말 하나로 센 값에 넓은 이름을 붙였다

계획서 64개를 `karpathy` 로 grep 하니 6개만 걸렸는데, 나는 그 결과를 「원칙 줄이 7월 이후 끊겼다」 로 말했다.
원칙 이름으로 다시 세자 07-20 의 둘은 제약 줄로, 07-26 · 08-01 · 08-07 · 09-05 는 본문에 「수술적 변경」 을 적어 두었다.
끊긴 것은 「네 원칙을 한꺼번에 적은 머리 줄」 뿐이었다.

## 3. 공통점

| 자리 | 도구가 버린 것 | 되살리는 비용 |
| --- | --- | --- |
| 추출 | 붙여넣기 블록 | 정규식 한 줄 |
| 짝짓기 | 짧은 조각 · git 밖의 초안 | 키워드 grep · 대화 기록의 Write 내용 |
| 시험 | 경계값 바로 위 | 시험 줄 길이를 한 번 재기 |
| 집계 | 같은 원칙의 다른 이름 | grep 패턴 하나 더 |

「없다」 는 대상을 두고 하는 말인데, 실제로 확인한 것은 「이 도구로는 안 보였다」 뿐이었다.
넷 다 되살리는 비용이 명령 하나였다.

## 4. 이렇게 한다

- 「없다 · 특정 불가 · 안 된다」 를 보고하기 전에, 그 도구가 버린 입력을 한 줄로 적는다.
- 버린 것을 되살리는 비용이 명령 하나면 되살려서 다시 본다.
- 짧은 조각을 짝지을 때는 유사도 대신 키워드로 찾는다.
- 사용자가 본 글이 커밋 전 초안일 수 있으니, 지적 전 문장은 대화 기록의 파일 쓰기 내용에서 꺼낸다.
- 경계 조건이 있는 검사는 경계 바로 위 · 아래 입력을 함께 넣고, 시험 입력의 길이 · 값을 먼저 잰다.
- 장치가 안 움직이면 ① 불리는가 (실행 기록) ② 같은 입력으로 손으로 돌리면 어떤가 ③ 시험 입력이 조건에 맞는가 를 나눠 본다.
  가장 싼 것은 ③ 이다.
- 낱말로 센 개수에는 「이 낱말로 센 값」 이라는 단서를 붙인다.
