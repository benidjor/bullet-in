# 명단의 성 하나가 서빙 두 층으로 새어 든다 — 동명이인 (2026-08-31)

사용자가 홈에서 「베네치아, 주앙 제주스와 구두 합의… 내일 계약 체결 예정」 이 가브리엘 제주스 묶음 안에 있는 것을 발견했다.
주앙 제주스는 우리와 무관한 FA 수비수다.

고치고 보니 **같은 뿌리가 두 곳에서 오작동하고 있었고**, 한 곳만 고치자 증상이 더 잘 보이는 자리로 옮겨 갔다.

## 1. 뿌리 — 명단 표기가 대부분 성이다

선수 사전은 97개 중 87개가 성만 담고, 매치는 부분 문자열이다.
같은 성을 쓰는 다른 사람이 제목에 나오면 그 기사가 우리 선수의 것으로 읽힌다.

「제주스」 하나로 세 사람이 걸렸다.

| 사람 | 정체 | 우리 것인가 |
| --- | --- | --- |
| 가브리엘 제주스 | 아스날 공격수 | ⭕ |
| 주앙 제주스 | 베네치아로 간 FA 수비수 | ❌ |
| 조르제 제주스 | 포르투갈 대표팀 감독 | ❌ |

## 2. 그 사실을 쓰는 곳이 둘이었다

「제목에 나오는 남의 이름」 은 도메인 사실인데, 그것을 쓰는 층이 둘이고 마스킹은 한 곳에만 있었다.

| 층 | 하는 일 | 마스킹 |
| --- | --- | --- |
| `render.protagonist` | 사건 묶음의 주인공 판정 | 있었음 (`_NOT_OUR_PLAYERS`) |
| `run._serving_kept` | fmkorea 전재 글의 아스날 관련성 판정 | **없었음** |

두 번째 층이 이 기사를 **화면에 들여보낸 자리**다.
DB 를 따라가니 출처가 `fmkorea` 전재 글이었고 (`outlet` 은 게시자가 적어 둔 「디 마르지오」), 제목의 「제주스」 가 명단 표기와 맞아 관련성 판정을 통과했다.

**묶음만 고치면 증상이 더 나빠진다.**
묶음에서 빼내자 그 기사가 관련 보도 접힘에서 **독립 카드**로 올라와 오히려 잘 보이게 됐다.

## 3. 이름 마스킹만으로는 못 잡는 자리 둘

### 3.1. 제목에 성만 나오면 지울 이름이 없다

「포르투갈 대표팀 지휘봉 잡은 제주스, 전술 변화 예고」 는 조르제 제주스 감독 기사인데 제목에 성뿐이라 `_NOT_OUR_PLAYERS` 가 닿지 않는다.

### 3.2. 원문과 번역의 띄어쓰기가 다르다

번역 제목은 「주앙 제주스」 인데 원문 제목은 「주앙제주스」 였다.
목록의 「주앙 제주스」 가 원문에 안 걸리고, 붙여 쓴 문자열 안의 「제주스」 가 명단 이름과 맞아 통과한다.

**그래서 마스킹을 관련성 판정에 붙이는 것만으로는 서빙 산출물이 하나도 안 바뀌었다.**

## 4. 채택한 규칙 — 본문이 풀네임으로 뒷받침할 때만

동명이인이 잦은 성은 본문에 풀네임이 있을 때만 이름으로 인정한다.

```python
_AMBIGUOUS_NAMES = {"제주스": "가브리엘 제주스"}

def mask_ambiguous(title: str, body: str) -> str:
    for surname, full in _AMBIGUOUS_NAMES.items():
        if surname in title and full not in (body or ""):
            title = title.replace(surname, " " * len(surname))
    return title
```

본문 표기가 우리 기사와 남의 기사를 정확히 갈랐다.

| 제목이 성만 쓴 기사 7건 | 본문 |
| --- | --- |
| 우리 기사 4건 | 전부 풀네임 |
| 남의 기사 2건 | 전부 성만 |
| 예외 1건 (x_afcstuff 트윗) | 성만 · 그러나 이 필터의 대상이 아닌 소스 |

**본문은 떨어뜨리는 쪽으로만 본다.**
2026-08-28 에 뺀 규칙은 「본문에 구단 키워드가 있으면 남긴다」 는 통과시키는 쪽이었고, 그것이 배경 설명 한 줄로 타 구단 기사 14건을 끌고 왔다.
여기서는 본문이 기사를 들여보내지 못하므로 같은 고장이 안 생긴다.

**본문이 없는 소스에는 쓰면 안 된다** — 「본문 없음」 이 「풀네임 없음」 이 되어 전량을 버린다.

## 5. 기각한 대안 — 명단 표기를 풀네임으로

가장 먼저 떠오르는 「`ko_name` 을 「가브리엘 제주스」 로 바꾼다」 는 두 이유로 안 듣는다.

- **성이 자동으로 되살아난다** — `roster_surnames` 가 두 어절 이름의 마지막 어절을 성으로 파생하고, 관련성 판정의 셋째 신호가 그 성 목록을 쓴다.
- **미탐이 생긴다** — 배포본 전수로 제목에 「제주스」 가 든 20건을 읽으면 「제주스」 만 쓴 우리 기사가 5건이다.

표기를 바꾸면 파급이 추출 프롬프트 · 사건 묶음 · 선수 페이지까지 함께 간다.

## 6. 여기서 두 번 틀린 잣대

### 6.1. 제목 문자열로 필터 영향을 셌다

「fmkorea 제목 298건 중 가리는 이름이 든 것 3건」 을 세어 「3건이 빠진다」 고 보고했다.
**실제 판정을 돌려 보니 0건이었다.**

관련성 판정은 신호 넷의 OR 이고 신호마다 보는 필드가 다르다 (원문 제목 · 번역 제목 · 성 목록 · 귀속).
한 필드에서 문자열을 세면 나머지 신호가 살려 낸 행을 못 본다.

**판정 함수를 껐다 켜며 두 번 돌려 차집합을 낸다.**

```python
new_keep, _, _ = serving_rows(rows, ...)      # 변경 후
R.mask_other_people = lambda t: t              # 변경분을 끈다
R.mask_ambiguous = lambda t, b: t
old_keep, _, _ = serving_rows(rows, ...)      # 변경 전
print(len(old_keep - new_keep), len(new_keep - old_keep))
```

「되살아나는 것」 도 함께 센다 — 0이 아니면 판정이 뒤집힌 자리가 있다는 뜻이다.
운영 데이터가 필요하면 판정에 쓰이는 필드만 골라 내려받는다 (본문 전체 대신 「풀네임 포함 여부」 불리언 하나로 충분했다).

최종 델타는 이렇다.

```
서빙 입력 949행 · 변경 전 남김 884 · 변경 후 남김 882
  이름 마스킹만: 0행
  본문 뒷받침까지: 2행 제외 · 되살아나는 것 0행
```

### 6.2. 배포본을 파이썬으로 긁어 「이상 없음」 을 읽었다

선수 페이지 57개를 대조하다 **두 번 연속 빈 결과**를 얻었고, 첫 번째는 그것을 「어긋난 선수 0명」 으로 읽어 보고할 뻔했다.

| 증상 | 원인 |
| --- | --- |
| `HTTP Error 403` 전량 | urllib 기본 User-Agent 를 Cloudflare 가 막는다 |
| `HTTP Error 308` 전량 | `/player/<slug>.html` 이 확장자 없는 주소로 넘기는데 urllib 은 308 을 안 따라간다 |

`curl -sSL` 이나 UA 헤더 + 확장자 없는 주소를 쓴다.
**가져오기 결과가 비면 「일치함」 이 아니라 「못 쟀음」 이다.**

### 6.3. 200 을 존재의 증거로 읽었다 (2026-09-01 추가)

이 기사가 화면에 남아 있는지 보려고 `curl` 로 상세 주소를 쳤더니 `HTTP 200` 이 왔다.
**그 페이지는 없는 페이지였다.**

```
없는 기사 주소   → HTTP 200 · 805,693 bytes   ← 첫 화면과 같은 크기
살아 있는 기사   → HTTP 200 · 58,201 bytes
```

Cloudflare Pages 가 없는 경로에 인덱스를 돌려주는 soft-404 다.
**상태 코드만 보고 「페이지가 있다」 고 답하면 틀린다.**
크기를 알려진 기사와 대 보거나, 받은 본문에 그 `content_hash` 가 있는지 센다 (이 건은 0건이었다).

## 6.4. 세 번째 층은 수집이다 (2026-09-01 추가)

위 두 층은 **화면에 들여보내는 자리**였다.
2026-09-01 에 같은 성이 **수집 단계에서도 두 번 작동한다**는 것을 코드로 확인했다.

```
active_link_players()   status='confirmed' AND transfer_status IN ('in_link','out_link')
   └─ 가브리엘 제주스 (id=14 · squad · out_link) · ko_name = 「제주스」
        │
        ▼  워치리스트가 fmkorea 에서 「제주스」 를 검색한다
   「베네치아, 주앙 제주스와 구두 합의… 내일 계약 체결 예정」   ← 제목에 제주스가 있어 걸린다
        │
        ▼  무관 글 필터는 confirmed_ko_names() 를 인정 집합으로 쓰는데 거기에도 「제주스」 가 있다
   통과 · 저장 · 번역 · 주앙 제주스 (id=610 · candidate) 로 귀속
```

**검색어를 만드는 쪽과 무관 글을 걸러 내는 쪽이 같은 `ko_name` 을 쓴다.**
그래서 성만으로 끌어온 동명이인 기사가 필터에서도 근거를 얻는다.

- 실물 = `content_hash = 5ac7757952c6d7f3ee10aa0656b9057fbffa91347ffa3a5a08256ffe76447ef4` (fmkorea · 2026-08-29 19:15:09)
- 두 함수는 `src/bullet_in/storage/players.py` 의 `active_link_players` (검색 대상) 와 `confirmed_ko_names` (필터 인정 집합) 다
- **§2 의 수정으로 서빙은 막혔다** — 상세 페이지가 없는 것을 §6.3 절차로 확인했다

**행을 지우지 않기로 했다** (2026-09-01 사용자 결정).
화면에 안 나오고, 가브리엘 제주스의 이적 축이 활성인 한 같은 종류가 또 들어오므로 한 행을 지우는 것은 증상 제거다.

## 7. 남은 것

- **조르제 제주스 감독 기사** — 사건 묶음에서는 여전히 가브리엘 제주스 쪽에 붙어 있다.
서빙에서는 빠졌지만 묶음 판정은 본문을 안 봐서 이름으로 가릴 방법이 없다.
