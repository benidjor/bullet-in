# 번역이 선수의 성 Read 를 동사로 옮겼고 고칠 자리가 둘이었다 (2026-09-23)

- **영역**: 번역 · 요약 / 통용 표기 사전 / 운영 데이터 정정
- **관련 문서**: `docs/troubleshooting/2026-08-29-spelling-drift-after-the-glossary.md` · 세션 메모리 `canonical-name-vs-the-layer-that-rewrites`

## 1. 증상

사용자가 라이브 기사를 보고 짚었다.
페예노르트 오른쪽 수비수 **Givairo Read** 의 성이 동사로 번역돼 「기바이로 읽」 으로 나왔다.

- 기사 — https://bullet-in.pages.dev/article/41c346dc45548ec133546f9be8834ee988a4297716d087efbf2c4bff1b8343f8
- 제목 — 「리버풀, 페예노르트 수비수 **기바이로 읽** 영입 노려... 아스날 · 맨시티도 주시」
- 원문 — BBC Football Gossip

한 기사의 **네 필드 전부** (`title_ko` · `summary_ko` · `summary3_ko` · `body_ko`) 에 퍼져 있었고, 조사가 붙은 형태가 섞여 있었다 (맨 형태 · 에게 · 을 두 번).

## 2. 원인

`Read` 는 영어에서 흔한 동사다.
모델이 이것을 고유명사로 보지 않고 「읽다」 의 어간으로 옮겼다.

이 실패는 기존 게이트가 보는 축 밖에 있다.

| 게이트 | 이 오류를 잡는가 |
| --- | --- |
| 인명 게이트 (`players` 사전) | 못 잡음 — Givairo Read 가 아스날 선수가 아니라 사전에 없다 |
| 재작성 수치 검사 | 못 잡음 — 숫자가 아니다 |
| dbt 데이터 계약 테스트 21종 | 못 잡음 — `not_null` · `unique` 축이라 문자열 내용을 안 본다 |

즉 **사전 밖의 고유명사를 흔한 보통명사로 옮기면 어느 축도 보지 않는다** (세션 메모리 `passing-a-gate-is-not-safety` 와 같은 구조다).

## 3. 고칠 자리가 둘이었다

이미 저장된 행과 앞으로 들어올 기사는 서로 다른 층이 담당한다.

- **이미 저장된 행** — 운영 데이터를 직접 고쳐야 한다.
`enrich` 는 `rows_missing_translation()` 으로 대상을 고르고 그 조건은 `WHERE title_ko IS NULL` 이다 (`src/bullet_in/storage/mariadb.py:145`).
이미 번역된 행은 후보에 들어오지 않으므로 **다음 회차가 다시 번역해 주지 않는다.**
- **앞으로 들어올 기사** — `config/glossary.yaml` 에 등재해야 한다.
`apply_glossary` 가 번역 결과의 한국어 필드에 사전을 치환 적용한다 (`src/bullet_in/enrich.py:194`).

한쪽만 하면 과거 기사가 남거나 (사전만 등재) 같은 오류가 또 생긴다 (데이터만 정정).

## 4. 처방

### 4.1. 저장된 행 정정

대상을 먼저 셌다.

```sql
SELECT SUM(title_ko LIKE "%기바이로 읽%"), SUM(summary_ko LIKE "%기바이로 읽%"),
       SUM(summary3_ko LIKE "%기바이로 읽%"), SUM(body_ko LIKE "%기바이로 읽%")
FROM articles;
-- 1행 · 4필드
```

치환은 **긴 형태를 먼저** 넣어 중첩했다.

```sql
UPDATE articles SET
  title_ko = REPLACE(REPLACE(title_ko, "기바이로 읽을", "기바이로 리드를"),
                     "기바이로 읽", "기바이로 리드"),
  ...
```

결과는 바꾼 행 1 · 남은 「기바이로 읽」 0 이고, 네 필드를 눈으로 읽어 조사가 자연스러운지 확인했다.

### 4.2. 사전 등재

받침 유무가 조사를 바꾸므로 **조사가 붙은 형태를 짧은 형태보다 앞에** 둔다.

```yaml
  기바이로 읽을: 기바이로 리드를
  기바이로 읽은: 기바이로 리드는
  기바이로 읽이: 기바이로 리드가
  기바이로 읽: 기바이로 리드
  Givairo Read: 기바이로 리드
```

`apply_glossary` 는 사전을 **순서대로 맹목 치환**한다.
짧은 「기바이로 읽」 이 먼저 오면 「기바이로 읽을」 이 「기바이로 리드을」 이 되어 비문이 남는다.
다섯 문장 (맨 형태 · 에게 · 을 · 은 · 이) 에 사전 전체를 적용해 순서를 검증했다.

## 5. 배운 것

- **고칠 자리가 둘인 오류가 있다.**
표기 오류는 저장된 행과 사전을 함께 손봐야 끝난다.
번역 층이 이미 채운 필드를 다시 만들지 않기 때문이다.
- **받침 있는 오표기를 받침 없는 표기로 바꾸면 조사가 깨진다.**
사전이 맹목 치환이므로 순서가 곧 정답률이다.
긴 형태를 먼저 두고, 조사별 문장으로 한 번 돌려 본다.
- **게이트가 보는 축 밖에 있는 실패를 따로 세어 둔다.**
사전에 없는 고유명사를 흔한 보통명사로 옮기는 실패는 지금 어느 게이트도 보지 않는다.
발견 경로는 사실상 사용자가 화면에서 짚는 것뿐이다.
- **말투 백필은 이 정정을 덮지 않는다.**
`select_tone_backfill` 이 요약을 다시 만드는 경우가 있지만 (`src/bullet_in/run.py:542`), 재생성 결과에도 `apply_glossary` 가 걸리므로 사전에 등재한 뒤에는 어느 경로로도 옛 표기가 돌아오지 않는다.
