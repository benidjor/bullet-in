# 잰 화면과 말한 화면이 달랐다 (2026-08-28)

홈 카드 접기 회차에서 화면 수치를 세 번 틀리게 보고했다.
숫자 자체는 다 실측이었고, **그 숫자가 무엇을 잰 것인지가 틀렸다.**

사용자가 매번 화면을 보내며 「전혀 맞지 않잖아」 라고 지적해 드러났다.

## 1. 겹 ① — 마크업을 세고 화면이라고 말했다

「최근 3일 카드 21장」 이라고 보고했는데 화면에는 18장이 보였다.

`site/index.html` 에서 `<div class="block">` 을 센 값이 21이고, 브라우저에서 실제로 그려지는 것은 18이다.
셋이 마크업에는 있고 화면에는 없다.

| 안 보이는 이유 | 건수 |
| --- | --- |
| 단계가 「기타」 라 `app.js` 가 감춤 (`isOther`) | 3 |
| 히어로 밴드에 이미 실린 기사의 재출현 카드 (`band_dup`) | 2 |

**마크업에 있는 것과 화면에 그려지는 것은 다르다.**
이 저장소의 홈은 필터가 기사 단위로 닿게 하려고 **숨김 카드를 일부러 마크업에 넣는다.**
그래서 HTML 계수는 언제나 화면 계수보다 크다.

세는 법은 이렇다.

```javascript
// 화면에 실제로 서 있는 카드
[...document.querySelectorAll('.daygroup .block')]
  .filter(b => b.style.display !== 'none').length
```

## 2. 겹 ② — 배포 안 된 코드의 화면을 현재형으로 말했다

「최신 소식에 최하 카드는 안 섭니다 (0장)」 이라고 답했는데, 라이브에는 2장이 서 있었다.

0장은 **아직 머지도 배포도 안 된 PR** 을 로컬에서 렌더한 결과였다.
라이브는 그 앞 배포본이었다.

```
라이브 VM     #355 까지 배포됨      최신 소식 BBC Gossip 카드 2건
내가 잰 것    PR #357 로컬 렌더     0건
```

**측정값에는 어느 코드로 그린 화면인지가 붙어 있어야 한다.**
이 저장소에는 「배포본 · 프리뷰 · 라이브 세 곳을 순서대로 본다」 는 절차가 이미 있는데
(`2026-07-20-vm-cohost-bootstrap.md` §8), 그건 **배포한 뒤** 확인하는 절차라
**배포 전 측정값을 말할 때의 규율은 비어 있었다.**

말할 때 조건을 붙인다.

- 「PR #357 을 적용하면 0장이 됩니다」 (측정은 로컬 렌더)
- 「지금 라이브는 2장입니다」 (측정은 캐시 우회 조회)

## 3. 겹 ③ — 근거 없이 「그런 규칙은 없다」 고 단정했다

사용자가 「bbc football gossip 은 전부 가십으로 내리는 규칙이 있었다」 고 하자
「그런 규칙은 없습니다」 라고 답했다.

**실제로는 있었다.**
다만 **절을 가르는 규칙이 아니라 단계를 루머로 고정하는 규칙**이었고 (#121 도입 · #197 로 저장 계층 이동),
사용자가 화면에서 본 「가십에만 있더라」 는 인상은 **다른 이유**로 생긴 것이었다 (아래 §4).

같은 실수가 세션 메모리에 이미 적혀 있었다.
「컨트롤러가 DB 분포만 보고 "가십 루머 고정 규칙은 없다" 고 잘못 답변 → 사용자 지적으로 정정」.

**「없다」 는 찾아본 범위를 함께 대지 않으면 말하지 않는다.**
이번에 대야 했던 범위는 이것이다.

```bash
git log --all -S 'bbc_gossip' -- src/bullet_in/serve/    # 소스 이름이 서빙 코드에 박힌 이력
git log --all -S 'is_gossip'  -- src/bullet_in/serve/render.py
grep -rn "가십" docs/superpowers/specs/ docs/superpowers/plans/
```

## 4. 인상이 맞았던 이유 — 세 자리가 최하를 막고 있었다

사용자의 「최하는 가십에서만 봤다」 는 인상은 **화면상 사실이었다.**
꺼내기 (안건 π) 이전에는 최신 소식에 최하 카드가 **설 수 없었다.**

| 자리 | 규칙 |
| --- | --- |
| 대표 선정 | `pick_representative` 의 `not_lowest` — 묶음에 최하가 아닌 기사가 있으면 대표는 최하가 안 된다 |
| 묶음 분리 | `is_gossip_cluster` — 전부 최하인 묶음은 통째로 가십 절로 |
| 히어로 밴드 | `pick_top_stories` 가 상위 3등급만 뽑는다 |

셋이 다 막고 있어서 **화면에서는 최하가 가십 절에서만 보였다.**
실제로는 356건이 최신 소식 이야기 안에 접혀 있었는데, 카드가 아니라 눈에 안 띄었을 뿐이다.

꺼내기가 접힘에서 직접 카드를 만들면서 그 세 자리를 **우회했다.**

**「화면에서 못 봤다」 와 「데이터에 없다」 는 다른 문장이다.**
사용자의 인상을 부정하기 전에 그 인상이 어느 층의 사실인지부터 가른다.

## 5. 재발 방지

1. **화면 수치는 브라우저에서 센다** — HTML 계수를 쓸 때는 「마크업 기준」 이라고 밝힌다.
2. **측정값에 코드 상태를 붙인다** — 「라이브」 · 「PR 적용 시」 를 문장에 넣는다.
3. **「없다」 에는 찾은 범위를 붙인다** — 코드 이력 · 스펙 · 계획서 · 메모리를 다 훑고 명령을 적는다.
4. **사용자의 화면 인상은 층을 갈라 확인한다** — 카드인지 · 접힘인지 · 저장값인지.
