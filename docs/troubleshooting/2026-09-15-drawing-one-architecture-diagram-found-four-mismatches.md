# 아키텍처 그림 한 장을 그리다 덱 · 문서 · 코드가 어긋난 자리 넷을 찾았다 (2026-09-15)

소개 자료 4장의 아키텍처 그림을 다시 그리는 회차였다.
상자와 선을 놓으려면 「이 상자를 누가 읽고 누가 쓰는가」 를 코드에서 확인해야 했고, 그 확인이 덱과 README 와 코드가 서로 다른 말을 하는 자리 넷을 드러냈다.
그림 자체의 함정은 슬라이드 수정 런북 §9 에 적었고, 이 문서는 어긋난 사실과 그 처리만 남긴다.

## 1. 증상 — 선을 그을 수 없는 상자가 생겼다

그림에는 서빙 경로의 Gold (dbt + DuckDB) 상자가 있고, 덱 7장은 「집계가 필요한 대시보드만 Gold 조회」 라고 적혀 있었다.
그 문장대로면 Gold 에서 대시보드로 가는 선이 있어야 한다.
그런데 `src/bullet_in` 에서 dbt Gold 모델 이름 (`gold_slo_rollup` · `gold_daily_source_quality` · `gold_tier_distribution`) 을 찾으니 참조가 0건이었다.
선의 출발점은 있는데 도착점이 코드에 없었다.

## 2. 어긋난 자리 넷

| 무엇 | 덱 · 문서가 말한 것 | 코드가 말한 것 | 처리 |
| --- | --- | --- | --- |
| Gemini 모델 | 4장 배지 「Gemini 2.5」 · README §3 · §7 「Gemini 2.5 Flash-Lite」 | `run.py` 의 `GEMINI_MODEL = "gemini-3.1-flash-lite"` (2026-07-21 PR #109 부터) | 덱은 3.1 로 고쳤다. README 두 곳은 다음 PR 몫으로 남겼다 |
| dbt Gold 의 소비자 | 7장 「집계가 필요한 대시보드만 Gold 조회」 · 18장 「Gold 집계 표 → 화면용 집계」 | 수집 현황 화면은 Silver 표 셋과 게이트 테스트 결과를 읽는다 (`ops_view.py` 467행) · Gold 표를 읽는 파이썬 코드는 없다 · Gold 위 테스트 4종은 `tier` · `slo_id` 의 unique · not_null 뿐이다 | 덱 두 문장을 「행동 지표 화면만 레이크하우스 Gold 조회, 수집 현황 화면은 Silver 운영 기록 직접 조회」 로 고쳤다 · 안건 2ψ (골드무소비) 로 등재했다 |
| 카탈로그의 「관리형」 | 그림 초안 부제 「Google 관리형」 | 비용 때문에 피한 것은 BigQuery 가 관리하는 Iceberg 표 (BigLake Table Management · 시간당 과금) 이고, Lakehouse runtime catalog 의 REST 엔드포인트는 월 5,000회 무료 구간 안에서 쓰고 있다 (설계 2026-09-02 §2.1 · `warehouse.py` load_catalog) | 부제를 「Iceberg REST 카탈로그」 로 바꿨다 |
| 행동 지표의 경로 | `run.py` 주석 「웨어하우스 타이머가 떨어뜨린 집계」 | 집계를 쓰는 주체는 Airflow 의 warehouse_load 태스크다 (`warehouse.py` 1499행 · 타이머는 2026-09-04 전환 전의 이름) | 그림은 behavior Gold → publish 실선으로 그렸다 · 주석은 그대로다 |

넷 다 값이 틀린 것이 아니라 **말이 낡았거나 한 낱말이 두 뜻을 가진** 경우였다.
Gemini 는 모델을 바꾼 PR 이 덱과 README 를 안 건드렸고, Gold 는 「게이트가 만들고 검사하는 집계」 와 「화면이 읽는 집계」 를 같은 낱말로 불렀고, 「관리형」 은 관리형 표와 관리형 카탈로그를 구분하지 않았다.

## 3. 왜 그림이 잡았나

문장은 「Gold 를 조회한다」 고 적어도 읽는 사람이 확인하지 않으면 그대로 남는다.
그림은 다르다.
선을 하나 그으려면 출발 상자와 도착 상자를 둘 다 코드에서 찾아야 하고, 한쪽이 없으면 선을 그을 수 없다.
그래서 이번 회차의 그림 작업은 사실상 덱 문장의 감사였다.
같은 이유로 그림에 넣을 값은 전부 저장소에서 다시 셌다.
소스 10종 (`config/sources.yaml`) · Silver 표 6개 (`schema.sql`) · 태스크 8개 (`bullet_in_cycle.py`) · 타이머 4개 (`infra/systemd/`) · 일 1회 적재 (`warehouse.py` 의 `_DAILY`) 가 그것이다.

## 4. 처리

- 덱 4장 그림을 v16 으로 확정했고 7장 · 18장 문장을 고쳤다.
- 안건 2ψ 골드무소비를 등재했다.
  처방 후보는 수집 현황 화면이 `gold_slo_rollup` 을 읽게 해 SLO 정의를 한 곳에 두는 것이다.
  단 publish 가 gate 앞이라 (설계 2026-08-31 §58 ~ 71) 화면은 직전 실행의 Gold 를 읽게 되고, 그것을 받아들일지가 착수 때 정할 첫 질문이다.
- README §3 · §7 의 「Gemini 2.5 Flash-Lite」 는 이 PR 에 넣지 않았다.
  코드 사실 정정이라 화면 문구 「회차 → 실행」 치환과 함께 별도 PR 로 묶는다.

## 5. 다음에 같은 일을 줄이려면

- 모델 · 카탈로그 · 저장소처럼 이름이 있는 부품을 바꾸는 PR 은 README 와 소개 자료의 같은 이름을 grep 해서 함께 고친다.
- 「Gold」 처럼 한 낱말이 두 층 (게이트용 · 화면용) 을 가리키면 문장에 어느 쪽인지 붙인다.
- 아키텍처 그림은 문장보다 먼저 낡음을 드러내므로, 큰 구조 변경 뒤에는 그림부터 다시 그려 본다.
