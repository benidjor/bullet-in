# 구단명 변형 표기 (아스널) 가 문자열 판정을 층마다 따로 우회한다 (2026-08-01)

#186 라벨의 첫 회차 확인 (2026-08-01 15:00) 에서 오폭 1건이 나왔다.
"월드컵 여파, **아스널** 여름 이적시장 계획에 미칠 영향은?" — 제목이 이미 아스날 글인데 "아스날 링크 선수" 라벨이 붙었다.
라벨 제외 조건이 "아스날" · "arsenal" 두 표기만 검사해, 변형 표기 "아스널" 이 빠져나갔다.

한 줄짜리 픽스 (#189) 로 끝날 일 같지만, 같은 유형의 검사가 코드에 몇 층 더 있어서 인벤토리를 남긴다.
요지는 두 가지다 — **변형 표기는 프롬프트 지시로 막히지 않는다** · **문자열 판정을 새로 만들 때는 이 목록을 먼저 본다**.

## 1. 근본 원인 — 표기 지시는 어겨진다

번역 프롬프트는 통용 표기를 명시한다 (`enrich.py` 의 `고유명사는 통용 한글 표기(Arsenal=아스날)`).
그런데도 이번 기사는 "아스널" 로 번역됐다.
한국 언론이 두 표기를 혼용하므로 (연합뉴스 류는 아스널 · 커뮤니티는 아스날 우세) 모델 출력도 흔들린다.
프롬프트 지시는 확률을 낮출 뿐이고, **하류의 문자열 판정은 변형이 온다는 전제로 짜야 한다**.

## 2. "아스날" 문자열 판정 인벤토리 (2026-08-01 grep 실측)

| 위치 | 하는 일 | 아스널이 오면 | 조치 |
| --- | --- | --- | --- |
| `serve/render.py` `_ctx` | 링크 선수 라벨 제외 (아스날 글 제목이면 라벨 생략) | 아스날 글에 라벨 부착 (실측 발생) | **#189 로 수정 완료** |
| `serve/render.py` `_arsenal_subject_rank` | 사건 묶음 대표 선정 — 아스날 주어 제목 우대 | 대표 순위만 한 단계 낮아짐 (표시 품질 · 오류 아님) | 미조치 · 후속 후보 |
| `serve/render.py` `_ARSENAL_INBOUND` | "아스날행" 류 인바운드 신호로 타 구단 관점 판정 보정 | "아스널행" 제목이 타 구단 기사로 오판될 수 있음 | 미조치 · 후속 후보 |
| `config/sources.yaml` fmkorea `search_keywords` | 수집 검색 키워드 "아스날" (title) | 아스널 표기 제목의 게시글 미발견 | 미조치 — 커뮤니티는 아스날 우세라 실측 후 판단 |
| 워치리스트 스펙 `relevance_terms` 예시 | 무관 글 필터의 구단 키워드 | 아스널만 쓴 글이 무관 판정될 수 있음 | **구현 계획에 "아스널" 포함 반영할 것** |

여기 없는 곳 — 인명 게이트 (`detect_title_hallucination` 등) 는 구단명이 아니라 선수 표기 사전 기반이라 이 문제와 무관하다.

## 3. 판단 기준 — 전부 고치지 않는 이유

- 라벨 (#189) 은 독자에게 바로 보이는 오류라 즉시 고쳤다.
- 대표 선정 · 인바운드 신호는 발생 빈도가 낮고 (번역이 표기 지시를 어긴 경우 × 해당 판정 경로) 틀려도 표시 품질 문제에 그친다.
실측 사례가 나오면 그때 같은 방식 (변형 표기 추가 1줄 + 재현 테스트) 으로 고친다.
- 수집 키워드는 요청 예산이 걸려 있어 (키워드 1개 = 회차당 검색 1회 추가) 유실 실측 없이 늘리지 않는다.

## 4. 재발 방지 규칙

- **구단명을 문자열로 판정하는 코드를 새로 쓸 때는 §2 인벤토리에 행을 추가하고, 변형 표기 (아스날 · 아스널 · arsenal) 를 처음부터 셋 다 넣는다.**
- 멀티 클럽 확장 시 이 문제는 구단 수만큼 곱해진다 (첼시는 단일 표기지만 토트넘/토텐햄 · 뉴캐슬/뉴캐슬 유나이티드 류 변형이 늘어난다).
구단 키워드를 코드가 아니라 설정 (스펙의 `relevance_terms` 방식) 에 두고, 변형 표기를 설정 목록에 나열하는 구조가 이관 비용을 줄인다.
