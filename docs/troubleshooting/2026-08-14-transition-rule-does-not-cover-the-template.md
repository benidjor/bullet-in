# 전환 규칙은 데이터에만 걸린다 — 같은 배포의 템플릿 변경은 그 밖이다 (2026-08-14)

새 컬럼을 넣을 때는 값이 비어 있는 동안 옛 규칙으로 판정하는 전환 규칙을 함께 짠다.
그러면 배포 순간에는 화면이 그대로이고 소급이 끝나는 순간에만 바뀐다는 것이 그 규칙의 약속이다.
공저자 다중 귀속 구현에서 그 약속을 실제로 재 봤더니 **소급 전인데 110개 페이지가 달라져 있었다.**

원인은 전환 규칙의 결함이 아니었다.
규칙은 제 몫을 했고, 같은 배포에 들어 있던 **표시 코드 한 줄이 그 규칙의 적용 범위 밖**이었다.

## 1. 무슨 일이 있었나

기사 상세 페이지의 원문 블록은 저장된 기자명을 그대로 보여 주고 있었다.

```jinja
{% if a.journalist %}<span>{{ a.journalist }}</span>{% endif %}
```

공저 표기 (「대표 외 N명」) 를 넣으면서 이 자리를 정규화된 대표 이름으로 바꿨다.

```jinja
{% if a._authors %}<span>{{ a._authors[0] }}{% if a._more_authors %} 외 {{ a._more_authors }}명{% endif %}</span>{% endif %}
```

새 컬럼이 비어 있으면 `_authors` 에는 대표 한 명만 들어오므로 「외 N명」 은 안 붙는다.
그래서 이 줄은 안전해 보였다.

**안 붙은 것은 「외 N명」 뿐이고, 이름 자체가 바뀌었다.**

```
- <span>David Ornstein Aug</span>
+ <span>David Ornstein</span>
```

저장값과 정규화 이름이 다른 기사가 110건이었다.
한글 말머리로 저장된 기자 (`온스테인`) · 여러 이름을 이어 붙인 문자열 · 날짜 조각이 붙은 값이 전부 여기 걸린다.

## 2. 왜 전환 규칙이 못 막았나

전환 규칙은 **저장된 값을 읽는 자리**에만 걸린다.

- 컬럼이 비면 옛 규칙으로 판정한다 → 사이드바 항목 · 계수 · 카드 속성은 그대로다.
- 그런데 템플릿은 「무엇을 보여 줄지」 를 고른 코드다.
같은 데이터로도 다른 것을 보여 주기로 바꾸면 컬럼이 비어 있든 말든 화면이 바뀐다.

**전환 규칙이 덮는 것은 값이지 표현이 아니다.**
새 컬럼을 넣는 작업은 대개 표시 변경을 함께 들고 오기 때문에 이 구멍은 매번 열린다.

## 3. 어떻게 고쳤나

표시 변경을 **공저일 때만** 걸리게 좁혔다.

```jinja
{% if a._more_authors %}<span>{{ a._authors[0] }} 외 {{ a._more_authors }}명</span>
{% elif a.journalist %}<span>{{ a.journalist }}</span>{% endif %}
```

- 저자가 한 명이면 예전과 똑같이 저장값을 보여 준다.
- 컬럼이 비어 있는 배포 구간에는 저자가 항상 한 명이므로 화면이 안 움직인다.
- 소급이 끝나고 공저가 실린 뒤에야 「외 N명」 이 나타난다.

고친 뒤 다시 재니 배포 구간의 변경이 **110건에서 0건**이 됐다.

## 4. 다음에 쓸 절차

새 컬럼 · 새 판정을 넣는 작업이면 **세 벌을 렌더해 두 번 비교한다.**

| 벌 | 코드 | 데이터 |
| --- | --- | --- |
| A | 현행 | 소급 전 |
| B | 개정 | 소급 전 |
| C | 개정 | 소급 후 |

- **A ↔ B 가 0건이어야 전환 규칙이 실제로 도는 것이다.**
0건이 아니면 그 차이는 전부 「데이터와 무관하게 바뀐 것」 이라 목록을 그대로 읽으면 원인이 보인다.
- B ↔ C 가 이번 변경의 진짜 화면 델타다.
- A ↔ C 만 재면 둘이 섞여 있어서 갈리지 않는다.

**A ↔ B 를 0건으로 만드는 것을 목표로 삼으면 표시 변경의 범위가 저절로 좁아진다.**
이번에는 그 목표 때문에 「대표 이름을 항상 정규화해서 보여 준다」 를 「공저일 때만」 으로 줄였다.
그 축소가 손실인지도 따로 봐야 한다 — 이번 건은 원문 블록이 원래 원문에 적힌 그대로를 보여 주는 자리라 잃은 것이 없었다.
