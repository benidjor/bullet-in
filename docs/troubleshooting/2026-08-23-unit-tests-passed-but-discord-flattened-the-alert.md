# 문자열 테스트를 통과한 문안이 디스코드에서 뭉갰다 (2026-08-23)

## 1. 증상

#322 로 개편한 알림이 실서비스에 나간 뒤, 사용자가 화면을 보고 「한 눈에 알아보기 어렵다」 고 했다.
열어 보니 **내가 의도한 줄바꿈이 실제로는 안 먹고 있었다.**

내보낸 문자열은 이랬다.

```
- 검색 키워드 4개가 전부 실패했습니다
  · 아스날 (제목) · "de roche" (제목·본문)
  · 온스테인 (제목·본문) · 아르테타 이적 시장 (제목·본문)
```

화면에 그려진 것은 이랬다.

```
• 검색 키워드 4개가 전부 실패했습니다· 아스날 (제목) · "de roche" (제목·본문)· 온스테
  인 (제목·본문) · 아르테타 이적 시장 (제목·본문)
```

구획 제목 `▸ 무슨 일이 있었나` 도 굵기 · 크기가 없어 바로 아래 불릿과 같은 무게로 그려졌다.
층이 하나도 안 보였다.

## 2. 왜 테스트가 못 잡았나

**단위 테스트 22종이 전부 통과한 상태로 나갔다.**

- 테스트가 본 것은 **우리가 만든 문자열**이다.
- 화면을 만드는 것은 **디스코드의 마크다운 렌더러**다.
- 둘 사이는 테스트가 닿지 않는다 — 모킹으로는 원리상 못 본다.

이 저장소가 셀렉터 드리프트에서 이미 배운 것과 같은 모양이다 ( CLAUDE.md 「자주 밟는 함정」 ) .
**단위 테스트는 우리 코드의 계약을 지키고, 바깥 시스템이 그것을 어떻게 다루는지는 안 지킨다.**

## 3. 디스코드가 실제로 하는 일

**들여쓴 이어붙임 줄을 앞 불릿에 흡수한다.**

- `- 항목` 다음 줄이 공백으로 시작하면 그 줄은 같은 목록 항목의 이어짐으로 읽힌다.
- 이어짐이므로 줄바꿈이 사라지고 앞 문장 뒤에 그대로 붙는다.
- 그래서 키워드 넷이 한 덩어리로 흘렀다.

**굵기만으로는 층이 안 생긴다.**

- `**▸ 무슨 일이 있었나**` 는 굵어지기만 하고 크기 · 위아래 여백이 없다.
- 바로 아래 불릿의 굵은 라벨과 같은 무게라 제목으로 안 읽힌다.

## 4. 두 번 밟았다

**첫 수정 ( #325 초안 ) 도 문자열만 보고 냈다.**

- 키워드를 중첩 목록으로 바꾼 것은 맞았다.
- 구획 제목을 `**▸ …**` 로 굵게 한 것은 **여전히 추정이었다** — 굵기가 층을 만들 것이라고 가정했다.
- 사용자가 다시 화면을 보고 「항목별로 공백이 더 있었으면」 이라고 해서 두 번째로 뒤집혔다.

**같은 자리를 두 번 밟은 이유는 하나다** — 고칠 때도 실물을 안 봤다.

## 5. 어떻게 닫았나

**같은 내용을 세 서식으로 만들어 실제 디스코드에 나란히 쐈다** ( 사용자 승인 · 버릴 채널 대신 운영 채널 사용 ) .

| 안 | 서식 | 결과 |
| --- | --- | --- |
| A | `**▸ 무슨 일이 있었나**` ( 마크다운 굵기 ) | 크기 · 여백이 없어 층이 약함 |
| B | `### 무슨 일이 있었나` ( 마크다운 헤더 ) | 렌더는 됐으나 A 보다 낫지 않음 |
| C | **embed 필드 이름** | **채택** — 크기 · 여백을 디스코드가 직접 그림 |

- **여백은 폭 없는 공백 ( `U+200B` ) 한 줄** — embed 필드 간격 자체는 고정이라 값 끝에 그 줄을 붙여 띄운다.
- **필드로 펼치는 것은 대상이 하나일 때만** — 소스가 일곱 곳 동시에 끊기면 필드 상한 ( 25 ) 을 넘겨 알림이 발송에 실패한다.
  하필 전면 장애 때 알림을 잃는 자리라 여럿이면 소스당 한 필드로 접는다.
- **확정안을 실제 빌더 · 실제 설정으로 한 번 더 쏴서 확인했다.**

## 6. 남는 규율

- **서식은 추정으로 고르지 말고 한 번 쏴서 고른다.**
  웹훅 하나와 3분이면 되는 일이고, 이 트랙은 그것을 안 해서 두 번 되돌렸다.
- **실패해도 지금보다 나쁘지 않은 쪽을 고른다.**
  중첩 목록이 혹시 안 그려져도 키워드는 한 줄에 하나씩 남는다.
  반대로 작은 회색 글씨 ( `-# ` ) 는 안 그려지면 문자 그대로 찍혀 더 나빠지므로 안 썼다.
- **확인 안 한 문법은 안 쓴다** — 「아마 될 것이다」 는 서식 결정의 근거가 못 된다.
- **문안을 바꾸는 변경은 실발송 스모크를 통과해야 끝난다** — 절차는 `docs/runbook/2026-07-13-collection-alerts-ops.md` 의 「실발송 스모크」 절.
