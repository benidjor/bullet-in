# 같은 것을 세는 잣대가 층으로 쌓여 있다 — 렌더 결과는 원자료가 아니다 (2026-08-20)

사이드바 표기 설계 회차에서 **같은 대상을 네 번 세고 네 번 다른 값**을 얻었다.
데이터는 그대로였고 매번 다른 층에서 셌다.

앞선 잣대 문서 (`2026-08-14-suspect-the-yardstick-not-the-data.md`) 와 축이 다르다.
그 문서는 **값이 예상을 벗어났을 때** 잣대를 의심하라는 것이고, 이 문서는 **값이 그럴듯해서 그대로 쓴 뒤에** 틀린 것을 다룬다.
틀린 값이 이상해 보이지 않았다는 점이 이 유형의 어려움이다.

## 1. 층이 넷이다

서빙 파이프라인은 저장된 값을 네 단계로 가공한다.
각 단계에서 값이 합쳐지거나 빠지므로 **어느 층에서 세느냐가 곧 잣대다.**

```
① 저장 테이블            articles.authors_json · articles.outlet
   ↓ 뷰모델 계산          article_journalists() · outlet_display()
② 뷰모델                 대표 선정 · 별칭 접기 · 소스 폴백이 여기서 일어난다
   ↓ 템플릿 렌더
③ HTML 속성              data-journalist · data-outlet
   ↓ 페이지 구성
④ 화면에 보이는 것        index 는 접고 all 은 편다 · 기타 단계는 숨긴다
```

## 2. 실제로 밟은 네 자리

### 2.1. index 에서 재면 접힌 카드가 빠진다 (④ 층)

**증상** — 사이드바 건수와 화면 목록이 어긋나는 규모를 「언론사 4종 · 기자 19종」 으로 물려받았다.
전체 목록 페이지로 다시 재니 **언론사 20종 · 기자 38종**이었다.

**원인** — 사이드바 건수는 `write_site` 가 전체 기사로 한 번만 계산해 모든 페이지에 넘긴다.
그런데 `index.html` 은 카드 212장만 펼치고 나머지 546장을 사건 블록 안에 접어 둔다.
접힌 546장을 안 세면 그만큼이 「계수에만 있고 화면에 없는 것」 으로 잘못 잡힌다.

**함정의 모양** — 접힌 카드도 필터 대상이라 실제로는 도달 가능하다.
즉 화면에 안 보이는 것과 필터로 못 찾는 것이 다르다.

### 2.2. 사이드바 항목으로 세면 대표가 아닌 이름이 빠진다 (② 층)

**증상** — 한글로 남는 기자 표기를 사이드바 항목에서 세어 11종으로 보고했다.
카드 속성으로 세니 **18종**이었다.

**원인** — 기자 항목은 한 기사에서라도 대표가 된 이름에만 만들어진다 (`facet_counts` 의 정책 C).
한 번도 대표가 된 적 없는 공저자는 카드에 실려 필터로는 잡히는데 사이드바에는 항목이 없다.

**발견 경위** — 다른 작업 중 카드 속성에서 사이드바에 없는 이름이 눈에 띄었다.
찾으려고 한 것이 아니라 우연히 걸렸다.

### 2.3. 카드 속성도 렌더 결과다 (③ 층)

**증상** — 2.2 에서 「카드 원자료」 로 잣대를 고쳤는데 그것도 가공된 값이었다.
저장 테이블로 세니 **20종**이고, 게다가 **갈래 분류가 하나 틀려 있었다.**

**실물** — `fb5edaea4606` 의 저장값이 `["제임스 피어스", "James Pearce"]` 다.
한글과 라틴 표기가 한 배열에 함께 있는데, 카드의 `data-journalist` 는 `article_journalists()` 를 거쳐 **두 표기가 하나로 줄어** 있었다.
그래서 그 기자를 「라틴 짝을 모르는 갈래」 로 넣었다 — 짝이 데이터에 이미 있었는데도.

**이것이 이 문서의 핵심이다.**
「원자료」 라고 부른 것이 한 층 위였다.
층을 한 칸 내렸다고 바닥에 닿은 것이 아니다.

### 2.4. 저장값 계수와 화면 계수를 섞었다 (① 대 ②)

**증상** — 언론사 저장값 3행을 정정한 뒤 화면 반영을 확인하려고 기대값을 「`The Times` 4건 · `ESPN` 5건」 으로 적었다.
실제 사이드바는 12 와 10 이었다.

**원인** — 기대값은 `articles.outlet` 저장값 계수이고, 사이드바는 `outlet_display()` 결과다.
**저장값이 비어 있는 행은 화면에서 소스 폴백이 붙어 잡히므로** 화면 쪽이 항상 크다.

**정정 자체는 맞았다** — 증감으로 보면 `The Times` 11 → 12 · `ESPN` 11 → 10 · `Sky` 10 → 9 로 전부 정합했다.
절대값으로 대조했기 때문에 잠깐 「어긋남」 으로 읽혔다.

## 3. 왜 매번 못 알아챘는가

**매번 나온 값이 그럴듯했다.**
기자 종수만 봐도 11 도 18 도 20 도 「스무 명 남짓」 이라는 감각에 들어맞아서 값 자체로는 틀렸다는 신호가 없었다.

**층을 내릴 때마다 「이번엔 원자료다」 라고 생각했다.**
2.2 에서 사이드바 → 카드로 내리며 잣대를 고쳤다고 문서에 명시까지 했는데, 그 카드 값도 가공된 값이었다.

**같은 회차 안에서 반복했다.**
2.1 을 겪고 「잣대를 병기하자」 를 배운 뒤에도 2.3 과 2.4 를 밟았다.
교훈을 한 자리에만 적용하고 다른 자리에는 안 옮겼다.

## 4. 어떻게 막나

- **수치를 적을 때 층을 함께 적는다.**
「기자 18종」 이 아니라 「카드 `data-journalist` 기준 18종」 이라고 쓴다.
층이 없는 수치는 다음 사람이 다른 층에서 재서 다른 값을 얻는다.
- **「원자료」 라고 부르기 전에 그 값이 어떤 함수를 거쳤는지 본다.**
화면 · HTML 속성 · 뷰모델은 전부 가공된 값이다.
저장 테이블까지 내려가야 바닥이다.
- **합쳐지거나 빠지는 자리를 미리 안다.**
이 저장소에서는 대표 선정 (정책 C) · 별칭 접기 · 소스 폴백 셋이 값을 바꾼다.
그 셋 중 하나라도 거친 값이면 원자료가 아니다.
- **정정 결과는 절대값이 아니라 증감으로 검증한다.**
정정은 저장값에 하고 확인은 화면에서 하므로 층이 다르다.
증감은 층이 달라도 보존된다.
- **한 회차에서 배운 잣대 교훈은 그 회차의 다른 측정에도 옮긴다.**
이번에 세 번 다 「다음 자리에 안 옮겨서」 재발했다.

## 5. 이 유형을 빨리 잡는 검사

같은 대상을 **두 층에서 세어 값이 같은지** 본다.

```sql
-- ① 저장 테이블에서
SELECT COUNT(DISTINCT name) FROM (
  SELECT JSON_UNQUOTE(JSON_EXTRACT(authors_json, CONCAT('$[', n, ']'))) AS name
  FROM articles, (SELECT 0 AS n UNION SELECT 1 UNION SELECT 2 UNION SELECT 3) k
  WHERE JSON_EXTRACT(authors_json, CONCAT('$[', n, ']')) IS NOT NULL) t;
```

```bash
# ③ HTML 속성에서 — 다중 값이므로 구분자로 쪼개 센다
grep -o 'data-journalist="[^"]*"' all.html | sed 's/.*="//;s/"//' | tr '|' '\n' | sort -u | wc -l
```

**두 값이 다르면 그 사이 층에서 무언가 합쳐지거나 빠진 것이고, 그 차이가 곧 잣대의 정의다.**
값이 같으면 그 대상에 한해 층을 신경 쓰지 않아도 된다.
