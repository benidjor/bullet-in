# 문체 점검 산출물을 그대로 넣으면 PR 검사기가 12건을 낸다 (2026-09-03)

PR 본문은 게시 전에 두 도구를 차례로 거친다.
`.claude/tools/check-pr-format.py` 가 컨벤션 §2.2 의 형식을 보고, humanize-korean 스킬 (fast) 이 문체를 본다.
두 도구는 서로를 모른다.
그래서 문체 점검이 내놓은 파일을 그대로 검사기에 넣으면, 본문은 멀쩡한데 12건이 빨갛게 뜬다.

## 1. 증상

배포 자동화 스펙 PR (#451) 의 본문을 문체 점검에 넘겼다.
점검은 13곳을 다듬고 「등급 A · 자체검증 6/6」 을 보고했다.
그 산출물 `final.md` 를 검사기에 넣으니 이렇게 나왔다.

```
final.md:105  라벨 없는 불릿:   - 고유명사·수치·인용 100% 보존: OK
final.md:106  라벨 없는 불릿:   - 변경률 30% 이하: OK
…
final.md:112  라벨 없는 불릿:   - id: A-7
…
final.md:128  범위 물결표: grade_reason: "A — S1 잔존 0, 자체검증 6항 통과. 변경률 3.2% 는 A 밴드(10~25%) 아래인데,
12건 — 이 검사가 안 보는 것은 파일 머리 주석에 있다.
```

본문 7절 어디에도 위반이 없다.
12건 전부가 본문 뒤에 따로 붙은 부분에서 났다.

## 2. 원인

문체 점검 (monolith 모드) 은 산출물 끝에 자기 메트릭을 HTML 주석으로 붙인다.

```
<!-- HUMANIZE-SUMMARY v1.6.1
  self_check:
  - 고유명사·수치·인용 100% 보존: OK
  …
  grade_reason: "A — … A 밴드(10~25%) 아래인데, …"
-->
```

검사기는 HTML 주석을 모른다.
줄 단위로 훑으며 `- ` 로 시작하는데 굵은 라벨이 없는 줄을 「라벨 없는 불릿」 으로, `10~25%` 의 물결표를 「범위 물결표」 로 센다.
둘 다 본문에 적용하면 맞는 규칙인데, 주석 안까지 세는 것이 문제다.

GitHub 은 그 주석을 화면에 안 보여 주므로 그대로 게시해도 사람 눈에는 안 띈다.
그러나 PR 본문 원문에는 남고, 검사기가 12건을 내는 한 「검사기를 돌렸다」 는 확인이 무의미해진다.

## 3. 처방

둘 중 하나면 된다.

- **호출 프롬프트에서 붙이지 말라고 한다.**
  「파일 끝에 HUMANIZE-SUMMARY 주석 블록을 붙이지 말고, 메트릭은 최종 보고 메시지에만 적어 달라」 를 넣는다.
  같은 날 두 번째 PR (#452) 은 그렇게 불렀고 산출물이 깨끗하게 나와 검사기가 0건이었다.
- **잘라 낸다.**
  블록은 `<!-- HUMANIZE-SUMMARY` 로 시작하는 줄부터 파일 끝까지다.

```python
lines = open("final.md", encoding="utf-8").read().splitlines()
cut = next(i for i, l in enumerate(lines) if "HUMANIZE-SUMMARY" in l)
open("pr_body_final.md", "w", encoding="utf-8").write("\n".join(lines[:cut]).rstrip() + "\n")
```

순서는 **문체 점검 → 자르기 → 검사기 → 게시** 다.
검사기를 먼저 돌리고 문체 점검을 나중에 하면 점검이 문장을 바꾼 뒤의 형식을 아무도 안 본다.

## 4. 같은 자리에서 함께 걸린 것 — 레퍼런스 절의 불릿

같은 PR 본문에서 검사기가 §7 레퍼런스의 다섯 줄도 「라벨 없는 불릿」 으로 셌다.

```
- 스펙 — `docs/superpowers/specs/2026-09-03-deploy-automation-design.md`
```

`ci.yml` 의 주석은 이것을 「참고 절의 정상 표기」 라 하고 CI 는 본문 검사를 알림만으로 둔다.
그래도 라벨을 붙이는 편이 싸다.
검사기가 0건이어야 「돌렸다」 가 뜻이 있고, 라벨 하나에 드는 비용은 별표 넷이다.

```
- **스펙** — `docs/superpowers/specs/2026-09-03-deploy-automation-design.md`
```

## 5. 예방

- 문체 점검 호출 프롬프트의 변경 금지 목록 끝에 「요약 블록을 파일에 붙이지 말 것」 을 상용구로 둔다.
- 세션 메모리 `run-check-pr-format-before-posting` 에 이 두 가지를 적어 두었다.
- 검사기가 HTML 주석을 건너뛰도록 고치지는 않았다.
  본문에 주석이 남는 것 자체가 원치 않는 일이라, 검사기가 그것을 짚어 주는 편이 맞다.
