# 검증이 조용히 통과한 두 자리 — 훅의 경로 필터와 마크다운을 삼킨 diff (2026-08-15)

트윗 흡수 설계 회차에서 **검사를 돌렸는데 검사가 안 돌아간 일**이 두 번 났다.
둘 다 실패가 아니라 **통과**로 보였고, 하나는 하마터면 남의 작업을 틀렸다고 보고할 뻔했다.

두 사례의 공통점은 검사 방향이다.
「문제가 없음」 을 확인하는 검사는 **검사 자체가 안 돌아도 똑같이 「문제 없음」 을 돌려준다.**

## 1. 사례 1 — 서식 훅이 상대 경로를 검사하지 않고 통과시킨다

### 1.1. 증상

스펙을 커밋하기 전에 서식 훅을 손으로 불러 `exit 0` 을 받았다.

```bash
echo '{"tool_input": {"file_path": "docs/superpowers/specs/2026-08-14-....md"}}' \
  | uv run python .claude/hooks/check-doc-format.py
# → 훅 종료코드 0
```

문제는 이 문서가 검사를 통과한 것이 아니라 **검사 대상에서 빠졌다**는 것이다.

### 1.2. 원인

`.claude/hooks/check-doc-format.py` 의 `main()` 이 대상 여부를 이렇게 가린다.

```python
f = data.get("tool_input", {}).get("file_path", "")
if "/docs/" not in f or not f.endswith(".md"):
    return 0
```

`"/docs/"` 는 **앞에 슬래시가 붙은 부분 문자열**이라, 상대 경로 `docs/superpowers/...` 는 매치하지 않는다.
그래서 검사 없이 `return 0` 으로 끝난다.

**PostToolUse 훅으로 자동 호출될 때는 절대 경로가 오므로 문제가 없다.**
손으로 부를 때만 나는 함정이다.

### 1.3. 확인 방법 — 훅이 정말 잡는지 먼저 시험한다

일부러 위반이 든 파일을 만들어 훅이 `exit 2` 를 내는지 본다.

```bash
printf '# 시험\n\n가·나 (다) 라 —\n' > /tmp/docs/bad.md
echo '{"tool_input": {"file_path": "/tmp/docs/bad.md"}}' | python3 .claude/hooks/check-doc-format.py
#   문서 서식 위반(컨벤션 §2.2): ...
#     line 3: [줄끝 →/—]
#     line 3: [· 양옆 공백]
#   훅 종료코드 2
```

여기서 2 가 나오면 훅이 살아 있는 것이고, 그다음에 실제 문서를 **절대 경로로** 넣는다.

### 1.4. 처방

- **훅을 손으로 부를 때는 절대 경로를 쓴다.**
- **`exit 0` 을 통과로 읽기 전에 훅이 그 파일을 대상으로 삼았는지 확인한다** — 위반 파일 한 번으로 끝난다.

### 1.5. 곁들여 — `</dev/null` 은 셸에 따라 검사를 없앤다

이 훅은 stdin 으로 JSON 을 받는다.
그래서 `</dev/null` 을 붙이면 `json.load` 가 실패하고 `except: return 0` 으로 빠져 **검사 없이 통과한다.**

**다만 이것은 셸에 따라 갈린다.**
파이프와 `<` 리다이렉션이 같은 stdin 을 두고 다투는데 우선순위가 다르다.

```bash
zsh -c 'echo X | cat </dev/null'    # X      → 파이프가 이긴다
bash -c 'echo X | cat </dev/null'   # (빈 줄) → /dev/null 이 이긴다
```

훅으로 확인하면 이렇게 나온다 (일부러 위반을 넣은 파일).

```
zsh  + </dev/null : exit=2   (검사됨)
bash + </dev/null : exit=0   (조용히 통과)
bash 그냥          : exit=2   (검사됨)
```

- 이 저장소의 대화 셸은 zsh 라 **여기서는 `</dev/null` 을 붙여도 검사가 돈다.**
- **위험해지는 것은 bash 로 도는 경로다** — 스크립트 · 다른 셸을 쓰는 세션 · CI.
- 그래서 「멈출까 봐 `</dev/null` 을 붙인다」 는 습관 자체가 문제는 아니고, **셸이 무엇인지 모르는 자리에서 쓰면 검사가 사라진다.**
- 어느 쪽이든 §1.3 의 확인 (위반 파일로 `exit 2` 를 먼저 보기) 을 하면 갈린다.

## 2. 사례 2 — diff 를 거르는 grep 이 마크다운 불릿을 삼켰다

### 2.1. 증상

윤문 에이전트가 12곳을 고쳤다고 보고했는데 diff 에는 4곳만 보였다.
**「보고와 실물이 어긋난다」 고 사용자에게 보고했고 그것이 틀렸다.**

### 2.2. 원인

diff 출력에서 변경 줄만 남기려고 이렇게 걸렀다.

```bash
diff -u a.md b.md | grep -E '^[-+]' | grep -v '^[-+][-+]'
```

두 번째 `grep -v` 는 `---` · `+++` 파일 헤더를 지우려는 것이었다.
그런데 마크다운 불릿이 삭제 · 추가되면 이렇게 나온다.

```
-- **직전 상태** — 잔여 안건 k 의 장기 대기 항목이었고 ...
   ↑ diff 의 '-'    ↑ 마크다운의 '-'
```

`^[-+][-+]` 에 그대로 걸려 **바뀐 불릿 줄이 전부 사라졌다.**
이 저장소의 문서 규약이 「라벨 불릿」 (`- **핵심어** — 설명`) 이라 본문 대부분이 이 모양이고, 그래서 실제로 바뀐 12곳 중 8곳이 안 보였다.

### 2.3. 확인 방법 — 계수를 두 방법으로 낸다

한 방법의 결과만 보면 그것이 틀렸는지 알 수 없다.
같은 것을 다른 도구로 세어 값이 갈리면 **둘 다 의심한다.**

```bash
diff a.md b.md | grep -c '^<'   # 17
diff a.md b.md | grep -c '^>'   # 18
```

```python
for s in claims:
    print(s, old.count(s), new.count(s))   # 11개 표현 전부 1 → 0
```

이 회차에서는 파이썬 계수가 맞았고 `grep` 파이프라인이 틀렸다.

### 2.4. 처방

- **diff 출력을 정규식으로 거르지 않는다.**
파일 헤더를 빼려면 `diff -u` 대신 **`diff` 기본 형식** (`^<` · `^>`) 을 쓴다 — 마크다운의 `-` 와 안 겹친다.
- **바뀐 줄을 세는 것과 바뀐 내용을 확인하는 것을 분리한다.**
세는 것은 `grep -c '^<'` · `grep -c '^>'` 로, 내용은 필터 없이 눈으로 본다.
- **남의 산출물이 틀렸다고 말하기 전에 다른 도구로 한 번 더 센다.**
이번에는 도구를 바꾸자 결론이 통째로 뒤집혔다.

## 3. 두 사례의 공통 모양

**둘 다 「없음」 을 확인하는 검사였고, 검사가 안 돌아도 「없음」 이 나왔다.**

- 훅 — 위반이 없어서 0 인지, 대상이 아니어서 0 인지 구분되지 않는다.
- diff 필터 — 변경이 없어서 안 보이는지, 필터가 지워서 안 보이는지 구분되지 않는다.

**처방도 같다 — 검사가 무언가를 잡을 수 있다는 것을 먼저 보인다.**
훅은 위반 파일로, diff 는 다른 계수로 확인한다.
없어진 것을 세려면 없어지기 전 목록이 필요하다는 것 (`2026-08-14-a-tradeoff-weighed-one-loss-but-there-were-five.md` · 세션 메모리 `checking-what-disappeared-needs-a-before-list`) 과 같은 뿌리다.

## 4. 2026-09-02 — 같은 문서를 읽고도 재발했고, 새 모양이 하나 더 나왔다

이 문서가 §1 에 적어 둔 훅 실수를 열여드레 뒤에 그대로 반복했다.
그리고 그 회차에서 성격이 다른 넷째 모양이 하나 더 나왔다.

### 4.1. 훅 재발 — 문서가 있다는 것만으로는 안 막힌다

새로 쓴 스펙의 서식을 재려고 훅을 이렇게 불렀다.

```bash
uv run python .claude/hooks/check-doc-format.py --file <스펙 경로>
exit=0
```

`--file` 은 이 훅이 받는 인자가 아니다.
훅은 stdin 의 JSON 을 읽으므로 인자를 무시했고 파싱에 실패해 0을 돌려주었다.
검사는 아예 돌지 않았다.

멈춘 계기는 기억이 아니라 **숫자가 너무 쉽게 나왔다는 위화감**이었다.
256줄짜리 새 문서에 위반이 하나도 없다는 것이 의심스러워 호출 방식을 확인했고, `grep -n "stdin" .claude/hooks/check-doc-format.py` 한 줄로 드러났다.

**여기서 배울 것은 훅의 인터페이스가 아니라 재발 자체다.**
같은 실수가 문서에 적혀 있어도 도구를 부르는 순간에 그 문서가 떠오르지 않으면 소용이 없다.
그래서 규율을 「이 훅은 stdin 을 받는다」 가 아니라 **「검사 도구는 부르기 전에 입력 방식을 본다」** 로 넓힌다.

### 4.2. 새 모양 — 검사는 돌았는데 보는 자리가 너무 넓었다

화면 계측이 읽는 `data-hash` 속성이 두 자리에서 빠져 있어 고치고, 회귀 테스트를 이렇게 썼다.

```python
assert 'data-hash="main1"' in html
```

이 단언은 **페이지 어디에든 그 문자열이 있으면 통과한다.**
같은 기사가 최신 뉴스 카드로도 그려지고 그쪽에는 원래 속성이 있어서 수정을 되돌려도 테스트가 통과했다.

이렇게 고쳐야 결함을 잡는다.

```python
assert re.search(r'class="mitem"[^>]*data-hash="main1"', html)
```

**앞의 세 사례와 원인이 다르다.**
그것들은 검사가 안 돈 경우이고, 이것은 검사가 돌았는데 보는 자리가 너무 넓은 경우다.
값이 산출물의 여러 자리에 나타날 수 있으면 「있는가」 만 묻지 말고 **「어디에 있는가」 까지 물어야 한다.**

### 4.3. 두 번 다 처방은 같았다

일부러 실패시켜 봤다.
훅은 위반을 넣은 파일로, 테스트는 수정을 되돌려서 확인했다.

이 문서가 §2 와 2026-08-27 사례에서 이미 말한 방법이고, 네 사례 전부에서 유일하게 통했다.
**「통과」 를 근거로 쓰려면 그 검사가 실패할 수 있다는 것을 그 자리에서 보여야 한다.**

### 4.4. 고칠 때는 거부가 아니라 지원으로 (2026-09-03)

훅에 인자를 주면 실패하도록 만드는 방안을 먼저 검토했다가 접었다.

거부하면 **손으로 검사할 방법이 여전히 없다.**
그러면 같은 사람이 다시 우회로를 찾고, 그 우회로에서 다음 조용한 통과가 나온다.
경로 인자를 제대로 받도록 고치니 실제 필요가 채워지면서 조용한 통과도 함께 사라졌다.

**고치는 김에 같은 종류의 문제가 하나 더 나왔다.**
`violations()` 는 파일을 못 읽으면 빈 목록을 돌려준다.

```python
try:
    with open(path, encoding="utf-8") as f:
        lines = f.read().splitlines()
except OSError:
    return out          # 빈 목록 = 「위반 없음」 과 구별되지 않는다
```

없는 파일을 검사해도 통과가 나오던 자리다.
CLI 경로에서는 파일 존재를 먼저 확인하고, 통과할 때도 한 줄을 출력해 **아무 검사도 못 한 것과 통과한 것을 눈으로 구별하게** 했다.

**회귀 테스트는 여섯이고, 수정 전 검사기로 돌리면 그중 다섯이 실패한다** (`tests/test_doc_format_hook.py`).
이 문서가 말하는 함정을 새 테스트가 그대로 반복하지 않도록, 테스트를 쓴 뒤 옛 검사기로 한 번 돌려 확인했다.

## 5. 픽스처와 코드가 같이 틀리면 통과한다 (2026-09-03)

행동 지표 집계에서 클릭을 기사 수로 나누려고 마트 컬럼과 조인했다.
계획서에 `journalist_tier` 라고 적었고 테스트 픽스처의 기사 딕셔너리에도 같은 이름을 썼다.

**둘이 같이 틀려서 테스트가 통과했다.**
실제 마트에는 그런 컬럼이 없고 이름은 `tier` 다.
운영 자료로 집계를 내 보고서야 기사 1,010건이 전부 「없음」 으로 몰린 것이 드러났다.

이름을 고쳐도 안 붙는 자리가 하나 더 있었다.
등급은 클릭이 `4` 로, 마트가 `4.0` 으로 온다.

**내가 지어 만든 픽스처는 내 코드가 내 가정대로 도는가만 잰다.**
그 가정이 바깥 계약 (DB 컬럼 이름 · 외부 API 필드 · 다른 층이 정한 값 공간) 과 맞는지는 못 잰다 — 양쪽을 내가 썼기 때문이다.

**재는 법은 실물을 한 번 읽는 것뿐이고 명령 하나에 30초다.**

```python
rows = 실제_소스를_읽는다()
print(sorted(rows[0]))                      # 이름
print(Counter(str(r[k]) for r in rows))     # 값 공간
```

**신호는 「한 축이 통째로 0」 이다.**
값이 골고루 있는데 몇 개만 비는 것과는 다른 고장이다.

같은 자리에서 하나 더 나왔다.
「단계가 없는 클릭 52건」 을 「단계가 없는 기사 2건」 으로 나눠 기사당 26.0 이 나왔다.
두 층의 「없음」 은 뜻이 다르고, 그 값은 오류가 아니라 **그럴듯한 숫자로** 나온다.
