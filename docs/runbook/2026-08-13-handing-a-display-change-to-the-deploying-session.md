# 표시 변경을 배포하는 세션에 넘길 때 무엇을 주나 (2026-08-13)

머지까지만 하는 세션이 배포 주체가 다를 때 **배포 후 확인 기준을 어떤 형태로 넘기는지**를 다룬다.
2026-08-13 표시 규칙 회차 (#267) 에서 절대 건수를 넘겼다가 실패로 오독될 뻔했다.
병렬 세션이 짚어 줘서 불변 조건으로 바꿔 통과했다.

머지 전 화면 검증 자체는 `2026-08-11-premerge-screen-check-with-prod-copy.md` 가 다룬다.
이 문서는 그 검증을 **남에게 넘기는 구간**만 본다.

## 1. 문제 — 내가 잰 값과 그쪽이 볼 값이 다르다

머지와 배포 사이에 데이터가 움직인다.
병렬 세션의 데이터 작업 · 정기 회차의 신규 적재 · 소급 배치가 그 사이에 들어간다.

이번 회차의 실물이다.

| 시점 | 표시 쌍 |
| --- | --- |
| 내가 검증한 사본 | 646 |
| 병렬 세션이 재추출 뒤 잰 값 | 650 |
| 실제 배포 시점 | 또 다름 |

**차이의 원인은 내 변경이 아니다.**
공홈 기사 한 건이 새로 분류되고 정기 회차가 기사를 넣은 몫이다.

그런데 내가 「배포 뒤 표시 쌍 646 을 확인해 주십시오」 라고 넘겼다.
그대로 갔으면 배포 담당이 650 을 보고 **실패로 판정**했을 것이다.

## 2. 원인 — 검증한 것과 넘긴 것의 종류가 달랐다

표시 규칙 검증은 **옛 규칙과 새 규칙의 차이**를 보는 일이다.
그런데 넘길 때는 그 차이가 아니라 **한쪽의 절대값**을 적어 보냈다.

절대값은 데이터가 움직이면 깨진다.
차이는 안 깨진다.

## 3. 절차 — 불변 조건으로 바꿔 넘긴다

넘길 항목마다 「데이터가 늘거나 줄어도 참인가」 를 물어 본다.
참이 아니면 참인 형태로 고쳐 쓴다.

| 넘기지 말 것 | 대신 넘길 것 |
| --- | --- |
| 표시 쌍 646 | **표시 쌍 = 기사 목록 합계** (건수가 얼마든 두 값이 같음) |
| 종결 줄 6개 | **종결 줄을 가진 선수가 정확히 이 여섯 명** (이름 나열) |
| 서빙 670 | **`a975e9f2` · `c072c249` 두 기사가 목록에 없음** |
| 단계 필터 7줄 | **「개인 합의」 줄이 없고 「제안 · 협상」 이 있음** |

형태는 넷 중 하나로 떨어진다.

- **집합의 원소 나열** — 건수가 아니라 무엇이 들어 있는지.
- **두 값의 등식** — 규모와 무관하게 성립하는 관계.
- **특정 항목의 있음 · 없음** — 해시 · slug 처럼 고유한 것으로 지목.
- **구조의 유무** — 어떤 줄 · 절 · 라벨이 있는지 없는지.

**이렇게 넘기면 재측정을 기다릴 필요가 없다.**
이번에 병렬 세션이 「기준선이 흔들리니 재추출 뒤에 다시 재자」 고 제안했는데 불변 조건으로 바꾸니 그 대기가 사라졌다.

## 4. 절대값을 꼭 넘겨야 하면 델타로 준다

건수가 판단에 필요한 경우가 있다.
그때는 **전후 쌍**으로 준다.

```
사다리 줄   87 → 83   (개인 합의 4줄이 제안 · 협상에 흡수)
서빙       674 → 672  (fmkorea 제외 12 → 14)
```

이번에 병렬 세션이 같은 사본에서 내 변경이 있는 판과 없는 판을 나란히 돌려 이 델타를 재현했다.
**절대값이 내 검증과 달라도 델타가 같으면 통과다.**

한 배포에 두 세션의 변경이 함께 실려 이미 섞였을 때 각자의 몫을 가르는 절차는 별도 런북에 있다 (병렬 세션 소유 · 2026-08-13).

## 5. 건수를 넘길 때는 어느 집합인지 함께 적는다

같은 이름의 지표를 두 세션이 다르게 셌다.

```
「명단은 진행 중인데 선수 축이 무산인 귀속」
  확정 선수 전체                      11명 · 14건
  선수 페이지 술어를 통과하는 선수만    9명 · 12건   ← 내가 적어 보낸 값
  차이 2명 = 명단 축이 없어 페이지가 없는 선수
```

화면 이야기를 하다 보면 페이지 대상만 세는 것이 자연스러운데 받는 쪽은 테이블 전체로 읽는다.

**어느 정의가 맞는지는 그 값을 무엇에 쓰느냐가 정한다.**
추출 품질의 신호로 쓸 값이면 전체가 맞다 — 페이지 술어는 명단 값에 달려 있어 추출과 무관하게 움직인다.

## 6. 측정이 어느 코드에서 돌았는지 확인한다

워크트리에서 작업하면서 측정 스크립트를 메인 체크아웃에서 돌리면 **오류 없이 옛 코드의 결과가 나온다.**

이번에 실제로 두 번 그랬다.
셸의 작업 디렉터리가 명령 사이에 초기화됐다 (`cd` 가 든 명령 뒤).
그 뒤 측정이 메인 체크아웃에서 돌았다.
메인은 다른 브랜치에 있어 새 필드를 모르는 코드였다.
선수 페이지가 51개가 아니라 56개로 나왔다.

```bash
# 워크트리에서 도는 명령은 매번 cd 를 붙인다
cd <워크트리> && MARIADB_URL=... uv run python <스크립트>
```

**의심스러우면 스크립트가 아는 것을 찍어 본다.**
새로 만든 필드나 함수가 있을 때는 그 존재 여부를 한 줄 출력하면 갈린다.
