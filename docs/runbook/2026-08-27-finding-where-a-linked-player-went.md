# 아스날 링크 선수가 어디로 갔는지 찾는 절차 (2026-08-27)

「타 클럽행」 으로 적힌 선수의 행선지를 찾을 때의 절차다.
2026-08-27 회차에 12명을 이 순서로 채웠고, 그 과정에서 밟은 함정을 함께 적는다.

**우리 수집은 아스날에 묶여 있다** — 그 선수가 다른 팀으로 가는 순간 소식이 그물 밖으로 나간다.
그래서 이 조사는 외부 접촉이 따르고, 접촉을 줄이는 순서가 중요하다.

## 1. 가진 것부터 센다 (외부 접촉 0)

**「조사가 필요하다」 로 넘기기 전에 우리 기사 본문까지 훑는다.**
2026-08-27 회차에 외부 검색 32회를 돌렸는데 **새로 확인된 오피셜은 0명**이었다 — 답이 이미 우리 안에 있었다.

### 1.1. 제목만 보면 놓친다

얀 디오망데의 레알 마드리드 오피셜은 우리 DB 에 있었다.
그런데 그 기사 제목은 「비니시우스 주니오르, 레알 마드리드와 6년 재계약 체결」 이고, 오피셜은 **본문**에 있었다.

```sql
SELECT content_hash, source_id, published_at, title_ko
FROM articles
WHERE COALESCE(title_ko,'') LIKE '%<이름>%'
   OR COALESCE(body_ko,'') LIKE '%<이름>%'
   OR COALESCE(summary_ko,'') LIKE '%<이름>%'
ORDER BY published_at DESC;
```

### 1.2. 이름 둘레만 잘라 읽는다

전문을 읽지 말고 이름 앞뒤 100 에서 150자만 뽑으면 눈으로 훑을 수 있다.
**창을 너무 좁게 잡으면 미탐이 난다** — 130자 창에 「아스날」 이 안 들어와 프레스네다를 「근거 없음」 으로 낸 적이 있다.
「아르테타의 레이더망」 처럼 구단명 없이 아스날을 가리키는 표현이 있다.

### 1.3. 가장 최신 언급까지 읽는다

한 겹만 보고 종결로 단정해 **셋이 뒤집혔다** (코네 · 돈체프 · 버나드).
07 월의 「합의」 를 08 월 기사가 뒤집고 있었다.

## 2. fmkorea 검색 (외부 접촉)

### 2.1. 승인과 계수

- fmkorea 는 자동 접촉을 **430** 으로 막은 이력이 있다 — 접촉 축을 나눠 승인받는다.
- **붙기 직전에 대상을 다시 센다** ([[count-targets-right-before-running]]).
- 출력은 `tee` 로 남기고 **확인 목적 재실행은 하지 않는다.**

### 2.2. 검색어는 성만 쓴다

성 + 이름으로 쓰면 게시글 표기가 한 글자만 달라도 **통째로 미탐**이다.

| 검색어 | 결과 |
| --- | --- |
| `우스망 디오망데` (성 + 이름) | 오피셜 **놓침** — 게시글이 「우스만 디오망데」 |
| `존 마틴` (성 + 이름) | 재계약 글 **놓침** — 게시글이 「욘 마르틴」 |
| `부아디` · `아센시오` · `데바스트` 등 (성만) | 전부 정상 판독 |

**동명이인이 섞이는 것은 눈으로 가르면 되지만 미탐은 눈에 보이지도 않는다.**

### 2.3. 넓게 훑는 갈래도 있다

키워드를 `공홈` 하나로 잡고 1 에서 3 페이지를 훑으면 최근 공식 발표를 한 번에 본다.
요청 3회로 60건을 보고 우리 명단과 대조하는 방식이다.

**대조 목록을 좁게 잡으면 놓친다** — 이미 `archived` 로 바꾼 선수를 목록에서 빼는 바람에 부아디의 맨시티 공홈을 「걸린 사람 없음」 으로 낼 뻔했다.

### 2.4. `href` 를 반드시 함께 뽑는다

검색 결과에 **날짜가 없다.**
글 번호가 시간순이므로 링크에서 번호를 뽑으면 추가 요청 없이 시점이 갈린다.

```python
m = re.search(r"(\d{9,})", a.get("href", ""))
srl = int(m.group(1)) if m else 0
era = "이번창" if srl >= 9_900_000_000 else "옛글"      # 2026-06-01 ≈ 99억
```

이 한 줄이 없어서 프레스네다 · 스벤손 · 일디즈를 세 번 잘못 읽었다.
경위와 앵커 표는 `docs/troubleshooting/2026-08-27-the-search-had-no-dates-so-we-read-old-posts-as-new.md` 에 있다.

### 2.5. 파이프를 닫지 않는다

`| head -N` 으로 출력을 자르면 SIGPIPE 로 스크립트가 죽는다.
2026-08-27 에 28명 중 22명에서 중단됐고, 이어 붙이다 430 을 만났다.

**파일로 받고 나중에 읽는다.**

## 3. 결과를 가르는 규율

### 3.1. 동명이인을 먼저 본다

「타이난 톰슨」 (토트넘 유스 → 맨유) 을 「키란 톰슨」 (아스날 유스) 으로 읽을 뻔했다.
성이 같은 다른 선수다.

**명단의 `full_name` 과 `first_seen` 기사를 대 본다** — 그 기사가 어느 팀 소속이라고 적었는지가 갈라 준다.

### 3.2. 확신도를 세 층으로 적는다

| 층 | 무엇 | 예 |
| --- | --- | --- |
| 공홈 발표 | 구단 공식 채널 | 「[공홈] 맨체스터 시티, 아유브 부아디 영입」 |
| 기사 본문의 완료형 | 「영입했다」 · 「이적을 완료했다」 | 「첼시는 크리스털 팰리스로부터 라크루아를 £52m 에 영입했다」 |
| 합의 · 마무리 단계 | 「합의」 · 「메디컬」 | 「맨체스터 시티, 부아디 영입 합의」 |

**층을 적어 두면 나중에 뒤집혔을 때 어디부터 다시 볼지 안다.**

### 3.3. 유스 이적은 갈래가 다르다

아스날 유스가 떠난 것은 「아스날이 노리다 뺏긴 선수」 가 아니다.
같은 「타 클럽행」 그룹에 두면 뜻이 섞인다.

2026-08-27 회차는 키란 톰슨 · 미셸 은두카를 `transfer_status='none'` 으로 축을 종결했다 (사용자 판단).
**제레미 몽가는 남겼다** — 아스날이 진지하게 시도하다 맨시티에 뺏긴 건이다.

## 4. 값을 넣는다

### 4.1. 두 칸에 나눠 넣는다

`players.club` 은 **현 소속**, `players.former_club` 은 **전 소속**이다 (2026-08-27 신설).
타 클럽행이면 `club` 이 곧 간 곳이다.

**한 칸에 섞어 넣지 않는다** — 그전에 40행 중 4행이 뜻이 갈려 화면에 쓸 수 없었다.

### 4.2. 저장은 영문 · 화면은 한글

`roster_seed.py` 가 영문으로 쓰므로 DB 에 한글을 섞지 않는다.
표기는 `render.club_ko()` 가 맡고, 매핑에 없는 구단은 저장값을 그대로 띄운다.

### 4.3. 운영 DB 쓰기 절차

백업 → dry-run → 반영이다 (`docs/runbook/2026-08-08-onetime-db-batch-via-tunnel.md`).

- dry-run 이 **시작값을 전건 대조**하게 한다 — 값이 이미 움직인 행은 건너뛴다.
- **근거를 스크립트에 함께 적는다** — 나중에 「이 값이 어디서 왔나」 를 되짚을 수 있다.
