# 긴 한국어 문서에 문체 점검 돌리기

날짜 2026-09-22.
README 개편본 (23,000자 · 산문 15,000자) 에 `humanize-korean` 을 두 번 돌리며 정리한 절차와 함정이다.
PR 본문이나 트러블슈팅처럼 짧은 산출물은 fast 경로로 끝나므로 이 문서는 **8,000자를 넘는 문서** 를 위한 것이다.

## 1. 먼저 분량을 잰다

코드블록 · 표 · 제목 · 이미지 줄을 뺀 **산문만** 세야 한다.
8,000자를 넘으면 스킬이 strict (5인 파이프라인) 로 자동 승급한다.

```bash
python3 -c "
import re, pathlib, sys
t = pathlib.Path(sys.argv[1]).read_text(encoding='utf-8')
t = re.sub(r'\`\`\`.*?\`\`\`', '', t, flags=re.S)
prose = [l for l in t.splitlines()
         if l.strip() and not l.strip().startswith(('|', '#', '!', '['))]
print('전체', len(t), '자 · 산문', len(chr(10).join(prose)), '자')
" <파일>
```

## 2. 작업 폴더를 저장소 밖에 만든다

스킬은 `_workspace/{run_id}/` 를 **cwd 기준** 으로 만든다.
저장소 루트에서 부르면 저장소가 더러워지므로 세션 스크래치패드에 만들고 절대 경로로 넘긴다.

## 3. 지시에 반드시 넣을 것 넷

에이전트마다 지시를 따로 쓰되 아래 넷은 전부에 넣는다.

- **변경 금지 목록** — 수치 · 코드 펜스 안 전부 · 마크다운 표 · 링크 · 파일 경로 · 코드 식별자 · 절 번호 상호 참조 · 전문 용어.
  코드 펜스는 「공백 하나도 바꾸지 말 것」 이라고 적는다 (정렬이 깨진다).
- **문체 정본** — 합쇼체인지 서술형인지 · 엠대시 허용 여부 · `·` 와 `:` 의 역할 · 한글 수사 금지 여부 · 수량사 정본.
- **사용자가 직접 정한 문구 목록** — 아래 §5 참조.
- **독자가 누구인지** — 과윤문 판정의 기준이 된다.

## 4. 두 번째 회차는 입력이 달라져 있다

1회차 지적을 반영하면 문서가 바뀌므로 **탐지 리포트의 offset 이 전부 어긋난다.**
2회차 윤문 지시에 「offset 을 믿지 말고 문면을 직접 찾으라」 고 명시한다.

이미 처리한 finding 과 사용자가 유지를 결정한 finding 도 목록으로 넘긴다.
그러지 않으면 윤문 에이전트가 방금 고친 자리를 다시 고친다.

## 5. 사용자가 정한 문구는 보호 목록으로 넘긴다

탐지기는 사용자가 직접 고른 표현도 AI 티로 잡는다.
실제로 이 회차에서 사용자 지시 원문 넷이 열화로 분류됐다.

**문구의 출처를 갈라서 처리한다.**

| 출처 | 처리 |
| --- | --- |
| 내가 지은 문장 | 지적대로 고친다 |
| 사용자가 지정한 문구 | 지적 내용만 전하고 결정을 받는다 · 보호 목록에 넣어 윤문 에이전트가 못 건드리게 한다 |

## 6. 두 검증을 AND 로 합친다

의미 보존 감사는 「사실이 바뀌었나」 만 보고, 자연스러움 리뷰는 「사람이 읽기에 어떤가」 만 본다.
한쪽만 보고 고치면 다른 쪽이 깨진다.
이 회차에서 세 자리의 판정이 갈렸다.

- **감사관만 잡은 것** — 「A 가 B 를 차단합니다」 를 「B 를 막는 장치는 A 입니다」 로 바꾸자 **배타 함축** 이 생겼다.
  문서의 다른 절에 B 를 막는 장치가 더 있어 문서가 자기와 충돌했다.
- **리뷰어만 잡은 것** — 「정렬, 필터, 번역과 요약을 함께 싣습니다」 가 **연어 파괴** 였다 (「정렬을 싣다」 는 성립하지 않는다).
  근거는 문서 안에 있었다.
  손대지 않은 다음 캡션이 같은 구조에 다른 동사를 쓰고 있었다.
- **둘이 반대인 것** — 한쪽은 첨가라고 지적하고 다른 쪽은 정확하다고 지지했다.
  사실과 어긋나지 않으면 자연스러움 쪽을 따른다.

## 7. 오케스트레이터가 독립으로 다시 센다

에이전트 보고를 그대로 믿지 않는다.
이 회차에서 윤문 에이전트가 「인라인 코드 88개 일치」 라고 보고했는데 다시 세니 100개였다.
값 자체는 맞았지만 **세는 범위가 달랐다.**

```bash
python3 - <<'PY'
import re, pathlib
a = pathlib.Path("01_input.txt").read_text(encoding="utf-8")
b = pathlib.Path("03_rewrite.md").read_text(encoding="utf-8")
F = dict(코드펜스=lambda t: re.findall(r"```.*?```", t, flags=re.S),
         수치=lambda t: sorted(re.findall(r"\d[\d,.]*%?", t)),
         인라인코드=lambda t: sorted(re.findall(r"`[^`\n]+`", t)),
         링크=lambda t: sorted(re.findall(r"\[[^\]]*\]\([^)]*\)", t)))
for n, f in F.items():
    print(n, "일치" if f(a) == f(b) else "다름", len(f(b)))
PY
```

## 8. 함정

### 점수를 회차 사이에 비교하지 않는다

같은 탐지기라도 호출이 다르면 값이 달라진다.
1회차가 낸 14.0 은 2회차에서 재현되지 않았고, 같은 호출 안에서 두 산출물을 나란히 재니 29.0 이었다.

**비교하려면 한 번의 호출 안에서 둘 다 재야 한다.**
분모 (문장 수) 가 문장 분리로 바뀌므로 `raw weight` 도 함께 본다.

### 한 문장만 보고 고치면 문서 정합이 깨진다

지적받은 문장만 들여다보면 문서 전체와의 어긋남을 못 본다.
이 회차의 실물 둘이다.

- 「5가지 문서」 를 넣었는데 **바로 앞 문장** 이 「71편 · 61편 · 87편 · 180편」 이었다.
- 「실패의 3가지 유형」 이 문서에서 「가지」 를 쓰는 유일한 자리였다 (나머지는 「종」 34회).

**낱말을 바꾸기 전에 그 낱말을 문서 전체에서 센다.**

### 줄인 문장이 한정어를 떨어뜨린다

「레이크하우스 유지보수 비용이 0원」 을 줄이다 「레이크하우스」 가 빠졌다.
그러면 **시스템 전체가 0원** 이라는 더 센 주장이 된다.
길이를 줄일 때는 범위를 좁히는 말 (한정어) 이 남아 있는지 따로 본다.

### 탐지기가 프로젝트 서식 컨벤션을 오독한다

컨벤션 §2.2 의 「한 줄 = 한 문장」 을 탐지기가 문단 경계로 읽어, 한 문단 세 문장을 고아 문단 셋으로 판정했다.
**리뷰어가 실측으로 뒤집었다.**
탐지 결과에 「문단」 이 나오면 빈 줄 기준으로 다시 확인한다.

### 잔존 S1 이 임계 인공물일 수 있다

문서 레벨 지표는 자리를 지목하지 못한다.
같은 탐지기의 형제 지표가 그 축을 깨끗하다고 말하면 임계 설계를 의심한다.
이 상태로 다음 회차를 보내면 윤문 에이전트가 할 수 있는 일은 멀쩡한 문장을 건드리는 것뿐이고, **그것이 과윤문이다.**

## 9. 마무리 확인

- 변경률이 목표 구간 (15~25%) 안인가 · 30% 를 넘으면 경고 · 50% 를 넘으면 중단.
- 보호 영역이 바이트 단위로 같은가 (코드 펜스 · 표 · 제목 · 이미지).
- 사용자가 정한 문구가 그대로 있는가.
- 문체 정본을 지켰는가 (종결 · 엠대시 · 수량사).
