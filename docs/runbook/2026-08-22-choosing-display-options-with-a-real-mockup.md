# 화면 선택지는 목업을 만들어 고르게 한다 (2026-08-22)

화면 규칙을 바꿀 때 「어느 안으로 갈까」 를 표와 설명으로 물으면 답 대신 되물음이 온다.
사이드바 기자 목록 설계에서 **선택지 질문이 네 번 연속 반려됐고, 실제로 동작하는 목업을 띄운 뒤 한 번에 결정이 났다.**

**그리고 목업이 결론을 바꿨다** — 표로만 보면 가장 단순해 보이던 안이 만들어 보니 가장 나빴다.

## 1. 언제 이 절차를 쓰는가

- **화면에 보이는 것의 양 · 배치 · 조작 횟수가 판단 근거일 때** — 목록 길이 · 접기 단계 · 버튼을 몇 번 누르나.
- 표시명 · 접기 결과처럼 **값만 바뀌는 변경**은 `2026-08-20-predicting-display-delta-without-rendering.md` 로 충분하다.
- 배치 · 정렬 · 배지 위치까지 봐야 하면 운영 사본 전체 렌더 (`2026-08-11-premerge-screen-check-with-prod-copy.md` §2) 로 간다.

**이 절차는 그 사이다** — 전체를 렌더하지 않고 **한 조각만** 실제처럼 만들어 여러 안을 나란히 놓는다.

## 2. 절차

### 2.1. 배포 산출물에서 그 조각의 마크업을 그대로 떼어 온다

```bash
scp <vm>:'~/bullet-in/site/all.html' /tmp/<세션전용>/all.html
```

바꾸려는 영역만 잘라 낸다 (여기서는 `data-grp="journalist"` 블록).
**마크업을 새로 쓰지 않는다** — 클래스 이름 하나만 달라도 CSS 가 안 먹어 체감이 틀어진다.

### 2.2. 실제 데이터로 각 안의 항목을 생성한다

서빙 함수를 그대로 불러 항목 · 라벨 · 건수를 만든다 (인자는 `run.py` 의 `write_site(...)` 와 1:1).
**항목을 손으로 지어내지 않는다** — 「1건짜리가 몇 개인가」 같은 분포가 곧 판단 근거다.

### 2.3. 실제 CSS 와 실제 동작을 붙인다

```bash
cp src/bullet_in/serve/static/style.css /tmp/<세션전용>/mock/
```

- **스타일시트는 복사한다.** 목업 전용 CSS 로 흉내 내면 밀도 · 여백이 달라져 「길다 · 짧다」 가 안 맞는다.
- **상호작용 코드도 복사한다.** 이 회차의 결정은 「끝까지 보려면 버튼을 몇 번 누르나」 였는데, 그건 눌러 봐야 안다.
`app.js` 의 해당 함수 (`setupMore`) 를 그대로 붙였다.
- 새로 넣을 요소 (검색칸 등) 는 최소 구현으로 붙인다 — 실제 구현과 같을 필요는 없고 **눌러서 반응하면 된다.**

### 2.4. 안을 나란히 놓고 각 안 위에 그 안의 수치를 적는다

```
가. 새 단계 둘        나. 새 단계 하나       라. 1건 단계만       없음. 검색칸만
펼치면 21줄 + 버튼    펼치면 21줄 + 버튼     펼치면 21줄 + 버튼   펼치면 21줄 + 버튼
본 목록 46명          본 목록 46명           본 목록 62명         본 목록 201명
버튼 5번              버튼 4번               버튼 4번             버튼 5번
```

같은 화면에서 비교되면 **사용자가 스스로 조합을 제안한다** (이 회차에서 「B 와 D 를 같이 하면?」 이 나왔다).
표를 따로 두지 말고 각 안 바로 위에 붙인다.

### 2.5. 세션 전용 포트로 띄우고, 다 쓰면 내린다

```bash
cd /tmp/<세션전용>/mock && python3 -m http.server 8902 --bind 127.0.0.1
```

- 포트는 세션마다 다르게 잡는다.
- **새 목업을 띄우면 옛 것을 내린다** — 둘이 함께 떠 있으면 어느 화면을 보고 말하는지 서로 어긋난다.
내리지 못할 사정이면 「이것만 보라」 를 명시한다.
- 결정이 끝나면 서버 · 디렉터리 · 복사한 CSS 를 함께 지운다.

## 3. 목업이 결론을 바꾼 실물

「새 단계를 안 만들고 검색칸만 넣는다」 가 표에서는 가장 단순해 보였다.
만들어 보니 **가장 나빴다.**

| 안 | 더보기 본 목록 | 끝까지 보려면 |
| --- | --- | --- |
| 새 단계 둘 | 46명 | 버튼 5번 |
| 새 단계 하나 | 46명 | 버튼 4번 |
| **새 단계 없음** | **201명** | **버튼 5번** |

**갈 곳이 없어진 항목이 원래 묶음으로 되살아났기 때문이다** — 기사 한 건짜리 상위 공신력 기자들이 더보기에 「공신력 최상」 · 「공신력 상」 단계로 다시 나타나 단계가 오히려 늘고 목록도 길어졌다.

**「빼면 짧아진다」 가 항상 맞지 않는다** — 뺀 것이 어디로 가는지 함께 세야 하고, 그건 만들어 봐야 보인다.

## 4. 함정

- **목업 계수와 최종 계수가 갈릴 수 있다.** 이 회차의 목업은 뒤에 확정된 표기 합침을 켜기 전 값이라 본 목록이 46 · 47 로 한 줄 달랐다.
**어느 쪽이 정본인지 스펙에 명시한다** — 안 적으면 구현 회차가 목업 수치를 판정 기준으로 쓴다.
- **항목이 중복되기 쉽다.** 첫 화면에 실은 항목을 접힌 단계에도 다시 넣으면 총수가 늘어난다.
이 회차 초판이 205 대신 226 · 214 로 나왔다 — **각 안의 총수가 서로 같은지 먼저 확인하고 띄운다.**
- **목업은 「지금 화면」 이 아니라 「바꾼 뒤 화면」 이다.** 지금 상태를 재는 것이면 배포 산출물 한 장으로 충분하다 (`2026-08-11-...` §5).
