# 사전에 무엇이 빠졌는지 찾는 절차 (2026-08-28)

이 저장소는 사전 파일이 여럿이고 (`club_map.yaml` · `credibility.yaml` · `players` 테이블) **빠진 값은 오류를 안 낸다.**
조용히 다른 갈래로 새고, 화면을 눈으로 볼 때까지 아무도 모른다.

2026-08-28 에 알 힐랄이 구단 목록에 없어서 「알 힐랄, 마르티넬리 영입 임박」 이 **다른 구단 관점으로 안 잡히고 「아스날 쪽 보도」 로 새고 있었다** (코퍼스 19건).
그 결과 마르티넬리 묶음의 갈래 이름표가 「나폴리행 관련」 으로 어긋났다.

이 절차는 그때 두 번 (구단 · 동명이인) 실제로 써서 답을 낸 순서다.

## 1. 언제 쓰나

| 상황 | 이 절차 |
| --- | --- |
| 화면 분류가 이상한데 코드는 맞아 보인다 | **이것** — 사전 누락을 먼저 의심한다 |
| 사전에 값을 넣기 전 위험을 재고 싶다 | **이것** — 3절 |
| 코드 규칙 자체가 의심된다 | 아님 — `2026-08-28-three-rules-that-looked-right-and-broke-more.md` |

## 2. 터널을 열고 운영 데이터로 잰다

로컬 DB 로는 못 한다 — 코퍼스가 없다.

```bash
ssh -i ~/.ssh/<키> -f -N -L 13309:127.0.0.1:3306 <운영 사용자>@<운영 호스트>
nc -z 127.0.0.1 13309 && echo "터널 열림"
```

**포트는 세션마다 다르게 잡는다.**
끝나면 `pkill -f "13309:127.0.0.1:3306"` 로 닫는다.

돌릴 때 env 를 운영 주소로 바꾼다.

```bash
set -a; . ./.env; set +a
export MARIADB_URL="${MARIADB_URL/@localhost:3306/@127.0.0.1:13309}"
```

## 3. 누락을 찾는 두 갈래

### 3.1. 갈래 하나 — 「그 판정을 빠져나간 것」 을 센다

판정 함수를 그대로 불러 **아무것도 못 잡은 입력**을 모은다.
구단이라면 `club_in_title` 이 `None` 을 낸 제목이다.

```python
for cl in R.cluster_events(rest, players):
    for a in cl["articles"]:
        t = a.get("title_ko") or ""
        if t.lstrip().startswith("아스날"):
            continue
        fc = R._first_clause(t)
        if cl["key"] not in fc or R.club_in_title(fc, clubs):
            continue                       # 이미 잡히는 것
        head = re.split(r"[,·]", fc)[0].strip()
        miss[head] += 1
```

**이 갈래는 잡음이 많다.**
2026-08-28 실측에서 146건 · 머리말 98종이 나왔고 그중 실제 구단은 **둘**이었다.
나머지는 사람 이름 (「아르테타 감독」) 과 문장 조각 (「이적 시장 마감 1주일」) 이었다.

### 3.2. 갈래 둘 — 후보 목록을 만들어 코퍼스에 대 본다

도메인 지식으로 **있을 법한 값**을 적고 코퍼스에서 센다.
잡음이 없고 건수가 바로 나온다.

```python
CANDIDATES = ["알 힐랄", "알 나스르", "에버튼", "레스터", "마르세유", ...]
for t in titles:
    for cand in CANDIDATES:
        if cand in t:
            hit[cand] += 1
# 이미 사전에 있는 것은 빼고 출력
```

2026-08-28 결과다.

```
19건  알 힐랄     ← 최다 · 이번 화면 결함의 직접 원인
 7건  에버튼      ← 「에버턴」 은 있는데 「에버튼」 이 없다 (표기 변형)
 6건  레스터   3건  릴   3건  카디프   3건  입스위치
 2건  마르세유   1건  알 나스르 · 알 아흘리 · 피오렌티나 · 렌 · 니스
```

**두 갈래를 함께 쓴다.**
갈래 하나는 「생각 못 한 값」 을 찾고, 갈래 둘은 「건수와 우선순위」 를 준다.

## 4. 넣기 전에 등재 규칙을 대 본다

`config/club_map.yaml` 머리 주석에 규칙이 적혀 있고 **그 규칙이 「안 넣는다」 도 정한다.**

| 규칙 | 뜻 | 2026-08-28 적용 |
| --- | --- | --- |
| ① 별칭 누락 = 오탐 | 통칭까지 등재 | `알 힐랄: [Al Hilal, Al-Hilal]` |
| ② 짧은 한글 표기 주의 | 결합 오매치가 나면 미등재 | **릴 · 렌 · 니스를 뺐다** (릴레이 · 렌즈 · 니스칠) |
| ④ 복수 한글 표기는 각각 | 별칭 목록을 똑같이 | 「에버턴」 옆에 「에버튼」 |

**②가 이 절차의 핵심이다.**
「코퍼스에 3건 있다」 가 등재의 근거가 못 된다 — 그 표기가 일반어에 걸리면 넣는 순간 손해다.
릴은 파일 주석에 미등재 결정이 **이미 적혀 있었다.**

## 5. 넣은 뒤 효과를 같은 잣대로 다시 잰다

넣기 전후로 **같은 스크립트를 돌려 무엇이 바뀌는지 전수로 읽는다.**

```
전  결말 = 나폴리   | 갈래 「나폴리행 관련」 12건 (갈라타사라이 11 · AS 로마 1 · 나폴리 0)
후  결말 = 알 힐랄  | 갈래 「알 힐랄행 관련」 22건 (갈라타사라이 11 · 알 힐랄 9 · 나폴리 1 · AS 로마 1)
```

**계수만 보지 말고 구성을 읽는다.**
위 결과에서 「갈래가 12 → 22 로 늘었다」 는 개선이지만, 같은 줄이 **이름표가 여전히 여러 구단을 한 이름으로 부른다**는 것도 보여 준다 (잔여 안건 τ 로 열었다).

## 6. 사람이 다시 안 찾아도 되게 만든다

전수 대조로 얻은 목록은 정확하지만 **자라지 않는다.**
같은 누락이 또 생겨도 화면을 볼 때까지 모른다.

그래서 관측을 붙였다 — `quality.missing_club_candidates` 가 제목 머리말 중 **사전 셋에 없고 되풀이되는** 이름을 모아 디스코드 review 채널로 알린다.

**자동 등재는 하지 않는다.**
`club_map.yaml` 은 번역 환각 검출 (`enrich.detect_club_injection`) 의 사전이라, 모델이 지어낸 이름이 들어가면 그 가드가 자기 환각을 승인한다.

**문턱이 필터의 본체다.**
실제 구단은 여러 기사에 되풀이해 나오고 문장 조각은 한 번 나온다.
소급 검증에서 문턱 3 은 알 힐랄 7 · 에버튼 3 을 잡고 오탐이 0 이었고, 문턱이 없으면 후보가 45종으로 늘어 읽을 수 없었다.

**관측을 넣었으면 소급으로 검증한다.**
이번에 손으로 넣은 10종을 뺀 상태로 돌려 「그 탐지기가 우리가 손으로 찾은 것을 찾아냈을까」 를 확인했다.
