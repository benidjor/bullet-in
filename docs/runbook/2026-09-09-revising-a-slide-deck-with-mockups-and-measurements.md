# 런북 — 슬라이드를 고칠 때의 순서 · 목업, 조각 반영, 열별 측정, 캡처

소개 슬라이드 (저장소 밖 · `v9_build`) 한 장을 고쳐서 사용자 확인까지 가는 절차다.
2026-09-09 에 4 ~ 20장을 세 차례 통독받으며 굳어진 순서이고, 도구는 전부 `v9_build/` 에 있다.

## 1. 목업을 먼저 만든다

- 슬라이드 HTML 을 손으로 고치지 않는다.
  덱은 조각 `bullet_in_v2.html` 에서 `build_v9.py` 로 조립되므로, 조립본을 고치면 다음 조립 때 사라진다.
- 구조가 바뀌는 수정 (표를 도식으로 바꾸기, 열 배치 바꾸기) 은 `mockups/head.html` (덱 `<style>` 전체) 뒤에 슬라이드 하나를 붙인 목업으로 만든다.
- `shoot_any.py <dir> <name>` 으로 찍어 넘침을 확인하고 캡처를 사용자에게 보낸다.
  사용자 확인 전에는 조각을 건드리지 않는다.
- 두 안 이상을 비교할 때는 같은 장을 같은 조건으로 찍어 나란히 보낸다.
  요약 띠 색 같은 취향 결정은 실제 조립본 (청록 상자가 있는 장) 에서 비교해야 판단이 선다.
- 목업 머리 (`mockups/head.html`) 는 덱의 `<style>` 만이 아니라 조립기가 `</style>` 앞에 끼워 넣는 규칙 줄까지 담아야 한다.
  그 줄에 16장 공통 목록 규격 (`.bi`) 이 있어서, 빠지면 목업이 덱보다 짧게 재어진다 (2026-09-11 트러블슈팅).
  조립기의 규칙 줄을 바꿨으면 머리 파일의 마지막 규칙 줄도 같은 문자열로 바꾼다.
  검증은 덱과 목업을 Playwright 로 열어 같은 장의 `li` 글자 크기와 높이를 나란히 찍어 보는 것이다.

## 2. 조각에 반영하고 조립한다

```bash
cd ~/Documents/01_DE_project/bullet-in          # Playwright 가 이 저장소 venv 에 있다
B="$HOME/Documents/obsidian-vault/01 Projects/01-04 이력서/v9_build"
(cd "$B" && python3 build_v9.py)                 # 조립 · id 순서 · 목차 도달 검산
uv run python "$B/shoot.py"                      # 41장 넘침 (scrollHeight)
uv run python "$B/cols.py" 9 10 12               # 넘친 장의 열별 바닥
```

- `build_v9.py` 는 조각 id 순서 (`order`) 대로 번호를 다시 매긴다.
  장을 끼워 넣으면 `N_NEW` 와 목차 행 번호를 함께 밀어야 하고, 비교 장은 코드에 번호가 고정돼 있어 손으로 바꾼다.
- 조각 안의 쪽 번호 참조 (「17쪽」 같은 것) 도 함께 민다.

## 3. 넘침은 열별로 잰다

- `shoot.py` 의 넘침은 장 전체 값이라 원인을 안 가르쳐 준다.
  `cols.py` 가 찍는 열 바닥과 자식 바닥을 보고 어느 열의 무엇이 밀었는지 확인한다.
- 내용 한계는 720 − 그리드 아래 여백이다.
  대부분 14px 라 706 이고, 처음 v8 값은 24px 였다.
- 문장을 줄여도 값이 그대로면 CSS 를 의심한다.
  사례는 `docs/troubleshooting/2026-09-09-slide-overflow-came-from-css-not-sentences.md`.
- 왼쪽 열이 넘치고 오른쪽 열이 비면 지표 상자나 숫자 카드를 오른쪽 열 아래로 옮기는 것이 문장을 줄이는 것보다 낫다.
- 인라인 SVG 의 `<style>` 은 문서 전체에 적용되므로 클래스 이름에 장별 접두어를 붙인다 (`.glb` · `.xb` · `.dpb`).
  같은 이름이 덱에 몇 개인지는 `grep -o '\.이름{[^}]*}' 덱.html | sort | uniq -c` 로 센다.
- 도식 안 글자가 상자를 넘는지는 눈이 아니라 `getBBox()` 로 잰다.
  글자마다 오른쪽 끝 좌표와 그 글자를 품은 상자의 오른쪽 변을 찍어 비교하면 한 번에 다 보인다 (7장 ERD · 15장 도식에서 씀).
- 문장을 줄여도 값이 그대로면 어느 항목이 두 줄인지 캡처로 본다.
  한 단어가 다음 줄로 넘어간 항목은 괄호 하나만 떼도 한 줄이 된다.

## 4. 문장 규칙 (통독에서 굳어진 것)

- 항목은 「`·`」, 하위 항목은 「`→`」 표식뿐이다.
  문장 첫머리에 화살표를 두지 않고 항목 안에서 `<br>` 로 끊지 않는다.
- 「`·`」 은 짧은 명사 나열에만 쓰고 절과 절 사이는 「`,`」 다.
- 「`→`」 는 흐름, 「`⇒`」 는 결론이다.
  「`⇒`」 로 시작하는 결론 줄은 표식 없는 하위 항목 (`sub num`) 으로 두고 청록으로 강조한다.
- 명사형 종결과 「—」 금지를 지키고, 「↓」 같은 기호는 대체 서체로 찍히므로 「단축」 같은 말로 푼다.
- 내부 용어는 세션 메모리 `external-audience-terms` 의 표로 한 번 걸러 낸다.
- 「`·`」 은 짧은 명사 나열에만 쓴다.
  절과 절 사이, 캡션 · 코드 라벨 · 표 안의 절은 「,」 다.
  2026-09-10 통독에서 캡션 · 코드 라벨 · 표 안 스물여섯 곳이 「`·`」 로 이어져 있어 전부 바꿨다.
- 강조는 두 단계다.
  청록 굵게 (`.tb`) 는 요약 띠의 핵심, 「왜」 절의 상위 항목, 「해결」 절 전부에 쓰고, semibold 검정 (`.sb`) 은 「문제」 절과 「왜」 절의 하위 항목에 쓴다.
  규칙으로 한 번 배정하고 사용자가 짚은 자리만 개별로 바꾼다.
- 다른 장을 가리킬 때는 「N쪽」 이 아니라 「슬라이드 N」 이고, 클릭하면 이동하도록 `<a href="#slide-N">` 을 건다.
  SVG 캡션 안에서는 `<a>` 로 감싼 `<tspan>` 을 쓴다.
- 예시는 「예)」 로 시작하고, 표 안에서 줄이 넘어가면 걸린 들여쓰기 (`padding-left:1.4em; text-indent:-1.4em`) 로 둘째 줄을 들인다.
- 하위 항목에 표식이 필요 없을 때 (① ② ③ 나열) 는 `sub nomark` 클래스로 화살표를 뺀다.
- 구어체 (긁다 · 돌다 · 겪다 · 뒤지다 · 뚫리다) 는 검색어 목록으로 훑어 걸러 낸다.
- 수치는 저장소나 같은 날 실측에 닿아야 한다.
  이번 회차에서 co-author 커밋 수를 `git log` 로 다시 세어 586 이 587 로 바뀌었다.

## 5. 캡처를 보낸다

- 바뀐 장만 `shots/slide-NN.png` 를 보낸다.
  한 번에 여섯 장 안팎이 읽기 좋다.
- 대시보드 캡처는 창을 KPI 카드와 차트가 보이는 구간으로 옮긴다 (`object-position`).
  원본 캡처가 1040 × 1500 이라 위 절반은 설명 글뿐이다.
- 사이트 캡처는 양옆 여백을 잘라 확대한다 (`width:127%`, `margin-left:-13.5%`).
- Airflow 화면은 VM 루프백에만 묶여 있어 SSH 터널 (`-L 8081:127.0.0.1:8080`) 로 연다.
  터널과 비밀번호 파일 읽기는 auto mode 분류기에 막히므로 사용자가 `!` 로 직접 연다.
  Playwright 로 로그인해 찍는 스크립트도 막히며, 사용자가 허용한 뒤 비밀번호를 스크립트 파일에 두고 돌린 다음 그 파일을 지운다.
  그리드 패널과 상세 패널 사이 경계를 끌면 일정 폭을 넘길 때 상세 패널이 통째로 접히므로, 접힌 상태에서 찍고 태스크 이름 열과 실행 열을 잘라 붙인다 (Pillow 는 `uv run --with pillow`).

## 6. 목업을 조각에 옮긴다

- 목업 파일에서 `<div class="sw" id="slide-NN">` 부터 `</body>` 앞까지를 잘라 조각의 같은 장 블록 (다음 `<!-- ═` 주석 앞까지) 과 바꾼다.
  `id="slide-NN"` 은 조각 id (`K` · `L` · `M`) 로, `<div class="pg">NN</div>` 은 `0` 으로, 이미지 경로 `../../portfolio_assets/` 는 `portfolio_assets/` 로 되돌린다.
- 옮기기 전에 목업 SVG 의 클래스 이름이 덱의 다른 클래스와 겹치는지 본다.
  15장 도식의 `.kw` 는 코드 블록의 `.code .kw` 와 겹쳐 접두어를 바꿨다.
- 옮긴 뒤에는 41장 전체를 다시 잰다.
  목업이 0 이어도 덱에서 넘칠 수 있고, 2026-09-11 에는 16장 16px · 17장 31px 가 그렇게 나왔다.

## 8. 이어진 회차에서 더 밟은 것 (2026-09-11)

통독 15차에서 21차까지 가면서 §1 부터 §7 에 없던 함정이 여섯 더 나왔다.

- **모든 줄이 한 줄인데 넘치면 줄 수 자체가 문제다.**
  항목마다 높이를 찍어 두 줄짜리를 찾는 것이 첫 단계인데, 전부 20px 이면 문장을 줄여도 소용이 없다.
  그때는 뜻이 안 바뀌는 짧은 줄 둘을 앞 줄에 붙여 줄 수를 줄인다 (11장에서 「수정 직후에는 이상 없음」 과 「실행 직전 대상 재확인」 을 그렇게 합쳤다).
  항목 높이는 `measure_items.py` 로 찍는다.
- **한 줄 문장의 가용 폭은 요소 폭이 아니라 슬라이드 오른쪽 여백까지다.**
  `white-space: nowrap` 인 요소는 내용만큼 넓어지므로 `clientWidth` 가 늘 텍스트 폭과 같게 나온다.
  잘렸는지는 「슬라이드 오른쪽 끝 − 여백 − 요소 왼쪽」 을 가용 폭으로 두고 후보 문장의 폭을 대 봐야 안다 (3장 소개 문장은 가용 844px 에 885px 이라 잘렸다).
- **조립기의 사실 확인 assert 는 문장을 바꿀 때 함께 갱신한다.**
  표지 · About 문장을 바꾸자 옛 문장을 찾는 assert 두 줄이 조립을 멈췄다.
  assert 는 치환이 실제로 됐는지 보는 장치라 지우지 말고 새 문장의 일부로 바꾼다.
- **v8 에서 찾는 옛 상자와 새로 넣는 상자의 템플릿을 분리한다.**
  표지 상자 템플릿 하나로 옛 상자 검색과 새 상자 생성을 같이 하다가 줄 간격 한 줄을 넣자 옛 상자를 못 찾았다.
  새 상자용 `BOX_NEW` 를 따로 두면 옛 상자 검색이 안 흔들린다.
- **강조는 절 규칙으로 한 번 감사한다.**
  문제 절은 semibold, 왜 절의 상위는 청록 · 하위는 semibold, 해결 절은 청록이라는 규칙을 스크립트로 대 보면 어긋난 자리가 한 번에 나온다 (5에서 13장에서 43곳, 그중 18곳을 고쳤다).
  ① ② ③ 열거와 「e.g.」 줄처럼 규칙 밖으로 둔 자리는 따로 적어 둔다.
- **SVG 도식의 화살표는 직각 경로 헬퍼로 긋는다.**
  꺾는 점 하나만 받는 함수에 두 번 꺾을 경로를 넣으면 대각선이 그어진다.
  점 목록을 받아 폴리라인으로 긋는 `route()` 를 쓴다.
  아이콘은 simple-icons (CC0) 의 path 를 인라인으로 가져오고, 없는 로고 (Apache Iceberg) 는 공식 아이콘 PNG 를 데이터 URI 로 넣는다.
  이렇게 만든 4장 그림 두 안 (영역 배치 · 태스크 열 구조) 은 2026-09-11 에 둘 다 기각됐고, 생성기 (`arch_v2.py` · `arch_v3.py`) 와 산출물 (`architecture-v2.svg` · `-v3.svg`) 은 다음 안의 재료로 남아 있다.

## 9. 아키텍처 그림 회차에서 밟은 것 (2026-09-15)

4장 그림을 v4 에서 v16 까지 열세 번 고쳐 확정한 회차다.
그림 생성기 (`arch_v16.py`) 와 겹침 검사기 (`svg_overlaps.py`) 는 소개 자료 조립 폴더에 있고, 여기에는 절차와 함정만 적는다.

- **겹침은 눈이 아니라 렌더로 잰다.**
  SVG 를 브라우저에서 열어 글자마다 `getBBox()`, 선마다 `getPointAtLength()` 로 점을 뽑아 글자 상자 · 테두리 변 · 작은 상자와 대조한다.
  이름과 부제처럼 같은 중심선에 쌓인 글자 쌍과 테두리 위 · 아래 변에 걸치게 둔 이름표는 의도한 배치라 검사에서 뺀다.
  확정 전에 「겹침 없음」 을 본다.
- **선이 다른 선을 건너면 반원으로 넘긴다.**
  직각 폴리라인 헬퍼에 건널 좌표 목록을 주면 그 자리에 반지름 5 의 반원을 끼운다.
  세로 구간은 y 목록, 가로 구간은 x 목록이다.
- **되돌이 선은 그림 둘레로 돌린다.**
  산출물 (Pages) 에서 입력 (GA4 태그) 으로 돌아가는 선을 안쪽으로 그으면 교차가 여럿 생기고, 바닥과 왼쪽 가장자리를 따라 돌리면 0 이다.
  선 위에 흰 이름표를 얹는 안은 그림 제목처럼 읽혀 기각됐고, 입력 상자의 부제가 그 선의 뜻을 맡는다.
- **이름표는 테두리 변에 걸친다.**
  위 변에 둘 자리에 선이 지나가면 아래 변으로 옮긴다.
  같은 x 에서 시작하는 선이 둘이면 꺾는 자리도 같은 x 로 맞춘다.
- **테두리는 두 종류다.**
  제공자 (Oracle VM · Google Cloud · Cloudflare) 는 색 실선, 묶음 (Airflow DAG · Data Lakehouse) 은 색 점선이고, 색은 종류마다 하나씩이다.
  묶음 점선이 제공자와 같은 색이면 갈리지 않는다 (Airflow 를 청색에서 보라로 바꿨다).
- **오케스트레이터는 가운데 띠에 둔다.**
  위에 VM 저장, 아래에 Google Cloud 를 두면 태스크에서 나가는 선이 위아래로 짧게 닿는다.
  위 띠의 상자는 캡션을 위에 두어 아래에서 올라오는 선이 상자 바닥에 닿게 한다.
- **흐름은 한 방향으로 맞춘다.**
  오른쪽에서 왼쪽으로 흐르던 행동 이벤트를 GA4 를 입력 열로 옮겨 왼쪽에서 오른쪽으로 바꿨다.
- **캡션은 두 줄, 숫자에는 단위를 붙인다.**
  「태스크 8」 은 「태스크 8개」, 「타이머 4」 는 「타이머 4개」 다.
  영어 뒤 조사는 붙여 쓴다 (「VM에」).
- **요약 띠의 폭은 굵은 글씨까지 잰다.**
  일반 굵기로 잰 폭이 띠 안에 들어도 청록 굵은 span 이 늘어나 한 낱말이 넘친다.
  후보 문장은 5% 여유를 두고 고른다.
- **헤더 두 줄을 한 줄로 합쳐 그림 자리를 얻는다.**

## 10. 두 번째 검토 회차에서 더 밟은 것 (2026-09-17)

14 ~ 20장을 두 번째로 검토해 승인까지 간 회차다.

- **강조는 스크립트로 감사하고 예외는 목록으로 둔다.**

  한 줄은 37px, 두 줄은 58px 이상이다.
- **목업을 조각으로 되돌릴 때는 다음 장 구분선 앞까지만 자른다.**

  조각 쪽 기준으로 자르고, 되돌린 뒤 조각의 id 목록이 그대로인지 본다.
- **목업 머리는 인라인 스타일에서 새는 규칙까지 가져야 한다.**
  덱에서 정상으로 보이는 것이 목업에서 깨지면, 어느 장의 인라인 `<style>` 이 다른 장을 살리고 있었는지부터 의심한다.
  덱의 공통 `<style>` 과 목업 머리를 규칙 단위로 대조하는 짧은 스크립트로 차이를 찾고, 인라인 규칙은 손으로 옮긴다.
- **날짜에 묶인 수는 승인 직전에 한 번에 다시 센다.**

  Merge 는 `gh pr list --state merged`, 커밋은 트레일러를 대소문자 무시로, 문서는 폴더별 파일 수, 실행은 Airflow `list-runs -o json`, 판정은 judge 로그에 「반영 완료」 가 든 run 수다.

  이번 회차에 그렇게 답하다 덱 문장 셋이 코드와 다른 것을 찾았다 (`docs/troubleshooting/2026-09-17-three-deck-sentences-disagreed-with-code-and-two-numbers-had-no-method.md`).

## 12. 비교 표 · 띠 · 소개 문장을 고친 회차에서 더 밟은 것 (2026-09-18 저녁)

41장 비교 표의 열여덟 칸 · 아래 띠 · 3장 소개 문장 · 표지 상자 라벨을 사용자 지적에 따라 고친 회차다.

- **표 칸은 바꿀 것을 전부 넣은 상태에서 잰다.**
  자동 열 폭 표는 한 칸이 열 폭을 바꾸므로 칸마다 독립으로 잰 결과는 참고값이다.

  두 층 칸의 행 높이가 기준 (64 → 59 → 57 로 여백에 따라 다르다) 보다 크면 어느 층이 접힌 것이다.
- **접히지 않는 요소는 폭으로 잰다.**
  한 줄 소개 · 라벨 · 배지처럼 `nowrap` 인 요소는 높이가 안 변하고 넘친다.
  `v9_build/try_w.py` 로 글자 오른끝을 슬라이드 폭 (1280) 과 그 장의 구분선 (3장은 약 1215) 에 견준다.
- **요소 하나에 후보 문장과 CSS 를 같이 넣어 본다.**
  `v9_build/try_css.py <items.json>` 은 `[슬라이드, 라벨, 찾을 문자열, 새 innerHTML, CSS]` 를 받아 그 요소의 높이 · 글자 오른끝 · 슬라이드 높이를 돌려준다.
  여백 · 줄 간격 조합을 문장과 함께 비교할 때 쓴다.
- **간격은 글자 상자 사이로 잰다.**
  `v9_build/gap41.py` (41장 표 칸의 검정 → 회색 · 회색 → 회색) · `try3gap.py` (3장 제목 → 항목 → 보조 줄) 가 빈 공간을 px 로 돌려준다.
  캡처로 「비슷해 보인다」 를 판단하지 않는다.
- **조립 뒤에는 출력 줄을 확인한다.**

  치환을 바꾸면 검사 문자열도 같은 자리에서 바꾼다.
- **비교 캡처는 해시로 대조한다.**

- **조각 안에 새 블록을 끼울 때는 상속을 끊는다.**
